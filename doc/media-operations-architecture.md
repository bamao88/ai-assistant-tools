# 新媒体运营 Skill 体系

现在可以从 [按用途导航](media-operations-catalog.md) 查找全部现役入口。源码统一位于 `skills/`，修改一次即可通过原来的 Codex 入口使用。`registry.yaml` 是唯一正式清单，导航由脚本生成。

## 职业流程与能力边界

| 工作环节 | 当前承担方式 | 交接给下一环节的内容 |
|---|---|---|
| 定位与账号策略 | `self-media-init` 加项目定位、受众、账号角色 | 目标、受众、内容支柱、平台分工、资源约束 |
| 调研与洞察 | `content-creator-research`、`product-deep-research` 及项目研究编排 | 来源证据、对标结论、待验证机会 |
| 选题与规划 | `content-topic-planning` 及项目选题工作台 | 选题取舍、角度、范围、依据和本轮计划 |
| 素材与知识准备 | `platform-fetch`、`video-content`、`content-production-prep` 及项目知识流程 | 来源材料、版本、制作输入与已确认决定 |
| 内容制作 | 文章、口播、剪辑、卡片、配图与项目视觉规范 | 可审阅的作品及来源、版本、素材 |
| 平台适配与发布 | `content-package-create` 制作文案，`Agent-Publish` 执行平台动作 | 每个账号和渠道独立的发布包与发布事实 |
| 互动与用户关系 | `xhs-interact` 及项目客户管理 | 反馈、需求、关系记录与后续动作 |
| 数据与迭代 | `content-operations-ledger` 加项目数据、复盘入口 | 同口径指标、结论、改进动作及下一轮验证 |

这张流程图用于划分责任，不意味着每个格子都要新建一个 Skill。战略、用户研究、商业化等不足的能力，先在真实任务中验证方法，再决定是否独立；不先堆空入口。

## 源码、项目和平台怎样分工

- 通用 Skill 维护可复用的方法、输入输出和质量要求。
- 项目 Skill 维护该项目的编排、内容规范与事实源连接。新建或更名时，以完整项目名加 `_` 为前缀。
- 项目目录保存账号身份、登录配置、作品、台账、客户信息、历史数据与确认记录。Skill 可以读取它们，不把它们复制成另一份运营总账。
- 媒介工艺处理文章、口播、视频、卡片等不同作品形态；平台规则与执行留在相应 reference 和执行器。
- `engines/` 是被调用的程序，`vendor/` 是外部依赖；它们不因出现在调用链上就成为新的 Skill。

多账号必须区分项目、品牌、出镜人、平台账号与登录会话。同一篇母内容可以派生多种媒介版本，再投到多个渠道；每次渠道发布分别记录状态和指标。平台登录成功也不等于当前身份就是目标账号。

## 本次已经完成的结构调整

集中范围是 38 个入口，含一个知识管理兼容入口；按规范源码去重，避免把同一个全局链接和项目链接重复计数。

- 原来外置于 WXP、MiMi 和 ZH 项目的 17 个 Skill 进入 `tools/skills/`，连同引用、模板、必要脚本、素材与来源许可一起管理。
- 原项目路径保留软链；六个泛名 ZH Skill 的规范名称补齐 `assistant_zh_` 前缀，旧路径仍可找到同一份内容。
- WXP 与 MiMi 原有全局可选入口继续指向集中源码；ZH 本地工作台仍在项目内发现。
- 误放进 Skill 的账号配置、客户样本和历史策略留在原项目。公开源码保留读取方法或模板。
- `registry.yaml` 的 `media_domain` 表示用途，`project` 表示归属，`hosts/scope` 表示发现位置，`project_entry` 记录原项目入口。归属和安装位置分开维护。

旧触发的映射继续以 `registry.yaml: deprecated` 为准。历史版本可从 Git 找回，不将旧正文重新注册成另一套现役入口。Claude 专用安装本轮不调整。

## 下一步按责任逐组重组

| 现有能力组 | 处理方向 | 合并前必须保持的行为 |
|---|---|---|
| 通用研究与项目研究 | 通用方法与项目资料、输出规则分开；项目研究作为编排 | 研究证据、完整报告与项目落点不丢失 |
| 通用选题与 ZH 三个选题入口 | 验证后将 ZH 收敛为一个项目选题工作台的不同模式 | 展示推荐默认只读，明确刷新才采集或写入，确认后才进入正式制作 |
| ZH 五个知识入口 | 先区分只读检索与维护，旧 owner 别名逐步退场 | 检索不写入，维护权限和修订记录独立 |
| 素材准备与平台文案 | 保持独立入口，用明确交接衔接 | 整理版本和写平台字段都能单独完成，沿项目已有作品目录和事实源 |
| 长文、表达润色和口播风格 | 各自保留，按任务调用 | 视频转文章能继续写完；文章不被强制套入口播语气 |
| 通用卡片与 WXP 知识卡片 | 通用排版工具与项目内容方法分层 | 项目完整分析、分页和视觉质量不被简化为排版转换 |
| 台账、发布记录、指标与复盘 | 项目工作台统一入口，底层状态职责继续分开 | 母内容与各渠道发布独立，官方指标有时间、口径与来源 |
| `customer-management` | 下一轮与调用方一起更名为 `assistant_zh_customer-management` | 当前旧入口先保持可用；私有身份配置继续可读 |

通用调用名暂时保持稳定。`media-*` 或 `writing-*` 等候选名字需要和真实任务、旧引用一起迁移后才启用，不再增加一组同义入口。

## 修改与验证

新增能力前先在导航查是否已有相同输入和交付物。只改变项目规则时修改项目工作台或项目配置；只改变平台规则时修改对应适配；只有出现独立、重复的任务和交付物才增加入口。源码、注册、调用方、显示名称和废弃映射一起更新。

```bash
python3 scripts/check-media-skills.py --write-catalog --installed
python3 scripts/check-tools.py --host codex --strict
python3 scripts/check-media-skills.py --installed --git-ref <提交号>
```

第一条生成导航并检查源码、元数据与本机入口；第二条检查整个注册表与 Codex 安装；第三条逐文件核对集中源码是否完整进入该 Git 提交。这些是 `logic/contract` 层验证。

本轮是 Skill 源码集中，运行继续复用本机项目与引擎。公开仓库的引擎版本可能落后于本机，且 vendor、登录态、项目数据和依赖环境不随 Skill 包分发；这不是开箱即用的独立运行发行包。集中检查不代替真实内容 replay、平台 E2E 或用户验收。
