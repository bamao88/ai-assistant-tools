# 新媒体运营：架构、命名与关键字段规则

更新日期：2026-10-23。状态：目标规则与架构已修订；实际 Skill 合并、删除、项目更名尚未执行。职责树与数据流见 [统一架构](media-operations-architecture.md)，执行顺序和现役能力去向见 [迁移计划](plan/media-operations-restructure.md)。

本文是项目命名、入口准入、关键字段关系的唯一规则来源。`registry.yaml` 是唯一现役 Skill 清单，各项目原有文件继续保存账号、作品、知识与运营状态。规则固定的是含义、边界和引用关系；昵称、路径、状态、指标等运行值按事实更新。

|---|---|---|

项目标识、Skill 调用名、源目录名、自有模式和枚举标识，以及显示名中的英文标识，一律小写。项目根目录末级名称与最终项目标识一致。项目专属 Skill 必须以前缀 `<完整项目标识>_` 开头，不能自行缩写或恢复大写形式。

本规范约束自有命名；`SKILL.md`、`AGENTS.md` 等协议文件名、外部 API 字段、原生 UID/AppID、引用原文及历史记录使用其真实字面值。项目改名不改变外部账号身份。公开昵称、品牌、出镜角色和项目标识分别维护。

旧 `assistant_wxp_xiaohongshu_ops` 骨架的有效规则吸收后退出，最终小红书工作区只有 `assistant_wxp_xhs`。公众号的个人学习日报保留其原业务边界，不自动当作公开内容。

## 2. 先确定职责归属，再确定是否注册入口

取消“一个动作或一个动词对应一个 Skill”的规则，不再固定独立入口数量。按 [架构中的职责树](media-operations-architecture.md) 区分：

| 层次 | 组织方式 | 入口规则 |
|---|---|---|
| 业务领域入口 | 内容管理、知识管理、客户管理等完整业务对象 | 对该对象的生命周期和事实负责 |
| 领域内部模块 | 入库、选题、版本、排期、数据导入、分析、复盘等 | 同一业务入口内部按模式和 references 组织，不逐项注册 |
| 专业工作流 | 调研报告、文章、视频、卡片、封面等独立交付 | 有持续独立需求和质量标准时保留入口，由业务入口按需调度 |
| 平台执行 | 发布、账号认证、互动及底层 adapters/engines | 平台动作按权限独立；认证、上传等步骤优先作为执行模式 |

一个子任务可以单独请求，并不意味着需要单独注册。用户说“排一下下周”“导入这批内容”“分析这周数据”，都可由内容管理直接选择对应模式、完成该项后停止。

新增入口须有独立责任对象或完整交付物、持续独立使用价值，且现有入口的模式不能清楚承担。单纯换动词、换平台、换项目路径、换风格或增加一个处理步骤，不足以创建新 Skill。

## 3. 命名与注册关系

| 字段或关系 | 固定规则 |
|---|---|
| 通用调用名 | `<业务对象或独立交付物>-<核心任务>`，任务部分使用小写英文和连字符 |
| 项目专属调用名 | `<完整小写项目标识>_<同类任务后缀>` |
| 显示名 | `通用｜中文业务任务` 或 `<小写项目标识>｜中文业务任务` |
| 名称相等关系 | `registry.name = SKILL.md.name = skills/<name>目录名 = 正式发现入口名` |
| `source` | 相对 tools 根目录的规范源码路径，最终为 `skills/<name>` |
| `project` | 项目归属，通用入口不填写；项目入口使用最终小写项目标识 |
| `scope` / `hosts` | 发现范围和环境，与业务归属分开；项目 Skill 全局可选也不变为通用能力 |
| `project_entry` | 实际项目入口位置，更名后直接指向新源码，不指向旧名兼容层 |
| `entry_kind` | 目标分类：`bootstrap`（初始化）、`domain`（业务入口）、`workflow`（专业工作流）、`executor`（平台执行）；实施时补入 registry，不另建清单 |
| `media_domain` | 保留现有八个运营环节值用于检索；它是流程标签，不决定 Skill 数量、父子关系或数据写入责任 |
| `layer` | 技术编排层级，与业务职责分类分开；自有值同样小写，如 `l1/l2`，实施时同步检查器与使用方 |
| `default_prompt` | 引用同一 `$调用名`；显示、描述、正文和调用方同步迁移 |
| `uses_engines` / `uses_vendor` | 实际底层依赖；Skill 改名不连带改变引擎、认证或算法参数标识 |

同一职责使用同一后缀，例如 `content-manage`、`assistant_zh_content-manage`、`mimi_tv_operations_content-manage`。项目入口只绑定事实源、角色约束和独有编排，共享方法只有一份。

不再设置固定任务动词清单。动作词帮助表达已有职责，不决定架构；例如文章写作与润色可以是一个文章工作流的两种模式，入库与分析可以是一个内容管理对象的不同处理过程。名称不堆阶段编号、强度、风格、批次或版本。

`media_domain` 沿用 `strategy/research/topics/materials/production/distribution/community/review`。多环节任务按主要目的分类，其内部模块仍属于同一责任入口；不能为了八个标签创建八套平级流程。

## 4. 项目身份与业务身份分开


以下是概念字段，不要求给所有旧项目新增同名字段或新建一套表。项目已有字段和 ID 继续作为事实源，只对齐含义和引用。 项目归属在现有文件中可能叫 `project`、`project_name` 或 `agent.name`，分别在其原合同内同步；`agent.work_dir` 记录真实根路径，不把它们复制成第二份项目注册。

| 身份或记录 | 含义 | 本次更名规则 |
|---|---|---|
| 项目标识 | 工作区与管理归属 | 按第 1 节迁移 |
| `persona` / 品牌 | 公开表达角色及身份 | 保留原有区分，不据新目录名合并 |
| 平台与项目内账号 ID | 一个具体渠道 | 复用现有映射；同平台多个账号分别记录 |
| 原生 UID / AppID 等 | 平台提供的实际身份 | 保留；不能按项目新名称伪造、重新生成或直接替换 |
| 工具认证 profile | 工具调用身份的配置键 | 单独核对消费者与真实身份；不由项目名自动推导 |
| 凭据环境变量名 | 运行环境的配置接口 | 与实际部署绑定；不因目录更名自动改变，不把值写入源码 |
| 登录会话 / 浏览器 profile | 当前执行身份与权限 | 进入平台时核验目标账号；不把登录成功当成身份正确 |
| 算法 profile / preset | 剪辑、画面或美颜参数 | 独立参数域，如既有 `wxp_self` 参数键；不按 `self` 子串改写 |
| `content_id` | 母内容及其原始作品 | 既有 ID 保留，不因项目更名重新编号 |
| 媒介版本 / 素材版本 | 同一内容的文章、视频、卡片等版本 | 沿用现有关系；最终选定版不由“最新版本”自动替代 |
| 发布记录 / destination | 一个具体账号的一次发表或投稿 | 保留平台、账号、草稿/文章/投稿 ID、时间与结果；各渠道分别维护 |
| 指标快照 | 某次发布在某时点、某口径下的数据 | 保留来源、采集时点、口径及原值；不能随迁移重算为无来源新数值 |

项目根路径是可迁移的物理位置；路径变化需要更新现役读取方。历史证据中的原路径与当时身份保留原貌，不对全文和二进制产物做机械替换。内容状态、平台昵称、账号可用性和指标是动态事实，不能冻结为命名规则。


## 5. 一份核心方法、一个事实责任方

内容管理统一管理内容生命周期：来源与作品登记、选题与计划、作品版本、排期与渠道事实、指标分析、复盘改进。具体模块及其唯一责任见统一架构；不另外平铺“排期 Skill”“数据导入 Skill”“分析 Skill”“复盘 Skill”。

知识管理负责原始资料到观点、wiki 与 pending 的处理；客户管理负责人员、客户和学员资产。它们与作品入库、运营指标导入的对象不同，内容管理通过来源和结果引用协作，不重复维护其数据。

专业工作流交付稿件、视频、图片、平台文案等；内容管理维护其关联、选定版本与生命周期。平台执行返回真实观察和回执，内容管理按证据记账。更换账户、保存平台定时或点击提交的权限不因业务入口合并扩大。

模块按请求按需读取，不将旧正文拼接为每次全量加载的巨型 Skill。项目台账已有稳定 ID、字段与文件时继续使用原事实源；不为统一架构另建总账、平行资料库或重复主文件。

默认查询只读，写入按请求范围执行；整合知识入口后普通提问仍不写 wiki，更新本地排期仍不操作平台定时。真实字幕交回文章任务后继续完成文章，不能以中间步骤代替交付。用户确认的换行、空行、选定版与事实来源边界继续保留。

## 6. 迁移与验证

仍按“先合并、更新调用方、删除重复与失效入口，验证完整任务；最后统一项目及 Skill 名称”执行。本次先修订架构和规则，当前运行注册与目录尚未切换。

本轮不做旧名兼容：最终不留旧注册、别名、转交 Skill、兼容软链或重定向。正常项目发现链接直接指向新规范源码；历史材料与 Git 历史保留原事实，现役执行引用必须更新。Claude 专用安装不纳入本轮整理。

验证分别报告 `logic/contract`、`real replay`、`E2E agent loop`、`product acceptance`。入口数量减少、规则已落盘、静态检查或单元测试通过均不等于真实业务通过。合并后需用代表性真实输入验证正向交付、任务停止点与关联场景，再进行最终更名。
