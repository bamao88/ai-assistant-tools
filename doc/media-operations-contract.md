# 新媒体运营：项目、Skill 与关键字段规则

状态：规则已确定，执行顺序见 [迁移计划](plan/media-operations-restructure.md)。本文规定本次迁移完成后的统一合同；现有项目和 Skill 尚未全部切换。日期：2026-10-22。

本文是这套体系中项目命名、Skill 命名及关键字段关系的唯一规则来源。`registry.yaml` 继续是现役 Skill 的唯一机器清单；账号事实、作品和运营状态继续保存在各项目原有事实源。其他说明文档引用本文，不复制维护另一套字段规则。

“固定”指字段含义、身份边界、命名格式和引用关系固定。昵称、工作路径、登录状态、内容状态、指标和运行配置仍按事实更新。后续明确改变规则时同步迁移其消费者，不能在某次任务中临时发明另一套解释。

## 1. 已确定的项目名称

| 当前名称 | 最终项目标识及目录名 | 范围 |
|---|---|---|
| `assistant_wxp_self` | `assistant_wxp_xhs` | WXP 小红书内容运营工作区 |
| `assistant_wxp_ai8zu` | `assistant_wxp_gzh` | WXP 微信公众号内容运营工作区 |
| `assistant_zh` | `assistant_zh` | 保留现有项目标识和项目内角色区分 |
| `MiMi_TV_Operations` | `MiMi_TV_Operations` | 保留现有项目标识及多平台运营范围 |

项目标识按本表精确使用，包括大小写和下划线。项目根目录末级名称与项目标识一致。公开账号昵称、品牌、出镜角色、平台身份和项目标识分别维护，不能按目录名推断它们相同。

`assistant_wxp_xiaohongshu_ops` 是原拆分计划建立的骨架，独有有效规则吸收后退出；最终小红书工作区统一为 `assistant_wxp_xhs`。公众号更名不新增一套平台账号，不将个人学习日报自动视为公众号公开内容。

项目名中的 `xhs`、`gzh` 是本次确定的项目标识组成部分；平台字段继续使用其合同中的规范值，如 `xiaohongshu`、`gongzhonghao`。外部 API 或旧项目文件使用不同平台编码时，在边界映射，不全库替换。

## 2. Skill 命名与字段相等关系

| 项目 | 固定规则 |
|---|---|
| 通用调用名 | `<任务对象>-<动作>` |
| 项目专属调用名 | `<完整项目标识>_<任务对象>-<动作>` |
| 任务部分 | 小写英文；多词对象用连字符；动作使用动词原形并放在最后 |
| 通用显示名 | `通用｜中文任务` |
| 项目显示名 | `<完整项目标识>｜中文任务` |
| 源目录 | `skills/<调用名>/`，全部位于 tools 仓库内 |
| 必须相等 | `registry.name = SKILL.md.name = 源目录名 = 正式安装入口名` |
| 默认提示 | `agents/openai.yaml` 的 `default_prompt` 引用同一个 `$调用名` |

同一职责在通用与项目入口中使用相同任务后缀。例如 `operations-manage`、`assistant_zh_operations-manage`、`MiMi_TV_Operations_operations-manage`。

任务后缀表达实际责任。项目已经限定平台时，不重复堆叠平台词：本轮 WXP 封面最终为 `assistant_wxp_xhs_cover-design`。通用的特定平台能力仍明确平台，例如 `xiaohongshu-interact`。

运营环节、优先级、模式、批次和版本不进入调用名；不用 `Agent`、`final`、`v2` 等代替任务职责。`deep` 等强度词退出名称不降低现有研究标准。

### 固定任务动词

| 动词 | 责任含义 | 中文任务用词 |

| `search` | 只读检索和基于既有资料回答 | 检索 |
| `write` | 根据资料完成文章 | 写作 |
| `polish` | 修改表达与阅读或口播节奏 | 润色 |

同一职责不再混用动词、动名词或名词词尾。不同职责仍按实际交付区分，不为了名称整齐合并入库与检索、制作与排版、准备与发布。

## 3. 注册字段分别负责什么

| 现有字段 | 固定含义与约束 |
|---|---|
| `name` | 唯一正式调用名，符合第 2 节 |
| `source` | 相对 tools 根目录的规范源码路径；最终为 `skills/<name>` |
| `project` | 项目归属。通用 Skill 不填写；项目 Skill 必须是最终项目标识 |
| `scope` | 发现位置。沿用现有格式：`global` 或项目标识；项目本地值必须与 `project` 一致 |
| `hosts` | 显式声明发现环境，与业务归属分开；本轮执行及验收面为 Codex |
| `project_entry` | 实际存在的项目本地入口位置；更名时同步真实路径，不能指向旧名兼容入口 |
| `media_domain` | 唯一主运营环节，使用下面的八个值；多环节编排不复制 Skill |
| `layer` | 现有技术编排层级，不充当运营环节 |
| `uses_engines` / `uses_vendor` | 实际依赖，引用原有引擎或 vendor 标识；Skill 更名不连带改它们的 ID |
| `interface.display_name` | 采用第 2 节格式；中文明确该任务的交付 |

项目 Skill 可以全局可选，但其适用范围仍由 `project` 限定，名称和显示名仍带完整项目前缀。通用与项目同职责共用方法，项目入口只补项目约束、事实源和工作编排。

### 运营环节枚举

| `media_domain` | 环节 |
|---|---|
| `strategy` | 定位与运营底座 |
| `research` | 调研与洞察 |
| `topics` | 选题与内容规划 |

| `production` | 内容制作 |

| `review` | 数据、复盘与改进 |

## 4. 项目身份与业务身份分开

以下是概念字段，不要求给所有旧项目新增同名字段或新建一套表。项目已有字段和 ID 继续作为事实源，只对齐含义和引用。 项目归属在现有文件中可能叫 `project`、`project_name` 或 `agent.name`，分别在其原合同内同步；`agent.work_dir` 记录真实根路径，不把它们复制成第二份项目注册。

| 身份或记录 | 含义 | 本次更名规则 |
|---|---|---|
| 项目标识 | 工作区与管理归属 | 按第 1 节迁移 |
| `persona` / 品牌 | 公开表达角色及身份 | 保留原有区分，不据新目录名合并 |
| 平台与项目内账号 ID | 一个具体渠道 | 复用现有映射；同平台多个账号分别记录 |
| 原生 UID / AppID 等 | 平台提供的实际身份 | 保留；不能按项目新名称伪造、重新生成或直接替换 |
| 工具认证 profile | 工具调用身份的配置键 | 单独核对消费者与真实身份；不由项目名自动推导 |
| 凭据环境变量名 | 运行环境的配置接口 | 与实际部署绑定；不因目录更名自动改变，不把值写入源码 |
| 登录会话 / 浏览器 profile | 当前执行身份与权限 | 进入平台时核验目标账号；不把登录成功当成身份正确 |
| 算法 profile / preset | 剪辑、画面或美颜参数 | 独立参数域，如既有 `wxp_self` 参数键；不按 `self` 子串改写 |
| `content_id` | 母内容及其原始作品 | 既有 ID 保留，不因项目更名重新编号 |
| 媒介版本 / 素材版本 | 同一内容的文章、视频、卡片等版本 | 沿用现有关系；最终选定版不由“最新版本”自动替代 |
| 发布记录 / destination | 一个具体账号的一次发表或投稿 | 保留平台、账号、草稿/文章/投稿 ID、时间与结果；各渠道分别维护 |
| 指标快照 | 某次发布在某时点、某口径下的数据 | 保留来源、采集时点、口径及原值；不能随迁移重算为无来源新数值 |

项目根路径是可迁移的物理位置；路径变化需要更新现役读取方。历史证据中的原路径与当时身份保留原貌，不对全文和二进制产物做机械替换。内容状态、平台昵称、账号可用性和指标是动态事实，不能冻结为命名规则。

## 5. 单一事实源与业务边界

- Skill 正文、模板与工具规则在 tools 中维护；项目保存身份、定位、作品、台账、真实配置与历史证据。
- 现有项目有稳定索引和台账时继续复用，不因本规则另建项目注册表、内容总账或账户表。
- 同一能力跨项目或跨平台复用同一核心实现；适配层只处理实际平台差异。不同账号的事实和状态分别保存。
- 普通知识检索和默认查看选题保持只读；知识维护、选题刷新、发布记账、指标写入和平台发布分别遵循其任务授权。
- 资料采集后继续原任务；YouTube 转文章必须交付文章，单取字幕不能代替完整写作。既有独立任务及质量要求不因入口合并丢失。
- 运营正文中的确认换行、空行和选定版本属于内容版本，迁移与格式整理均保留。

## 6. 固定迁移顺序与退出规则

顺序为：**先合并、更新调用方、删除重复和失效入口，验证职责完整；最后统一项目与 Skill 名称。** 合并阶段沿用承接入口的当前名称，最终切换前不引入第二套正式命名。

本轮不做旧名兼容。删除或更名后不保留旧 Skill 注册、别名、兼容软链或重定向；项目正常发现链接直接指向新规范源码。先更新现役调用方，再移除旧入口。

历史迁移记录、Git 历史及明确归档的材料可保留旧名用于追溯；其中仍参与执行的路径必须更新。不要求旧名字从所有历史文本消失，也不为历史引用重建旧入口。Claude 专用安装不纳入本轮整理。

每阶段分别报告 `logic/contract`、`real replay`、`E2E agent loop` 与 `product acceptance`。规则写好、静态检查或单元测试通过，只能说明对应层级；最终更名前需要受影响任务的正向真实回放，不能用失败拦截代替完成。
