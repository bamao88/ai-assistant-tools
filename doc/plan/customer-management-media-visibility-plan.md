# 学员管理 skill —— 聊天记录「无损分层 + 自描述信息地图」改造计划

> 面向 owner 的计划文档。前面讲**是什么、为什么、改完有什么不一样**;最后一节「技术细节」才是给写代码的 agent 看的。
> 状态:**待你最终确认 → 即可实现**。本文件取代早前的"媒体可见性"版本(那一版只想修图片,范围太窄)。

## 一、一句话目标

让 AI 在读微信聊天时**永远清楚三件事**:
1. **有哪些信息**(这段对话里有多少文字、图片、语音、链接、系统事件);
2. **它现在正在看的是哪一部分**(默认只看文字);
3. **其他部分能做什么用、怎么取**(卡住时回头去挖)。

底层保证:**聊天记录一条都不删,无损保留**;取舍只发生在"给 AI 看哪一层",不发生在"入库时删不删"。

## 二、为什么要做(两个真实的漏判)

**例一·漏了 Will。** 测"谁要退差价"时,Will 说「我是8900买的」**紧接着发了付款截图**——这是明确诉求。但系统把截图整条删了,AI 看到的是"没有图的半句话",判断成"他没要退",漏掉了。

**例二·永远找不到"加好友日期"。** 之前反复让 AI 找学员的加好友日期,它总找不到。原因是:微信里"**你已添加了X,现在可以开始聊天了**"这条系统提示**就是加好友的时间点**,但它被当噪音删了。

**共同的病根:入库时按"只留纯文字"的规矩,把图片、语音、链接、系统提示全删了。** 最糟的不是"看不到",而是**看不到却照样自信地给答案**——你根本不会知道它漏了。

打个比方:现在的系统像个**把聊天里所有带图、带语音、带系统提示的消息撕掉、只留纯文字**的助手。你问它"谁发过付款截图""谁哪天加的好友",它会很自信地说"查不到"——因为线索被它自己撕掉了。

## 三、核心理念(三句话)

1. **没有垃圾,只有"当前用不上的层"。** 系统提示、表情、链接……都可能是某个问题的关键证据,入库一律保留。
2. **取舍在消费端,不在入库端。** 全部留下,但**默认只把纯文字喂给 AI**做初判(省、快);其它层先不喂,只在"地图"上告诉它存在。
3. **给 AI 一张自描述的信息地图。** 让它知道"有什么、在看什么、其他能干嘛、怎么取",卡住时自己回头挖。

## 四、三层信息模型

把每条消息按"当前要不要默认看"分三层。**注意:分层只是"默认看不看",不是"删不删"——全都留着。**

| 层 | 包含什么 | 默认喂给 AI? | 怎么取 / 有没有工具 |
|---|---|---|---|
| **L0 文字层** | 纯文字对话(含"我通过了好友验证"这类文字事件) | ✅ 默认就看(现状行为) | 直接可读 |
| **L1 元信息层(便宜)** | 图片/语音/视频**的位置标记**、链接标签、**系统事件**(加好友、入群…) | ⛳ 默认**不看正文**,但在"信息地图"里**列出存在** | 标记本身就在地图里;无需工具 |
| **L2 重解析层(按需)** | 图片**里的内容**、语音**的转录** | ❌ 默认不看,AI 卡住时才取 | **图片:用现成工具**(已有解密+视觉);**语音/其它重依赖:不提供工具**,见第五节 |

## 五、工具策略(本次关键决策)

> 原则:**我们已经有的能力就接给 AI;依赖重、当前项目没现成的,就先不做工具,只告诉 AI "这有这么个东西",让它自己想办法。**

| 信息 | 我们给不给工具 | 说明 |
|---|---|---|
| **图片内容** | ✅ **给(用现成的)** | 解密+视觉读图能力已存在(付款截图就是这么读的),直接接进来,不重造 |
| **语音转录** | ❌ **不给** | 依赖 ASR,当前项目没现成、依赖重。**只在地图上标"这有一条 X 秒语音",让 AI 自己想办法**(它有自己的资源/办法去处理) |
| 其它重依赖能力 | ❌ 不给 | 同上,先不建工具,只暴露"存在" |
| 链接 / 系统事件 | —(无需工具) | 本身就是文字标签,L1 直接列出即可 |

这条决策让本次**不新增任何重工具**:系统只做"不删 + 分层 + 给地图",图片指向已有能力,其余靠 AI 自主。

## 六、自描述信息地图长什么样(本计划的灵魂)

AI 每次分析一段对话,开头先看到这样一段"地图"(示意,具体格式实现时定):

```
【本段对话信息清单】共 142 条消息
  · 文字 120 条        ← 你现在看的就是这部分
  · 图片 8 张          ← 可能是付款截图/课表;要读内容用「读图工具」按编号取
  · 语音 3 条          ← 共约 2 分钟;本系统不提供转录,需要时请自行处理
  · 链接 9 条          ← 含 1 个"微信转账"、1 张名片
  · 系统事件 2 条      ← 含「2026/4/1 添加好友」(= 加好友日期)
【你当前看到的】L0 文字层
【卡住时】可按编号调取 L1 标记 / 用读图工具看图片内容
```

要点:**有什么、在看什么、其他能干嘛、怎么取**——四件事一次说清。这正是你要的"让 AI 知道信息全貌、并能自主回头挖"。

## 七、改完后行为会怎么变(还用两个例子)

**Will(退差价)**:AI 初判看文字,看到"我是8900买的"但语气不完整 → 看地图发现"他这条后面紧跟一张图片" → 调读图工具 → 确认是付款截图 → 判定"在要退差价"。**不再漏。**

**加好友日期**:AI 要某人加好友日期 → 看地图"系统事件含 2026/4/1 添加好友" → 直接拿到。**不再找不到。**

## 八、分阶段(本次范围 + 路线)

| 阶段 | 做什么 | 本次? |
|---|---|---|
| **阶段1 · 无损入库 + 分层标签** | 入库不再删任何消息(含系统提示);每条打上层级/类型/角色/时间标签 | ✅ |
| **阶段2 · 自描述信息地图** | 给 AI 那张"有什么/在看什么/其他能干嘛/怎么取"的地图;同时"读不到的内容必须明说",杜绝静默漏判 | ✅ |
| **阶段3 · 图片按需读图(接现成工具)** | 把已有的解密+视觉能力,做成 AI 能按图片编号调用的"读图工具" | ✅(只接现成,不建新) |
| **阶段4 · 派生事实显式化** | 把"加好友日期"(来自系统事件+首条消息)等高频事实直接算好、可取 | ✅(确定性,无需 LLM) |
| 后续 · 退差价任务卡 | 固化"谁算要退、差价怎么算、何时该读图"的判定口径 | 后续(消费方/验证) |

### 本次不做什么(非目标)

- ❌ **不建语音转录(ASR)工具**,也不建任何"当前项目没现成、依赖重"的新工具——只暴露存在,交给 AI 自主。
- ❌ **不改判断口径、不写退差价卡**(那是后续)。
- ❌ **不碰业务数据**(`assistant_zh/student_manage/` 等),不联网、不动飞书。

## 九、风险与回滚

| 风险 | 对策 |
|---|---|
| 全留 → 喂给 AI 的内容变多、token 涨 | L0 默认只喂文字;L1/L2 只在地图里列存在,不灌正文 → token 基本可控 |
| 影响现有"就业回访/客户画像"两个分析 | 它们共用入库工序;验收含"同一学员改前/改后试跑,纯文字结论不变" |
| 图片工具调用出错/取不到图 | 阶段2 的"读不到必须明说"兜底:结论带"⚠️N 项未读",不静默 |
| 回滚 | 改动集中在入库工序 + 地图构建,`git` 可回退;不留半成品 |

## 十、验收标准(你可本地核对)

1. **无损**:对任一学员,入库后消息条数 = 原始条数(系统提示、图片、语音都在),不再凭空减少。
2. **地图**:跑分析时,AI 拿到的上下文开头有"信息清单 + 当前在看 + 其他能干嘛"。
3. **Will 正例**:对 Will 跑分析,AI 能看到"文字后紧跟图片"并据此正确判断。
4. **加好友日期**:任取一学员,能从系统事件直接得到加好友日期。
5. **回归不破**:1–2 个学员改前/改后 `--dry-run` 对比,纯文字判断结论不变。
6. **自检**:`python3 scripts/check-tools.py` 仍 0 error。

## 十一、技术细节(给执行 agent 看 —— owner 可略过)

**改动落点**:
- `engines/customer-management/capabilities/analyze/core.py` —— `normalize_messages()` 改为无损 + 分层标注;新增"信息地图"构建函数。
- 消费方 `capabilities/analyze/employment.py`、`profile.py` —— prompt 构建处接入"地图 + L0 默认"契约。
- 阶段3 读图:复用 `capabilities/acquire/{decrypt_dat,get_img_key}.py` + payment 视觉路径,封装"按图片 handle 取图→视觉读"的可调用入口。
- 阶段4 派生:`capabilities/recognize.py` 加"加好友日期"确定性派生(系统事件 `你已添加了X` / `通过好友验证` + 首条 `createTime`)。

**阶段1 — 无损分层(改 `normalize_messages`)**:
- 删除现有的 `if msg_type != "1": continue` 与 `[...]` 占位剔除两处"丢弃"逻辑。
- 改为:**每条消息都保留**,产出新增 `layer` 与 `kind` 字段:
  - `kind`:`text` / `image` / `voice` / `video` / `link` / `system_event` / `sticker` / `control` 等(按 type + content 双判定;type 码不全也能靠 content 前缀兜底)。
  - `layer`:`text`→L0;`image/voice/video/link/system_event`→L1;图片/语音的"内容"属 L2(按需解析,不在入库阶段做)。
  - 文字仍走 hex 解码 / `max_chars_per_msg` 截断;`media_placeholder_max_len` 语义退役(不再用于删除)。
- 媒体消息保留可定位 handle:图片用 `[图片 ...]` 内的引用 hex 作 handle(供阶段3 取图)。
- `system_event`:识别"你已添加了X""通过好友验证""邀请加入群聊"等,保留为结构化事件(阶段4 取用)。
- `control`(zstd app-control,`28b52ffd…` 解不出文本):保留原始指纹但归最低层,不喂正文。

**阶段2 — 信息地图 + 不静默**:
- 新增 `build_info_map(normalized) -> dict/str`:统计各 `kind` 计数、列出 L1 标记(带 handle/编号)、点名高价值系统事件(加好友日期)、声明"当前喂的是 L0"、声明"语音等无工具需自行处理"。
- prompt 构建:`地图段` + `L0 文字段`(默认);L1/L2 正文不默认注入。
- 输出契约加 `unread`:范围内有 N 项未读(图/语音)→ 结论必须显式带"未读 N 项",杜绝静默。

**阶段3 — 读图工具(只接现成)**:
- 暴露 `resolve_image(handle) -> 图像/视觉读结果`,内部走已有 decrypt + 视觉;AI 按地图里的图片编号/handle 调用。**不新建 ASR / 其它重工具。**

**阶段4 — 派生事实**:
- `recognize` 加 `friend_add_date(messages)`:优先取 `system_event` 的添加/通过事件时间,回退首条 `createTime`。
