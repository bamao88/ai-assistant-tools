# 学员管理 skill —— 让 AI「看得见聊天里的图片」改造计划

> 面向 owner 的计划文档。前面讲**是什么、为什么、改完有什么不一样**;最后一节「技术细节」才是给写代码的 agent 看的。
> 状态:**待你审阅** · 第一阶段(C1)已由你选定为最高优先级(P0)。

---

## 一、一句话目标

让 AI 在读微信聊天做判断时,**知道"这里有一张图片"**——而不是像现在这样,图片在喂给 AI 之前就被系统悄悄删掉,导致 AI 对着"缺了图的对话"下结论、还下得很自信。

## 二、为什么要做(一个真实的漏判)

上次用真实数据测"谁私聊要退差价",系统漏掉了 **Will**。复盘发现:

- Will 在 6/13 晚说了一句「**我是8900买的**」,**紧接着发了一张付款截图**。
- 这是一个很明确的"我多付了、想退差价"的诉求。
- 但系统在整理聊天、交给 AI 之前,**把那张截图整条删掉了**。AI 看到的是"Will 说了句我是8900买的",没有截图、没有上下文,于是判断成"他没在要退差价",把他剔除了。

**最糟的不是"看不到图",而是"看不到却照样给肯定答案"**——这种"安静地出错"最危险,因为你不会知道它漏了。

打个比方:现在的系统像一个**把所有带图的微信消息直接撕掉、只留下纯文字**的助手。你问它"谁发过付款截图",它会很自信地说"没人发过"——因为带图的那几页已经被它自己撕掉了。

## 三、现在到底发生了什么(大白话版)

微信聊天里有很多种消息:**文字、图片、语音、视频、链接、红包、名片、系统提示**("你已添加了 X")等等。

系统在把聊天交给 AI 之前有一道"整理"工序。这道工序现在的规矩是:**只留纯文字,其它一律删掉**。所以:

- ✅ 文字消息 → 留下,AI 看得到
- ❌ 图片 / 语音 / 视频 / 链接 → **全部删掉**,AI 完全不知道它们存在过

问题就出在这——"删掉系统提示"是对的(那是噪音),但"删掉图片/语音/链接"是错的,因为它们经常是**判断的关键证据**(付款截图、转账记录、名片、文件)。

## 四、我们要怎么改(分四步,这次只做第一步)

| 步骤 | 做什么 | 大白话 | 本次? |
|---|---|---|---|
| **C1** | 不再删图,留一个"这里有张图"的标记 | 把"撕掉带图的页"改成"在那一页贴个便利贴:**此处有一张图片(附取图凭证)**" | ✅ **本次** |
| C3 | AI 给结论时,必须报告"范围内有 N 张图我没读" | 让 AI 不能再"安静出错";读不到就**明说不完整** | 后续 |
| C2 | 给 AI 一个"按需取图、读图"的工具,它自己决定要不要用 | 当文字不够判断时,AI 能主动把那张图调出来看——**你要的"自主性"** | 后续 |
| C4 | 为"退差价"这类任务写一张专门的任务卡 | 把判断口径(谁算要退、差价怎么算、什么时候该读图)固化下来 | 后续 |

> **为什么先做 C1**:它是地基。图都被删了的话,后面"报告未读""按需读图"都无从谈起。C1 风险最低(只是"不删、加标记",不读图、不联网、不碰你的业务数据),却能立刻消除"安静漏人"这个最大的坑。

### C1 改完后,行为会怎么变(还用 Will 举例)

**改之前**,AI 看到的 Will 对话:
```
[6/13 21:xx] [学员] 我是8900买的
[6/13 21:xx] [助理] 差价＝实付-8600,后面统一退给大家
```
→ 截图不见了,AI 判断"他没明确要退" → **漏掉 Will**。

**改之后**,AI 看到的:
```
[6/13 21:xx] [学员] 我是8900买的
[6/13 21:xx] [学员] [图片#<取图凭证>]        ← 新增:便利贴
[6/13 21:xx] [助理] 差价＝实付-8600,后面统一退给大家
```
→ AI 看得到"他说完就甩了张图",能判断"这是在报自己付的价+发凭证要退差价" → **不再漏**。
(注:C1 阶段 AI 还看不到图里的具体内容,但**它知道图存在、能据此做更对的判断**,也为后续"按需读图"留好了凭证。)

## 五、这次不做什么(非目标,避免范围漂移)

- ❌ **不自动解图/读图内容**——那是 C2,涉及解密+视觉,成本和触发时机要单独评估。
- ❌ **不改任何判断口径、不写新任务卡**——那是 C4。
- ❌ **不碰你的业务数据**(`assistant_zh/student_manage/` 等)——只改 tools 引擎里"整理聊天"这一道工序的代码。
- ❌ **不联网、不动飞书**。

## 六、风险与回滚

| 风险 | 说明 | 对策 |
|---|---|---|
| 误把"系统噪音"也当内容留下 | 比如"你已添加了X"、表情贴纸、版本不兼容提示 | 第七节的分类表明确"留什么/删什么";噪音继续删 |
| 喂给 AI 的内容变多 → token 变多 | 多了些 `[图片#..]` 标记行 | 标记很短(一行);只多了原本被删的媒体行,可控 |
| 影响现有两个分析(就业回访/客户画像) | 它们共用这道整理工序 | 验收里包含"对同一学员改前/改后跑一遍,确认文字判断不变";见第八节 |
| 回滚 | 万一不对 | 单文件、单函数改动,`git` 一键还原;不留半成品状态 |

## 七、唯一需要你拍板的判断:哪些"留",哪些"删"

这次改动的核心,就是把"整理工序"的规矩从"只留文字"改成下面这张分类表。**这是唯一需要你过目的判断点**(我已给出推荐默认):

| 消息类型 | 例子 | 推荐处理 | 理由 |
|---|---|---|---|
| 文字 | "我是8900买的" | ✅ 留(不变) | 主要内容 |
| **图片** | 付款截图 | ✅ **留成 `[图片#凭证]`** | **本次重点·证据** |
| 语音 / 视频 | `[语音]` `[视频]` | ✅ 留成标记 | 是内容,虽暂不转写 |
| 链接 / 文件 / 名片 / 转账 / 红包 | `[链接]训练营介绍.pdf`、`[链接]微信转账` | ✅ 留(带原文标签) | 常是关键动作(发资料、转账) |
| 引用回复 | "…「引用:…」" | ✅ 留(它其实是文字) | 现在被误删了,是真对话 |
| 系统提示 | "你已添加了X"、"以上是打招呼的消息" | ❌ 继续删 | 纯噪音 |
| 表情贴纸 / 拍一拍 | `[表情 xxx]`、"我拍了拍X" | ❌ 继续删(默认) | 社交噪音,无判断价值 |

> 如果你对某一行有不同看法(比如"表情也想留着"),告诉我,我改这一行即可。否则按上表默认执行。

## 九、后续阶段衔接(本次之后的路线)

```
C1(本次:图看得见) → C3(读不到要明说,装安全网) → C2(按需取图读图,放权给AI) → C4(退差价任务卡)
```

- C4 是"退差价"判断口径的固化,放在 C1–C3 之后做消费方/验证。

## 十、技术细节(给执行 agent 看 —— owner 可略过)

**改动唯一落点**:`engines/customer-management/capabilities/analyze/core.py::normalize_messages()`(共享机器核,被 `employment.py` 与 `profile.py` 调用)。

**现状(要改的逻辑)**:
```python
msg_type = str(m.get("type", "1"))
if msg_type != "1":            # ← 把图片/语音/链接/引用全部丢弃
    continue
...
if content.startswith("[") and content.endswith("]"):   # ← 短括号占位也丢弃
    if media_placeholder_max_len is None or len(content) < media_placeholder_max_len:
        continue
content = try_decode_hex(content)
```

**目标分类(按第七节表,用消息内容+type 双重判定,避免硬编码所有 type 码)**:
- `SYSTEM_DROP`:`type==10000`;`拍一拍`("我拍了拍" 文案);纯 zstd 控制载荷(`content` 以 `28b52ffd` 开头且 `try_decode_hex` 后是 xml/控制串);表情贴纸(`[表情 ...]`)。→ 继续 `continue`。
- `TEXT`:`type==1`,以及虽非 type 1 但 `content` 是真文字(如引用回复 `…「引用:…」`,即"非系统、非纯括号占位"的文本)。→ 走原文本路径(hex 解码、`max_chars_per_msg` 截断、emoji 短占位仍可删)。
- `MEDIA`:图片(`type==3` 或 `content` 以 `[图片` 开头)、`[语音]`、`[视频]`、`[链接]…`/`[文件]`/名片/转账/红包。→ **不丢**,转成可见标记。

**标记格式(保持返回字段 `{createTime, ts_str, is_staff, sender_name, content}` 不变,仅改 `content`)**:
- 图片:`[图片#<handle>]`,`handle` = `[图片 ` 后那串引用 hex(去空格;作为后续 C2 按需取图的凭证)。
- 其它:保留原带标签占位,如 `[语音]`、`[视频]`、`[链接:训练营介绍.pdf]`。
- `is_staff`/`sender_name`/`ts_str` 照常计算 → 方向判定(自有号 vs 对方)不受影响。

**调用方迁移(canonical cleanup,不留兼容垫片)**:
- `media_placeholder_max_len` 参数语义变更:不再用于"删媒体",仅保留"删 emoji/短贴纸占位";媒体标记**恒保留**。
- `employment.py`(传 `media_placeholder_max_len=30`)与 `profile.py`(传 `None`)两处调用复核:确认新语义下行为符合预期;`profile.py` 拼接行 `f"[{ts}] [..] {content}"` 与 `employment.py` 同构,媒体标记会自然作为一行进入 prompt,无需改拼接。
- 注意 `employment.py` 的开场白 exact-match gate(`FOLLOW_UP_TRIGGER in content`)只匹配文字,媒体标记不含触发词,不会误触 gate。
