# 新媒体运营 Skill 重组：源码集中阶段

本阶段先让现有运营能力拥有可版本管理的共同维护位置。全部相关现役 Skill 的正文、引用、模板、脚本、必要素材与许可证进入 `tools/skills/`；原来的 Codex 全局或项目入口指向这里，避免两份内容分别修改。

范围是当前 Codex 可用的 38 个入口，包含一个兼容别名。按研究、选题、素材、制作、分发、用户关系和复盘归类；战略定位目前由初始化与项目规范承担，不先创建空 Skill。Claude 专用安装、第三方插件与软件开发流程不在本轮范围。

1. 核实源码、项目归属、现有调用与 Git 状态，备份迁移前文件。
2. 集中外置的项目 Skill；项目专属新名称使用项目名前缀，原路径作为兼容链接。
3. 将误放在 Skill 内的真实账号配置、客户样本和运营状态留在原项目；源码只保留配置合同和模板。
4. 在 `registry.yaml` 标记业务用途与项目归属，补统一导览和静态检查。
5. 验证文件、元数据、链接与所收录 Git 文件。独立分支提交并推送，只包含本轮源码范围。

本阶段不宣称完成所有合并或完整业务验收。下一阶段按真实业务输入逐组修改边界、合并重叠入口，再进行真实回放；见 [体系与迁移安排](../media-operations-architecture.md)。

## 原项目的连接调整

`registry.yaml: project_entry` 记录现有项目入口，本轮将这些入口改成链接，源码在 tools 中维护。原目录已在本地任务备份，未复制业务数据到 tools。

- ZH 选题历史策略与表现数据留在项目 `.agents/skill-data/assistant_zh_topic-select/memory-bank/`；客户身份、资源映射和原始匹配样本留在项目 `config/customer-management.private.json`。
- MiMi 的真实台账配置留在项目 `config/content-operations-ledger.json`，项目 `scripts/content_management.py` 的配置读取位置同步调整；tools 包提供 `ledger.config.example.json`。
- 项目链接、配置文件和这处项目程序修改属于各自本地项目，未混入 tools 仓库提交。新环境应绑定自己的项目和私有配置；不能仅克隆 tools 就假定业务环境已恢复。
- Skill 内已有 Git 忽略规则的运行游标和封面使用账本保留本机，完整性校验与导出均排除它们。上游包的 schema、测试、素材、来源记录和许可仍属于源码。

## 源码集中验收

38 个入口、462 个源码文件已逐文件与导出 Git 树核对；Codex 全局入口和原项目链接一致，注册检查为零警告、零错误。YAML/JSON/Python 静态解析通过，迁移所涉既有单元或合同测试共 60 项通过。MiMi 现有台账读取一致性检查通过，没有进入平台采数。

这些结论分别对应源码与安装合同、既有测试以及真实本地数据读取，不代表真实内容生产 replay、E2E agent loop 或 product acceptance。历史原文中的相对链接按归档前位置解释；活动引用单独核对。原资源的换行和末尾空行保持，不为迁移批量重排。
