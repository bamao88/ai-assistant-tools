# 多台 Mac 共用 Skill

目标是让任意一台 Mac 新增或修改的 Skill 都能传给另一台，并在当前 `tools` 目录维护共同源文件。实际日程继续由苹果同步，本次不读写日历。

采用现有 GitHub 仓库交换版本。Git 保存每次修改，发现双方改了同一处时保留冲突，避免共享文件夹的覆盖行为。两台 Mac 各有本地 tools 工作副本，Codex/Claude 的入口只是指向本机源文件的链接；磁盘名称和用户名可以不同。

1. 保留当前未提交工作，检查已有注册、安装入口与外置 Skill。
2. 增加可预览的 Skill 导入入口，将原文件完整备份后集中到 `skills/`；通用规则和实际本机配置分别保存。
3. 安装和检查支持按名称选择，另一台 Mac 无需启用全部 Skill。新增的源文件仍须登记进唯一清单 `registry.yaml`。
4. 日程规划 Skill 先作为真实迁移样本，保留本机分类表和既有入口，修正搬家后的配置定位。
5. 写清双向 Git 工作步骤、共享文件夹的使用边界和冲突处理；新增 Skill 在任一机器执行同一导入流程。
6. 用隔离的两个工作副本与一个本地 Git 远端验证双向传递、不同路径安装和冲突保留；另跑本仓库安装及结构检查。

集中范围默认指自己维护、手动安装的 Skill；Codex 内置和插件缓存仍由其安装器负责。外置项目 Skill 的运行依赖须先核对，不能将文件搬家冒充另一台机器已能执行业务。

负责人后续明确：本次只迁入日程 Skill，其余以后逐个加入；复用现有公开 tools 仓库，不另建私有仓库。个人分类表和配置不上传。当前开发分支包含其它未发布提交，发布时从远端 main 单独整理本次变更，不能将整条开发分支一起推送。

验收分别报告：源文件与本机入口迁移、两个隔离副本的真实 Git 往返、另一台实体 Mac 的接入状态。当前机器无法直接证明另一台实体 Mac 已完成安装。
