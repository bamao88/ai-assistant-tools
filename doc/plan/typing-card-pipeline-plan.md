# 打字机钩子卡 · 流程说明 + 固化计划

> 这条线现在在 **`var/zh_main/0618test/design/typing_card/`** 里跑通了（独立一套、一条命令出片）。
> 本文档讲清楚：它**是什么、长什么样、怎么搭出来的、怎么改**，以及**将来怎么固化成剪辑 skill 的一个原子能力**。
> 这是给 owner 看的，所以先讲"做了什么"，技术名词都配大白话。

---

## 一句话定位

把一句"钩子文案"做成 **黑底白字、像打字机一样一个字一个字蹦出来** 的竖屏开场卡：
配上**主播自己的原声**（从源视频里抠出来、稍微加速）和**键盘敲击的背景音**。
用在短视频开头，先用文字+人声把人"钩"住。

这次的样片文案（来自评测体系那期）：

```
所有做 AI 中台的同学 / 你们一定要留心了 / 时代变了
不要做低代码了 / 不要做工作流了 / 完全干不过 Agent 的
```

成片约 7.9 秒，竖屏 1080×1920。

## 长什么样（最终效果）

- **画面**：近纯黑底、近纯白字，思源宋体超粗体（就是公众号标题条那支字，"刀刻"般的硬朗衬线）。
  6 句话整块垂直居中，逐字出现，末尾有个会闪的光标方块 `▌`。
- **声音**：分两层——
  - **人声是主角**：主播原话，1.3 倍速（更紧凑、有压迫感）。
  - **键盘声是背景**：只在"正在打字"那几秒响，字一打完键盘声就停；音量压得很低，垫在人声底下当氛围。

> 设计过程里试过三种版式（统一字号 / 末句放大爆点 / 分段留白），最终选了**统一字号**这版（最干净、不抢话）。
> 键盘音也试过合成的（太刺耳），最后用主播自己录的真实键盘录音。

## 它是怎么搭出来的（三步）

整个流程拆成三块，各管一摊，互不干扰：

| 步 | 干的事 | 大白话 | 代码文件 |
|---|---|---|---|
| ① 人声 | 从源视频里按"每个字的起止时间"把 6 句口播一段段切出来、拼成干净人声 | 像拿剪刀沿着每个字的边缘剪，**只留字幕里的字** | `lib/voice.py` |
| ② 画面 | 黑底白字逐字渲染成一帧帧图，再拼成无声视频 | 每多打一个字就存一张图，串起来就是打字动画 | `lib/layout.py` |
| ③ 合成 | 画面 +（人声 1.3 倍速·主角）+（键盘录音·只在打字时当背景）→ 成片 | 把人声和键盘氛围铺到画面上，再精确剪到目标长度 | `lib/compose.py` |

`run.py` 把这三步串起来，一条命令 `python3 run.py` 就出片。

### 几个关键决策（为什么这么做）

1. **人声为什么要"按字精切"而不是直接截一段？**
   屏幕上这句钩子是把主播原话**重新排序**拼的（"所有做 AI 中台的同学"其实在源视频第 390 秒，"不要做低代码"在第 308 秒）。
   而且有的句子和旁边的字**贴得严丝合缝**——比如"所有做"前面紧挨着"最**近**"的"近"字。
   一开始为了不剪掉字头，给每段前面多留了 70 毫秒，结果把"近"字带进来了，听感上开头多了个字。
   **修法**：去查每段前后到底紧挨着什么字、隔多远——有空隙就safely多留一点，**零间隔就一点不留**，宁可削掉自己 20 毫秒也绝不带进邻字。这样人声内容和字幕**逐字对得上**。

2. **键盘声为什么只在打字时响？**
   字都打完了、画面静止了，还在"哒哒哒"敲就很假。所以给键盘音开了一个**时间窗**：只在"第一个字出现"到"最后一个字出现"这段响，字打完淡出即停。

3. **三段键盘音为什么要统一响度？**
   主播录的三段键盘音，原始音量差了 5~6 分贝。如果直接用，会让人误以为"某版键盘更带感"，其实只是它录得更响。
   用响度归一（loudnorm）拉到同一感知响度后，对比的才是**真音色**，不受录音音量干扰。

4. **1.3 倍速为什么不会变"鸭嗓"？**
   用的是变速不变调的处理（atempo），只让语速变快、音高不变。

## 想改东西 → 改哪里（都在一个文件，不用碰代码）

所有参数集中在 `typing_card/config.json`，改它就行：

| 想改的 | 改 config 里的 |
|---|---|
| **换文案** | `text.lines`（屏幕每行字）**和** `voice.spans_ms`（每行对应原声在源视频里的起止毫秒）——必须一一对应、同样行数 |
| 字大小 / 行距 / 分段留白 | `text.font_size` / `line_gap` / `group_end` |
| 打字快慢、开场停顿、收尾停留 | `timing.*` |
| 人声加速倍率 / 延后开场 | `voice.tempo` / `voice.delay` |
| **键盘音大小**（嫌吵调小、嫌轻调大） | `keyboard.lufs`（越小越轻，当前 -29 是"明显背景音"）|
| 出几版键盘音 | `keyboard.tracks` 加减条目（**当前默认只出 01 这版**）|
| 配色 / 字体 | `colors` / `font` |

> `voice.spans_ms` 怎么来：源视频的字级时间戳存在 `words.json` 里（每个字几点开始几点结束）。
> 挑出每行文案对应的字，取第一个字的起点、最后一个字的终点（毫秒）填进去，代码会自动处理"留多少余量"。

## 现状 / 验收

- ✅ 在 `typing_card/` 内**自成一体**：删掉早期所有散装脚本后，从零再跑照样出片。
- ✅ 一条命令 `python3 run.py` 出片，产物落 `out/`。
- ✅ 成片 1080×1920 / 7.87s / 含音轨；人声内容与字幕逐字一致（"近"字泄漏已修）。
- ✅ 默认只出 `typing_kbd_1.mp4`（01 版键盘音）；`out/` 里现存的 `_1/_2/_3` 三个文件留作**示例样片**。
- 🔲 待用户在本地用得完全顺手后，再按下节路线**固化进 scale**。

文件结构：

```
typing_card/
├── README.md       面向使用的说明（怎么跑、改哪里）
├── config.json     ★ 唯一要改的地方
├── run.py          主入口：一条命令出片
├── preview.py      只渲静态版式图（调字号配色时用）
├── lib/{voice,layout,compose}.py   三步逻辑
└── out/            产物（mp4 + voice_hook.wav + 预览图）
```

## 固化成原子能力的迁移路线（将来做）

目标落点：`engines/video-clip/`，对齐 [`doc/video-skill-architecture.md`](../video-skill-architecture.md) 的"加一个新能力"流程。
**现在还没动 scale**，只在 `var/` 里原型。将来搬迁时这么拆：

- **②画面 + ③合成 → 一个新原子** `engines/video-clip/atoms/typing_card.py`（生成型：吃文案+人声+键盘音，吐成片）。
  把这里内联的 ffmpeg 调用换成引擎自带的 `vutil`（统一的跑命令/探测/编码工具），字体复用引擎 `assets/fonts/`。
- **①按字切口播 → 归到 slicer 那条线**（`engines/video-slicer/transcribe/` 是"字级时间戳"的主场），
  作为内容准备步骤，不塞进画面叠加原子。
- 账号特定的偏好（字体粗细、键盘音、配色）将来走 `engines/<engine>/profiles/<account>/`，不写死在原子里。
- **搬完三件收口**：在 `video-clip/capabilities.json` 声明 → 跑 `video-compose/build_catalog.py` 重建总能力表 →
  更新 `registry.yaml` + 跑 `scripts/check-tools.py`，并在 `video-skill-architecture.md` 的能力表里**登记这个新原子**（结构变更必须同步架构文档）。
