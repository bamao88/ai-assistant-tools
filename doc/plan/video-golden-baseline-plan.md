# 视频切片"选段质量"金标准基准 · 建设计划

> 面向不读代码的 owner 写。先讲清楚**要解决什么、为什么、最后长什么样**，技术名词都配一句大白话。
> 一句话目标：给「每个选题该选哪些原话拼成切片」这件事，建一套**可重复生成 + 可人工拍定 + 可打分对照**的标准答案（金标准），让以后所有 prompt 迭代都能拿它当尺子量。

---

## 一、问题：现在的切片为什么"质量待提升"

现在系统切片分两步走（代码里叫 `twostage`，两阶段）：

| 步骤 | 它干的事 | 状态 |
|---|---|---|
| **阶段一 · 选题** | AI 通读 3 小时全文，挑出 22 个选题，每个只标"大概在第几句附近" | ✅ 你说没异议 |
| **阶段二 · 定脚本** | 对每个选题，**只在那个落点前后各放宽 6 句**的小窗口里挑句子拼成脚本 | ❌ 质量瓶颈在这 |

**瓶颈的本质：阶段二是"近视"的。**
打个比方——选题阶段相当于翻书时夹了张书签"这个观点大概在第 140 页"，定脚本阶段就**只读书签那一页前后**来凑稿子。可张和在 3 小时里经常**同一个观点在别处又讲了一遍、而且讲得更好、还举了更狠的例子**——这些都在"那一页"之外，现在的逻辑根本看不见，也就拼不进来。

代码佐证：`engines/video-slicer/video_slicer/twostage/stage2_script.py` 里 `WINDOW_PAD = 6`（只放宽 6 句），且兜底逻辑会**主动丢弃窗口外的句子**。

**你的构想正好是解药**：把每个选题当成一道独立的题，派一个 AI **拿着全场 3 小时逐字稿去找所有能佐证它的片段**，再组装成一条高质量脚本。代价是不同选题之间内容可能重叠——但你明确接受，因为换来的是每条切片质量拉满。

## 二、为什么先做成"金标准"，而不是直接换生产逻辑

（这是你拍板的定位：**先只做评测金标准生成器**。）

因为"换 prompt 到底有没有变好"这件事，**现在没法量**。你需要先有一份**公认的好答案**当尺子。流程是：

```
建金标准(标准答案)  →  以后改任何 prompt  →  重新跑  →  跟金标准打分对照  →  看分有没有涨
```

没有这把尺子，任何 prompt 改动都只能凭感觉。所以这一期**不碰线上生产的阶段二**（零回归风险），只新增一套"评测基准"的逻辑——这正是你说的"当前架构里没有的那一块"。

> 已有可复用的家底：你**已经手工筛过一版**高质量切片（`var/zh_main/cuts/agent全量-volc-native/剪辑脚本_人工筛选版.json`，带时间段和 `match_rate`）。引擎里也已经有个放"选段基准"的目录 `engines/video-slicer/baselines/`（目前装着"方案A"对照脚本）。我们就把新东西安在这个已有的窝里，不另起炉灶。

## 三、最后交付长什么样

1. **一个生成器**（代码）：喂给它 22 个选题 + 全场逐字稿，它对每条选题跑一次"全局取证"，吐出按论证结构组织的候选脚本。
2. **22 份人工评审稿**（每条一个 md）：方便你像现在筛选那样过一遍、勾留/删。
3. **一份金标准文件** `golden.json`：你拍定后的标准答案。
4. **一个打分器**（代码）：拿任意一版切片产出 跟 金标准 对照，给出分数。
5. **架构文档更新**：把"金标准/评测基准"这条线写进维护手册。

## 四、关键设计约定（决定质量与可信度的几条铁律）

### 1. 口径：论证结构化精选（你拍的板）
每条切片不是把全场讲到这观点的话都堆进来，而是按**短视频成片结构**精选组装：

> **钩子（0-3 秒抓人）→ 核心论点（一句话立住）→ 全场最有力的 1-2 个论据/举例 → 收尾**

- 论据/举例**允许从 3 小时里任何地方调取**（这就是"全局取证"的价值）。
- 跨选题之间可以重复，但**单条内部不许注水堆砌**，控制在一个目标时长内（如 60-120 秒，可调）。

### 2. 铁律：只能引用真实原话，禁止 AI 编造
AI 的产出**不是它改写的文字**，而是**一串"句子编号"**（指向逐字稿里真实存在的句子）。这样有两个硬好处：
- **可校验**：每个被选的句子都能在转录稿 `words.json` 里查到，AI 编不了假话。
- **可剪辑**：句子编号能直接换算成视频里的秒数（复用现成的 `twostage/resolve.py`，它专门干"句子→时间"这件事），所以金标准选完直接就能切出片子验证。

> 大白话：AI 只能"圈出原话第几句到第几句"，不能"自己写一段话假装是张和说的"。

### 3. 全场喂得进去吗？——能，但要心里有数
转录稿全文约 4.9 万字（`full_text` 49077 字符）、2048 句、张和的句子是其中一部分。一次把全场喂给长上下文模型读得下。**代价**：22 个选题 = 22 次"读全场"的调用（一次性，只针对这一个视频），token 花费比现在大，但可接受、可并行。

### 4. 人工定稿（你拍的板）
AI 出的是**候选**，不是终稿。你像现在筛 `人工筛选版` 那样过一遍，勾留/删/微调，最后落成 `golden.json`。金标准的权威性来自"你拍过板"，不是"AI 一次蒙对"。

## 六、分阶段做（每阶段都能单独验收）

### 阶段 0 · 约定脚手架
- 定 `golden.json` 的格式（每条选题：全局句子编号区间 + 每段的结构标签[钩子/论点/论据/收尾] + 组装后脚本文 + 估时 + 人工状态[留/删/改]）。
- 搭好读选题、读全场稿、写产物的骨架；README 写下口径。

### 阶段 1 · 全局取证生成器（核心）
- 实现"每条选题 → 喂全场张和句号稿 + 选题 brief → 一次 AI 调用 → 论证结构化的句子编号区间"。
- 把铁律写进提示词：只引真实句号、不得编造；按钩子/论点/论据/收尾组织；卡时长上限；跨条可重复、单条不堆砌。
- 22 条并行跑，产出候选金标准 + 每条一份人工评审 md。

### 阶段 2 · 人工筛选定稿
- 你过每条候选：留/删/微调区间 → 落成 `golden.json`。
- 给一个回填命令，把你的人工决定并回金标准（参考你现有的人工筛选流程）。

### 阶段 3 · 打分器（让基准能被迭代对照）
- `score.py`：任意一版切片产出 vs 金标准 → 指标（金标准片段召回率 / 时间重合度 / 论证结构覆盖度）。
- 这是"评测这一块逻辑"的闭环：以后改 prompt → 重跑 → 打分 → 看是否逼近金标准。先用现在的 `twostage` 产物打一个**基线分**，证明尺子能用。

### 阶段 4 · 文档收口
- 更新 `doc/video-skill-architecture.md`：维护表里加"金标准/评测基准"这条线（住哪、怎么生成、怎么打分）——遵守"架构文档随改随更"。

## 八、风险 / 待你拍板的遗留项（parked）

1. **token 成本**：22 × 读全场，一次性、可并行，针对单个视频。可接受但你知情。
2. **零生产回归**：本期不碰线上 stage2（已确认 eval-only），所以没有切片质量回退风险。
3. **金标准要不要长期留存**：`var/` 是不入库的运行时目录。若要把这份 `golden.json` 当成"冻结基准"长期保存（类比 G4 基线也在 `var/`），需决定是否单独存档/提交。**建议**：定稿后把 `golden.json` 复制一份到一个明确的"冻结"位置并在 README 标注版本。← 待你确认。
4. **组装顺序**：论证结构是按"钩子→论点→论据→收尾"的逻辑顺序组织，可能与原话时间先后不一致。现成管线本来就支持"跳接"（非连续片段拼接），所以技术上没问题；但**音频跳接听感是否自然**需要在阶段 2 出片试看时一并验。
