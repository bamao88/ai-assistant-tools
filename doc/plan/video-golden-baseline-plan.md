## 0. 本文档的范围（务必先读)

**我们这份文档只管两件事:**

| 在范围内 ✅ | 不在范围内 ❌ |
|---|---|
| **① 生成选题**：这场直播做哪些切片题目 | 具体怎么剪辑执行(按脚本 trim+concat、拼接) |
| **② 生成候选**：每条选题 → 一份「成片脚本」 | 裁框(crop)、盖挡块(mask)、字幕烧录 |
| 成片脚本含两层内容(见下) | 钩子画音对齐/拼接、片头片尾 |
| —— **字级去口水也在内**(它是脚本的一部分) | 发布分发 |

**我们产出的是一份「成片脚本」标准(金标准)——它定义"这条视频最终该剪成什么内容"。** 这份脚本包含两层:

1. **提取哪些部分**:选哪些句/段、按什么逻辑顺序排(选题 + 选段 + 编排)。
2. **在这些部分上做哪些精简**:句子内部删掉哪些口水字词(**字级去口水**)。

这两层合起来 = **后续所有剪辑工作的"脚本上层",内容已经完全定死**。下游只是照着这份脚本去执行(怎么剪),那部分不归本文。

> 一句话边界:**我们定「剪成什么」(脚本/内容),不定「怎么剪」(渲染/执行)。字级去口水属于「剪成什么」,所以在范围内。**

**为什么单独立这份**:现在这两步产出的候选**质量不可取**(切太碎 / 句子之间跳得大 / 两刀挨太近把中间吞掉 / 重复段),必须从「阶段划分 + 提示词」层面重做。**本文是这次重做的唯一计划真源。**

## 1. 为什么先做成"金标准",而不是直接改生产逻辑

"改 prompt 到底有没有变好"这件事,**现在没法量**。得先有一份**公认的好答案**当尺子:

```
建金标准(标准答案) → 以后改任何 prompt → 重新跑 → 跟金标准打分对照 → 看分有没有涨
```

没有这把尺子,任何 prompt 改动都只能凭感觉。所以金标准既是**「好的成片脚本长什么样」的样板**,也是**度量后续迭代的尺子**。

> 已有家底:你已手工筛过一版高质量切片(`var/zh_main/cuts/agent全量-volc-native/剪辑脚本_人工筛选版.json`);引擎里有放基准的窝 `engines/video-slicer/baselines/`。新东西安在这个窝里,不另起炉灶。

## 3. 流程一:生成选题

**正确应该只有 1 个 AI 阶段:选题。**

| 阶段 | 输入 | 输出 |
|---|---|---|
| **选题** | 整场编号逐字稿(每行 `#句号 [说话人] 文本`) | 选题清单,每条 = `title / one_argument / hook_line / audience / mainstream / why / rough_sid_spans(粗句号区间)` |

- 工具:`engines/video-slicer/video_slicer/twostage/stage1_topics.py`(prompt = persona + `STAGE1_TASK`)。
- 它只决定**"做哪些题、大概在哪几句"**,不给精确边界、不给时间戳。

### ⚠ 现状的问题:多了一个"近视"的定段步骤

现状还跑了 `stage2_script.py`(定脚本边界):它**只在选题落点前后各 6 句的小窗**(`WINDOW_PAD=6`)里挑句子定 `keep_sids`。

打个比方——选题阶段夹了张书签"这个观点大概在第 140 页",定段就**只读那一页前后**凑稿。可张和在 3 小时里经常**同一观点在别处又讲得更好、举了更狠的例子**——都在"那一页"之外,这个近视逻辑看不见。

而且:它选出来的 `keep_sids`,到了流程二会被 **②全局取证整段重选覆盖**。所以 stage2 在这条线里**又近视、又冗余**(违反"一个动作只有一个家"——"定哪几段"是流程二②的活)。

> **改造:生成选题到 stage1 为止(只给粗区间),停用 stage2。**

## 4. 流程二:生成候选(产出成片脚本)

**正确分 4 个阶段**(主轴 ②→③→④,①钩子是从②分出的支线):

| 阶段 | 一句话职责 | 输入 | 输出 | 是不是"剪刀口" |
|---|---|---|---|---|
| **② 总编**(全局取证+逻辑编排) | 选料 + 编成逻辑连续的结构 | 1条选题 + **整场编号句** | `segments[{role,sids,reason}]` → `keep_sids` | ✅ 句级剪刀口 |
| **③ 组装**(代码,无AI) | 把②原话按顺序粘成草稿 | ②的 segments + 句表 | `script_raw`(带口水草稿) | ❌ 内部产物 |
| **④ 字级去口水**(精简) | 句内删哪些口水字词 | ③草稿 + 字级时间戳 | 字级删除决策 → 成稿 | ✅ 字级剪刀口 |
| **① 钩子** | 选炸开场 | 选题 + 候选池(②覆盖句±3 ∪ 选题粗区间±2) | `hook_options`(2-3个) | ✅ 钩子那几秒 |

- 工具:`engines/video-slicer/baselines/global_evidence.py`。
- **顺序铁律:先总编(②)把骨架编对,再去口水(④)擦表面。**
- **剪辑跟着:② 定句级区间 + ④ 定字级删减。** 这两层合起来就是"这条视频说什么、minus 口水"。

### ⚠ 现状三个待改的点

1. **② `BODY_TASK` 只做了"选",没做"编"**。提示词里写着"每段短而准、~6句以内、禁圈几十句、多段=跳接"——**主动奖励了切碎和跳接**;代码侧也不去重、不合并。结果就是:碎 / 跳 / 吞 / 重复段。
2. **④ `REFINE_TASK` 产出的是"改写过的干净文字"(free-text)**——改写文本**对不回原视频、没法执行**。标准要的是**字级删除决策**(在第几句、删掉哪个"啊/嗯",带位置),下游才能照着精确剪。**粒度不对,要改。** 它现在还**兼做了"顺语序/合并绕回句"**(那是编排,该上交给②总编)。
3. **① `HOOK_TASK` 是"拼接思路"**(几个短句拼一句、片段≤14字、长句只抠小短语),会蹦字、丢限定词("95%以上"→"95%")、失真。应改"**整句优先**"(详见 `var/zh_main/eval/agent_eval_0613/doc/金标准建设-经验与提示词总结.md` 第七节)。

## 5. 贯穿两条流程的设计原则(铁律)

1. **一个动作只有一个家**:"选+编"全归 ②总编(别在选题 stage2 重做、别在④偷做);"删口水字词"全归 ④;别让一个动作散在多处。
2. **先编骨架,再擦表面**:②总编决定"留哪些、怎么连"(逻辑),④只做表面字级清理(不动结构)。
3. **全局取证 = 总编**:从全场选内容并编排成一条片子,"选+编"是一个动作,不拆成两步。
4. **只引真实原话,禁止编造**:②只回**真实句号编号**(指向 `words.json` 里真有的句子)。好处:① 可校验(编不了假话);② 可换算成秒/毫秒(剪得出来,复用 `twostage/resolve.py`)。
5. **精选合并原则**(2026-06-19 张和拍板,解决"碎"):
   - **源头连续(或只隔≤2句)的相邻刀 → 合并成一刀连续播**,被隔开的承接句**原声补回**;
   - **源头不连续的整句 → 保留编辑排序**(全局取证特性,如把收尾句挪到最后),不强行按时间拉平;
   - **去重叠/重复 → 删前留后**(被完全包含的丢、完全相同的留首个);
   - 判定钥匙:**只合并"编辑列表里相邻且中间≤2句"的刀**;非相邻的源头连续段=整句重排,不动。
6. **字级去口水准则**(参考 `videocut-zh/去口水规则细则/`):删前保后、承接句必留(段间设问/对比转折/解释上文/数据前主语)、不过碎(以语义完整短句为最小单位、宁可多留)、断了从原声补回。
7. **字级去口水必须可执行**:④的产出是"删哪些字词(带位置)",不是改写文本——否则标准落不了地。
8. **人工定稿**:AI 出候选,人挑钩子 + 核对 + 拍板。金标准的权威来自"人拍过板"。

## 6. 改造计划(要动的四件)

| # | 改哪 | 现状 → 目标 | 验收 |
|---|---|---|---|

| 3 | **④ `REFINE_TASK` → 字级去口水** | 从"出改写文本"改成"出字级删除决策";删掉"顺语序/合并"(上交②),只留删口水字词 | 产出能对回原视频字级时间、可直接驱动精剪 |
| 4 | **① `HOOK_TASK` → 整句优先** | 从"短句拼接"改成"整句优先、拼接兜底" | 钩子不丢限定词、不失真、优先用张和整句金句 |

### persona `zh_main`(`engines/video-slicer/personas/zh_main.md`)
张和编辑判断知识,6 块:**①选题闸5关**(独立可懂/单一论点/看反认知度不看内不内行/价值一句话/炸点可前置) **②富集度排序**(数据·转变故事·金句·背书·痛点 ≥3类优先) **③标题硬要求**(挂流量锚/默认疑问反问句式) **④in/out纪律 ⑤数量纪律**(覆盖优先18-25条) **⑥独家流量锚**(前小米/出海CEO/一线Claude Code+Codex)。

### 流程一 · `STAGE1_TASK`(选题,在用)
```
【你的任务·阶段一选题】读【编号逐字稿】(每行 #句号 [说话人] 文本)。按「选题闸5关+标题硬要求+数量纪律」,
从张和(host)发言里挑少而精的切片选题。学员的话只作背景。
【关键:只负责"选什么",不负责"切在哪一毫秒"】不输出时间戳;每条只给大致【句号区间】(rough_sid_spans),
可略宽,精确in/out交下一步;不连续的几段就给多个区间。
【输出JSON】{"clips":[{title,one_argument,hook_line,audience,mainstream,why,rough_sid_spans:[[起,止]]}]}
按mainstream高→低;覆盖优先、宁多勿漏,目标18-25条。
```

### 流程一 · `STAGE2_TASK`(定段,⚠近视/冗余,改造=停用)
```
【你的任务·阶段二定脚本】给一条选题 + 它附近的【张和候选句】。按in/out纪律挑真正进切片的句子:
in点=从hook那句起砍前面软铺垫;out点=论点说完即收;允许跳接(砍中间废话、保时间先后);只能选给你的候选句号、不编造。
【输出JSON】{"keep_sids":[[起,止],...]}  // 连续闭区间;多段=跳接
```
> 代码 `WINDOW_PAD=6`:只把选题粗区间两侧各放宽6句喂给它 → 近视来源。

### 流程二 · ② `BODY_TASK`(总编,⚠只写了"取证"、待加"编排")
```
【你的任务·全局取证定正文】选题已定不要更换。只产正文(论点→论据→收尾),不产钩子。
【根本区别】不要只盯落点附近;扫全场跨位置取证,把散落各处最有力的原话聚到一条。
【结构】argument一句立住观点;evidence从全场任意位置调最有力论据/案例/数据/金句(允许跨很远);closing一句收口(没有就不要)。
【反串味】每段只服务这条选题。【结尾】closing落在完整有力的话上。
【通用纪律】只引真实句号、不编造不改写;每段连续闭区间[起,止],多段=跳接;
  每段短而准~6句内、禁一段圈几十句;  ← ⚠ 这条在逼它切碎,待改成"源头连续就合并、按精选合并原则"
  总时长约60–120秒;按论证逻辑顺序排。
【输出】{"segments":[{role,sids:[起,止],reason}],"title_suggestion":""}
```

### 流程二 · ① `HOOK_TASK`(钩子,⚠拼接思路、待整句优先)
```
设计2-3个开场钩子,按吸引力高→低。【三要素】戳痛点/中目标用户/让人看到答案。
【形态】一个钩子=几个短句拼成一句;片段必须是短句≤12字,长句只抠最炸小短语;2-4个顺次拼、整条≤~30字;
  stitched≈各短句原话顺次拼接(只补极少衔接字)。允许直接用招牌原话整句立住。  ← ⚠ 待改成"整句优先、拼接兜底"
【硬约束】每片段≤14字、是原话一字不差子串;stitched字数≤片段和×1.2。
【铁律】片段必须是原话连续子串,不编造、不跨到没给的句子。
【输出】{"hooks":[{fragments:[{sid,text}],stitched,why}]}
```

### 流程二 · ④ `REFINE_TASK`(去口水,⚠出free-text+兼做编排、待改字级删除决策)
```
对张和原话做【精修】,产出能直接当成片用的脚本。
【必须做】1.去口水:删"啊/嗯/这个/那个/然后/就是/对吧/你知道吧"等口头禅与口吃;同句重说只留一遍最顺的。
  2.去重复+顺语序:把绕回、同意思的几句合并成一句,语序可调。  ← ⚠ 这是"编排",该上交②总编
  3.开篇独立:第一句不承接上文,剪掉承接/转折词。 4.结尾干脆:不停在"那接下来…/后面再说…"。
【铁律】只用原话出现过的字词,不新增观点、不改写实质——是"删和理顺",不是重写。
【输出】{"refined":"精修后纯文本"}   ← ⚠ 应改成"字级删除决策(删哪些字、带位置)",纯文本对不回原视频
```
