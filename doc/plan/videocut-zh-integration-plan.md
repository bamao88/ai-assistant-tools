# videocut-zh 集成计划：把"更好的剪辑流程"嫁接进我们的视频体系

> 读者 = 产品经理。这份文档讲**要做什么、长什么样、分几步、哪些要你拍板**。
> 不讲代码实现细节。技术落点交给后续 AI，按本计划执行。
> 状态：**草案 · 待产品决策**（见 §6）。日期：2026-06-16。

---

## 1. 一句话目标

把外部项目 `videocut-zh` 里**更成熟的"选片 + 去口水 + 内容编排"方法**，嫁接到我们现有的视频成片体系上；
**剪辑判断用它的，视觉呈现用我们的**；并**新增一种横屏成片能力**（我们现在只有竖版）。

---

## 2. 先厘清一个关键认知（决定整份计划怎么写）

很容易把 `videocut-zh` 当成"一套更好用的剪辑工具"直接搬过来——**这是误解**。实际盘下来：

| 它看起来是 | 它实际是 |
|---|---|
| 一套自动剪辑工具 | **一套方法论 + 半自动脚本**：关键的"哪句留、哪个字删"是**人/AI 手工填**的，脚本只负责执行 |
| 可以直接跑 | **Windows 来源包**：硬编码 Windows 路径、Windows 字体、绑定火山 ASR、要把音频传公网——**在我们机器上不能直接跑** |
| 视觉效果是核心 | **视觉是它的短板**（你也认同），它真正值钱的是**判断规则和方法论** |

所以**真正值得复用的只有 4 样无形资产**，不是它的代码：

1. **去口水规则**（语气词/卡顿/重复/残句怎么删 + 🚨"承接句保护"红线）——它最值钱的一章。
2. **选片方法论**（认知增量优先、富集度≥3、宁缺毋滥、问答也能剪）。
3. **内容编排规范**（手机端可读：字大字少、大数字对比、点名具体产品、开场点题卡）。
4. **横屏成片这种产物形态**（16:9，适合某些平台/场景）。

> **结论**：这是一次"**把别人沉淀的判断标准，灌进我们已有引擎**"的集成，不是"换一套工具"。
> 前 3 样是**纯内容/规则**，几乎零架构改动；第 4 样（横屏）才是真正要新建能力、需要你拍板的部分。

---

## 3. 我们现有体系长什么样（一句话回顾）

我们已经有一套四层的视频体系（详见 `doc/video-skill-architecture.md`）：

```
选片/去口水(决策层) → 框架页竖版渲染(视觉层) → 叠加(字幕/进度条/结尾卡) → 组合层(总指挥)
```

- 视觉风格：**竖版 720×1280**、框架页、圆形摄像头小窗、药丸字幕——**只有竖版**。
- 定制方式：每个账号的"选题口径/术语/版式"都集中放在 `profiles/<账号>/`，**不散回各业务项目**。

videocut-zh 的东西，就是顺着这套结构"**往对应的层里塞**"。

---

## 4. 集成蓝图：哪样东西塞进哪一层

| videocut-zh 的资产 | 塞进我们的哪一层 | 改动性质 | 影响产物 |
|---|---|---|---|
| ① 去口水 + 承接句规则 | **决策层**（去口水/纠错的"判断标准"） | 灌规则文本，**不改架构** | 竖版 & 横版都受益 |
| ② 选片方法论 | **决策层**（选片 persona） | 灌规则文本，**不改架构** | 竖版 & 横版都受益 |
| ③ 内容编排规范 | **决策层**（"每页放什么"的内容标准） | 灌规则文本，**不改架构** | 竖版 & 横版都受益 |
| ④ 横屏成片形态 | **视觉层**（新增一条横屏渲染路径） | **新建能力**，要你拍板 | 仅横版 |

**关键设计原则（这条最重要）**：
> **"内容"和"视觉"必须解耦**。"这一页讲什么、放哪个大数字"是内容；"用什么颜色、字幕什么样、横还是竖"是视觉。
> 解耦之后：**同一份内容，既能出竖版（我们现有视觉），也能出横版（新视觉），共用前面的选片和去口水判断。**

用图说话：

```
        ┌─────────── 共用的"判断/内容"前段（采纳 videocut-zh 的规则）───────────┐
素材 →  选片  →  字级去口水 + 承接句保护  →  内容编排（每页讲什么/大数字/点题卡）
        └──────────────────────────────────────────────────────────────────────┘
                                   │
                  ┌────────────────┴────────────────┐
                  ▼                                  ▼
        竖版渲染（我们现有视觉）            横版渲染（新增·用我们的配色+字幕风格）
        框架页 / 圆窗 / 药丸字幕            16:9 版式 / 方框适配横屏 / 同一套配色
                  │                                  │
                  ▼                                  ▼
            竖版成片（不变）                     横版成片（新产物）
```

## 5. 分阶段路线（先稳赢，再啃硬骨头）

### 阶段一：采纳判断规则（稳赢，零架构风险）—— 建议**先做**
把 videocut-zh 的**去口水规则 + 承接句红线 + 选片方法论 + 内容编排规范**，整理成我们账号的"判断标准"，放进 `profiles/zh_main/`。
- **价值**：立刻提升我们**现有竖版**的内容质量（更不容易剪秃、逻辑不断、选片更准）。
- **不依赖任何待决策项**，不碰架构，可单独验收、单独上线。
- 产物形态完全不变，风险最低。

### 阶段二：内容/视觉解耦（打地基）
把"每页讲什么"和"怎么渲染"在结构上分开，让同一份内容能喂给不同的渲染后端。
- **价值**：这是横屏能力的前提；做完之后竖版照旧、不受影响。
- 对产品来说是"看不见的地基"，但没有它就没有阶段三。

### 阶段三：新增横屏渲染（要你先拍板 §6，再启动）
按你确认的横屏视觉方向，新建一条横版渲染路径，**复用我们的配色 + 字幕风格**，吸收 videocut-zh 适合横屏的版式（如方框布局）。
- **价值**：解锁横屏成片这一新产物形态。
- **代价最大**：是真正的新功能开发，且依赖 §6 的决策。

### 阶段四（可选）：ASR / 转写链路决策
是否引入 videocut-zh 的火山字级转写，取决于 §6 的决策。可以推迟，也可以完全不做（沿用我们现有的转写）。

> **建议节奏**：阶段一立刻做并上线见效 → 阶段二打地基 → 你拍板 §6 后再上阶段三。
> 不要等横屏决策才动手——前两阶段的收益与横屏无关。

## 6. 待你拍板的产品决策（这几条不定，阶段三/四没法开工）

### 决策 A：横屏成片的视觉，到底走哪条路？（最关键，卡住全局）
你的原话有半句被截断了（"……方框其实是比较适合横屏的表现方__"），所以这条我给三个选项 + 我的推荐：

| 选项 | 含义 | 代价 | 适合谁 |
|---|---|---|---|
| **A1（推荐）** | 新建横屏渲染，**用我们的配色+字幕风格**，吸收它适合横屏的版式（方框等） | 中：新建一条渲染路径 | 想要"横屏 + 我们的质感"统一品牌 |
| A2 | 横版直接照搬 videocut-zh 的视觉（含它的字幕/配色），不嫁接 | 低：但视觉是它的短板 | 只想快速有个横版、不在意视觉一致 |
| A3 | 只把横屏当成一种"版式"，把我们的样式塞进它的画图工具 | 中高：技术耦合较深 | （一般不建议） |

> **我推荐 A1**：因为你反复强调"视觉效果还是用我们的、字幕用我们的、配色用我们的"，A1 最符合你的本意——**保留横屏这个形态，但披上我们的视觉外衣**。
> **请你补一句**：被截断的那半句到底想说什么？（方框适合横屏，所以横版要保留方框布局？还是别的？）这会直接影响 A1 怎么落地。

### 决策 B：横屏和竖版是什么关系？
- B1：**两种产物并存**——同一条片子，既出竖版又出横版（按平台选）。
- B2：**横屏只服务特定场景**（如某平台/某类内容），不是每条都出。
> 这影响工作量和默认行为，请给个方向。

### 决策 C：转写/ASR 要不要换？（有合规风险，请重视）
videocut-zh 的字级转写**绑定火山 ASR，且要把音频上传到公网中转**。
- C1：**只采纳它的"去口水规则"，转写仍用我们现有的**（不换供应商、不传公网）—— **我推荐这个**，规则和供应商本来就能分开。
- C2：整套换成火山字级转写（要新凭证 + 接受音频上公网）。
> ⚠️ **客户/会议素材上传公网是合规红线**，除非有明确理由，建议不碰（选 C1）。

## 7. 风险与合规（产品要知道的几条）

- **公网上传素材**：videocut-zh 默认把音频传到公网中转站做转写——**涉及客户隐私/合规**，默认不采纳（见决策 C）。
- **凭证管理**：若引入火山，需要新 API key，统一放我们的凭证目录（不进代码库）。
- **不要直接搬它的代码**：Windows 硬编码路径 + Windows 字体，搬过来跑不了；我们采纳的是**规则和方法**，代码按我们的体系重写。
- **竖版零回退**：所有改动必须保证**现有竖版成片效果一帧不变**（我们有逐帧回归验收门兜底）。

## 8. 怎么算做成了（产品级验收）

- **阶段一**：拿同一条素材，用新规则跑出的竖版，**逻辑更连贯、不剪秃、选片更准**（人工通读验收）。
- **阶段二**：同一份内容能分别走竖版/横版两个渲染后端，竖版效果不变。
- **阶段三**：能产出一条横屏成片，**配色/字幕是我们的风格**，版式适合横屏、手机上一眼能看清。
- **全程**：现有竖版生产线不受影响，可随时回退。
