## 一句话目标

把"录屏 demo 竖版切片"这条线，从 `var/` 里的一堆手搓脚本，**梳理成"引擎里的正式原子 + 一条配方 + 几道自检闸门"**——让 AI 每次切片照着配方跑，字幕对不上这类坑在交付前被闸门当场拦下，而不是等你看片才发现。

**为什么现在做**：clip_01 那次，同一个"字幕和声音对不上"反复出现、以为修好又复发（详见踩坑日志 ③④⑤）。根因是流程散、没有客观的"过/不过"卡点。这次把它收成熟。

## 一、前置条件（上游已备好，本流程不生产）

这条流程的起跑线是 `var/zh_main/0618test/source/` 三件套，**全是上游交付物**：

| source/ 里 | 是什么 | 谁产的 |
|---|---|---|
| 源视频.mp4 | 原始录屏/大录像 | 拍摄阶段 |
| `words.json` | **整条**录像的逐字转写（2048 句 / 约 3.27 小时，每个字带时间） | **转写阶段（上游）——本流程不转写** |
| 源视频_audio.wav | 从视频拆出的音频 | 上游 |

→ **转写是前置条件，不是本流程的步骤。** 本流程拿到的就是「视频 + 逐字稿 + 音频」，从这儿开始切。

> 唯一例外：当「闸门2 对齐自检」抓出后半段字幕漂移时，临时把拼好的那段身子**重转一次**——那是补救动作，不是常规步骤（见下文根因 B）。

## 二、这条流程在整张剪辑大图里的位置

工具仓的视频能力，按架构文档是一条主链，都在引擎里、由 `video-compose`（编排层，唯一对外入口）用「配方 recipe」串起来：

```
   选段决策              渲染成片                    叠加收尾
 video-slicer  →  video-framework-render   →   video-clip    →  成片
 (定剪哪几段)      (框架页 / 字幕 / 变速)          (标题/钩子/结尾卡)
       └──────── video-compose 用「配方」把上面这些原子串起来 ────────┘
```

- **原子（atom）** = 最小的、能单独调用的视频处理积木（如"拼接""加标题"）。
- **配方（recipe）** = 把若干原子按顺序串起来的预设清单，AI 选一条配方就能端到端跑。
- **编排（orchestration）** = 配方按顺序调原子这件事本身。

**本次的 0618test，本质是这条主链尾段（出字幕 → 去静音 → 变速 → 加标题 → 拼钩子）的一个手搓变体**，服务的是一条**新产品线**：「录屏 demo 竖版切片」（源是产品录屏，画面靠 crop 裁成竖版、mask 盖掉录屏 UI 按钮）。它跟线上那条 `zh_business` 框架页配方（幻灯片翻页 + 圆形人像）**不是同一条**。正因为是新线、没现成配方，它才落在 `var/` 里手搓——这就是它"不成熟"的根。

## 三、流程本体：7 步流水线 + 3 道自检闸门（动态可反馈）

这就是要固化的"流程"。它**不是纯代码**：主体是一份 AI 照着走的稿子（runbook），关键步后面卡一道"体检"——AI 跑个几十秒的小脚本读出数字，自己判断过/不过，不过就按决策树拐弯。

### 7 步流水线（跟着 clip_01 走）
| 步 | 干嘛（大白话） | 进 → 出 |
|---|---|---|
| 1 拼身子 | 按 `clip_NN_spec.json` 把录屏里那几段抠出来拼成一整条（顺手 crop 去外框、mask 盖 UI 按钮） | 源视频 → `_body_裁剪.mp4`（**107.7s 身子**，原速、带停顿） |
| 2 取字 | **不转写**，从 `source/words.json` 里把这几段对应的字+时间抠出来 | words.json → 该片用到的字 |
| 3 做字幕 | 排成药丸字幕：去口水（删"啊/嗯"）+ 分句 + `fixes.json` 改专业名词（**时间戳一个不动**） | → `clip_NN.ass`（时间轴=107s 身子） |
| 4 烧字幕 | 把 .ass 印到 **107s 身子**上（带 `-fps_mode passthrough` 防变帧率漂移） | → 107s 带字幕视频 |
| 5 去长静音 | 拿干净人声当尺子，把 >1.5s 的长停顿剪短；同一套剪法同时套到画面+字幕+人声 | → 短一点的带字幕视频 |
| 6 换音轨+变速 | 换上 demucs 分离的干净人声，整体 1.2 倍速（画面/字幕/声音一起加速，变速不变调） | → `clip_NN_裁剪版_字幕.mp4`（**78.683s**） |
| 7 加标题+拼钩子 | 顶部贴 ✅ 标题 + 前面接开篇钩子和翻页 | → `clip_NN_成片.mp4`（可发布） |

### 3 道闸门（把无声的坑变成当场报数）
- **闸门0 标题取对没**（第7步前）：打印要烧的标题，确认取的是「标题候选」节带 ✅ 那条，不是「封面标题候选」那条。
- **闸门1 身子认对没**（第4步前后）：烧之前比 `.ass` 末条结束时间 ≈ 要烧视频时长（都该 ~107s）；出片后比成片"裁剪版"段时长 == 基准（clip_01=78.683s）。**专防"把 107s 字幕烧到 78s 成品上"那个坑。**
- **闸门2 字幕真贴着声音吗**（第7步后，最关键）：在音频上找每句"起音点"、在字幕上找每条"切换点"，两两配对算偏差（`off=+2.35` = 字幕比声音晚 2.35s）。给 AI 一份报告（前/后半段最大偏差、超阈值的有几条在第几秒），AI 按决策树走：
  - 全段 ±0.3s 内 → ✅ 过，交付。
  - 只有后半段差、越往后越大 → 判定**根因 B**（长源深处时间戳漂移），自动改走"重转写实际身子"出字幕（`build_subs_retime`），从第2步重跑再过闸门2。
  - 前半段就乱 → 多半烧错身子（**根因 A**），回闸门1 查。

> **两条铁律（写进流程禁止动作清单）**：① 改词只动 `fixes.json` 做文字替换，时间戳永远来自转写、从不手填；② 永远从 107s 身子重跑流水线，绝不改成品、绝不把字幕烧回成片。

### 我们到底反复栽在哪（根因小结）
| 根因 | 大白话 | 哪道闸门兜住 |
|---|---|---|
| A 烧错身子 | 107s 的字幕烧到了 78s 成品上，越往后越偏 | 闸门1 |
| B 长源深处时间漂移 | 字时间来自 3 小时大转写，取到尾部就飘 | 闸门2 → 自动重转写 |
| C 变帧率重采样 | <0.05s 小漂 | 第4步固定带 passthrough（已内置） |

## 四、原子拆解：本次能力 vs 引擎已有（核心对照）

整个流程 = 一串原子的编排。把 `var/` 这堆脚本拆开，每个"原子活"和引擎现有原子对一遍，分三桶：

### 桶① 已在复用引擎原子 ✅（方向对）
| 0618test 里的活 | 调的引擎原子 |
|---|---|
| 拼开篇钩子+翻页定格 | `video-clip/prepend_hook` |
| 顶部贴纸标题 | `video-clip/title_bar --style label`（本次刚加进引擎） |

### 桶② 重复造轮子（引擎**已有**，又在 var/ 写了一遍）
| var/ 脚本里的活 | 引擎里早就有的原子 | 问题 |
|---|---|---|
| `build_subs.py` 出**药丸字幕 ASS** | `video-framework-render/subtitles`（标定字宽居中药丸 ASS + 术语纠错） | 同一种药丸字幕两份实现，几何/画法各写一份易跑偏 |
| `build_subs.py` 的**去口水** | `video-slicer/cut_word` 去口水（references 删前保后+承接句红线） | 判断基底重复一份 |
| `build_subs_retime.py` 的**重转写** | `video-slicer/transcribe`（火山主+阿里兜底） | 转写已有，retime 里其实也是调它 |
| `finalize.py` 的 **1.2x 变速** | `video-framework-render/accelerate` + `video-clip/speed_adapt` | 变速已有两种口径，这是第三种"固定倍速" |
| `assemble.py` 的**硬切拼接** | `video-clip/concat` | concat 已有，assemble 内联又写一份 |
| 烧 `.ass` 到画面 | `video-clip/subtitle_burn`（走 srt） | 半重叠：它吃 srt、我们吃 ass；title_bar 内部也烧 |

### 桶③ 真·新增（引擎**确实没有**，值得沉淀成新原子）
| var/ 里的活 | 为什么是新的 |
|---|---|
| `trim_silence.py` **去长静音**（拿干净人声当尺子，同区间同步套到画面+字幕+音频） | 引擎无任何"去长停顿"原子 |
| `assemble.py` 的 **crop 去录屏外框 + mask 盖 UI** | 框架页线不需要（它是渲染的），录屏线专属 |
| **闸门1 时长核对** / **闸门2 对齐自检** | 引擎无"自检"类原子。**这是把"看片才发现"变"当场报数"的核心价值，本次最该沉淀的东西** |
| demucs **人声分离**出干净人声 | 上游产物，待确认是否在本流程内跑；引擎无独立原子 |

## 五、归位方案：所谓"梳理成熟"具体做四件事

1. **桶③ 真新增 → 沉淀进引擎当正式原子**：`trim_silence`（去长静音）、`screencast_crop_mask`（录屏裁切+盖UI）、`align_check`（对齐自检）、`len_check`（时长核对）。各写进所属引擎 `capabilities.json`，跑 `build_catalog.py` 进总表。
2. **桶② 重复的 → 废掉手搓版、改调引擎原子**（药丸字幕走 `subtitles`、变速走 `accelerate`、转写走 `transcribe`…）。若确有非自己一套不可的理由（如 build_subs 的"字级直接定位"是 subtitles 没有的），就**明确写下为什么**，而非默默并存两套。
3. **整条流程 → 写成 `video-compose` 一条新配方**（暂名 `screencast_vertical`），`chain` 按序列原子 + 在关键步插闸门。以后任何批次/账号 `selector` 选这条配方即可跑，不用再翻 var/。
4. **业务胶水留薄**：`finalize_clip.py` 里"从 item 取 ✅ 标题、clip↔item 映射"这种纯业务杂活，留薄胶水层。

### 落地形态（不是纯代码）
- **一份 runbook**：7 步 + 3 闸门 + 决策树 + 禁止动作清单（AI 每次照走）。
- **几个几十行 check 脚本**：闸门1 比时长、闸门2 算对齐偏差（闸门0 复用现成 `--print-title`）。
- **一张"每片体检表"**：AI 跑完填数字（取的标题/身子时长/成片时长/前·后半段最大偏差），你扫一眼就知道这片稳不稳，不用看完整片。
