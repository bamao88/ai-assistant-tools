## 〇、一句话目标

火山转录里**本来就带**标点、句界、书面数字（"90%"），但目前在"去口水"和"出片"两步被丢成了裸字。这份计划把这份原生信息**一路带到底**，让成品字幕、文案、以及喂给 AI 生成 PPT 的输入，都是**带标点、带"90%"、按语义断好的句子**。

---

## 一、先厘清：火山给的是"一个文件、两层数据"（不是两个文件）

火山转录回来，我们解析成**一个文件** `words.json`，里面有**两层**：

| 层 | 字段 | 里面有什么 | 大白话 |
|---|---|---|---|
| **句层** | `sentences[]` | 火山按**语义**切好的整句，**带标点**、数字是 **"90%"**，每句带起止时间戳 | 一整句话，标点、阿拉伯数字、句子边界都在这层（火山的识别优化都在这） |
| **字层** | `words[]` | 一个一个字，每个字只带时间戳，**无标点**、数字是原始的"百分之九十" | 拆成单字 + 时间，专门用来对齐到视频的精确秒数 |

> 大白话：**句层负责"内容好不好读"（标点、语义、书面数字），字层负责"切到视频哪一秒"（精确时间）。** 这次的核心就是——内容用句层，时间用字层，两层各司其职、最后合起来。

这一层已经做好了（上一轮 `backends.py` 已经把 `sentences[]` 收下来存进 `words.json`）。

## 二、完整切片流程：每步「输入 → 输出」+ 真实片段

> 下面每步都配一段**真实数据**（取自 `var/zh_main/cuts/agent全量`，张和讲 Agent 的一条）。
> 步骤2 按你的提醒**拆成两层**：先 2a「出所有选题」，再 2b「给每条选题定边界」。

```
┌────────────────────────────────────────────────────────────────────────────┐
│ 步骤1 火山转录                                                                │
│ 步骤2 选题   ─2a 出所有选题(18-25条) ─→ 2b 每条选题定边界(覆盖哪几句/时间)      │
│ 步骤3 去口水  ★改动①输入升级  ★改动②对齐回字层拿时间                          │
│ 步骤4 出片    clip.mp4 / clip.srt / clip.txt / PPT输入(读srt)                  │
└────────────────────────────────────────────────────────────────────────────┘
```

### 步骤1 · 火山转录
- **IN**：源视频 + 火山 API
- **OUT**：一个 `words.json`，两层 ——

```jsonc
{
  "words": [                                  // 字层：每个字 + 毫秒时间戳，无标点
    {"text": "真", "begin_time": 305660, "end_time": 305820},
    {"text": "的", "begin_time": 305820, "end_time": 305980},
    {"text": "百", "begin_time": 330100, "end_time": 330240}, … // “百分之九十”是 5 个字
  ],
  "sentences": [                              // 句层：整句带标点 + ITN(90%) + 句时间戳
    {"text": "真的不要做低代码了，完全干不过 Agent。", "begin_time": 305660, "end_time": 312400},
    {"text": "今天用 Codex 能解决的，低代码只能解决30%，水平能差5到10倍。", "begin_time": 312400, "end_time": 367210}
  ]
}
```
> 大白话：同一句话，句层是"真的不要做低代码了，**完全干不过 Agent。**"（带标点）；字层是"真/的/不/要/做…"一个个字配时间。**内容看句层，时间看字层。**

### 步骤2a · 出所有选题（stage1，你提醒补上的"选题层"）
- **IN**：句层 `sentences[]`（语义句，句界准）
- **DO**：AI 通读全部句子，**覆盖优先、宁多勿漏**地选出一批选题（目标 18-25 条），按流量潜力高→低排
- **OUT**：**一个选题清单**，每条选题是这样一个对象（此时**还没定边界**，只是"这个点值得做"）——

```jsonc
// 选题清单 = [ 选题1, 选题2, … 共约 20 条 ]，下面是其中一条：
{
  "title":       "为什么企业AI落地别再做工作流？Codex 比工作流强 5-10 倍",
  "hook_line":   "真的真的真的不要做低代码了，不要做工作流了，完全干不过 Agent",  // 0-3秒钩子(原话)
  "one_argument":"2025年后企业AI落地用 Agent+Codex 比传统工作流强 5-10 倍，95%场景不需要人工编排",
  "audience":    "AI从业者/创业者老板/转型求职",
  "mainstream":  "高",                         // 流量潜力 高/中/低
  "why":         "反认知 + 强观点，易传播"
}
```

### 步骤2b · 给每条选题定边界（stage2）
- **IN**：步骤2a 的每条选题 + 句层
- **DO**：AI 为这条选题定出"它覆盖逐字稿里哪几号句子"
- **OUT**：在选题对象上**补三个字段**（句号区间 + 句级时间段 + 估时）——

```jsonc
{ …(2a 的选题字段不变)…,
  "keep_sids":           [[59, 73]],            // 覆盖第 59~73 号句子（“句号区间”）
  "sentence_time_spans": [[305.66, 367.21]],    // 对应视频 305.66s~367.21s
  "est_duration":        61.5                    // 估时 ~61.5 秒
}
```
> 大白话：2a 回答"做哪些题"，2b 回答"每道题对应原片的哪几句、在第几秒"。两步合起来 = 完整的 `clips` 清单。

### 步骤3 · 去口水　★本次两个改动都在这步
- **IN（★改动①：升级成句层带标点文本）**：把这条选题覆盖句子的**句层文本**拼起来喂 AI——

```text
真的真的真的不要做低代码了，不要做工作流了，完全干不过 Agent。今天用 Codex 能解决的，
如果用低代码只能解决30%、20%甚至10%，水平能差5到10倍。除了极少数场景比如外呼客服…
```
- **DO**：AI 通读、**只删不改**地删口水（"真的真的真的"→留一个、删"嗯/那个"/重复/残句），保护承接句
- **OUT①　带标点 ITN 文案**（AI 直接吐出，这就是成品文案）：

```text
真的不要做低代码了，完全干不过 Agent。今天用 Codex 能解决的，低代码只能解决30%，水平能差5到10倍。
```
- **OUT②（★改动②：对齐回字层拿精确时间）**：把上面这段带标点文本逐字对回字层 → keep_spans

```jsonc
"keep_spans": [[305.70, 309.10], [312.40, 366.90]]   // 删口水后真正保留的精确秒段
// 对齐时 "30%" 当一个整块，绑定字层“百分之三十”那几字的时间；标点跟随前一个字
```

> 📌 **对比现状**（字级裸拼、无标点、未书面化、连错字一起拼）——这正是今天 `script` 字段的真实样子：
> `我要给大家讲一下真的真的真的不要做低发了不要做工作流了完全干不过agent…百分之九十…百分之三十…`
> 改后 → 带标点、`90%`/`30%`、"低代码"。

### 步骤4 · 出片
- **IN**：步骤3 的【带标点文案】+【keep_spans 精确时间】
- **OUT**：
  - `clip.mp4`：按 keep_spans 从源视频切出的干净片段
  - `clip.srt`：字幕，带标点 ITN ——

```srt
1
00:00:00,040 --> 00:00:03,460
真的不要做低代码了，完全干不过 Agent。
```
  - `clip.txt`：文案 = OUT① 那段带标点文本
  - **PPT/框架页 pages**：`pages_gen.py` **读 `clip.srt`** 作输入 → 字幕带标点，它自动也带标点（无需单独改）

## 三、这次到底改什么（两个改动点，对应步骤3）

### 改动① 去口水的"输入"从字级裸拼升级成句级带标点
- **现状**：喂给去口水 AI 的是字一个个拼起来的裸文本（"我们增长了百分之九十嗯那个效率翻了五倍"），无标点、数字没书面化。
- **改后**：喂句层带标点 ITN 文本（"我们增长了90%，嗯那个效率翻了5倍。"）。
- **好处**：AI 看得到标点和句界，判断"哪是口水、哪是不能删的承接句"更准；而且 AI **只删不改**地删完，吐出来的**就是带标点的成品文案**。

### 改动② 把去口水后的带标点文本"对齐回字层"拿精确时间
- **为什么还要对齐**：步骤4 切视频、做字幕都要**精确到秒**，而精确时间只在字层。所以要把"AI 删口水后的带标点文本"和字层逐字对回去，给每段文字配上时间。
- **唯一的难点 = 书面数字块**：文本里的 "90%" 在字层是"百分之九十"5 个字、3 个字符，对不上号。所以对齐时把 "90%" 当成**一个整块**，绑定字层"百分之九十"那 5 个字的时间（起=百、止=十）。**整块要么留要么删，绝不切成"90"。**
- 标点（，。？）字层没有，挂在它前面那个字/块上，前面留它就留、前面删它就删。

> 大白话：AI 给的是"读起来对的文字"，字层给的是"时间对的字"。改动②就是把这两样**逐字捏在一起**，配出"既带标点、又知道每段在视频第几秒"的成品。数字"90%"是唯一要特殊照顾的——把它当一个不可拆的积木。

## 五、降级边界（保证不断流，任何一步出问题退回今天的可用状态）

| 情况 | 行为 |
|---|---|
| 火山没返回句层（旧文件/换转写源） | 没有 `sentences[]` → 去口水退回字级裸拼输入、字幕/文案退回字级裸拼，**和今天完全一致** |
| 某段文本对齐不回字层（数字块对不齐等） | **只这一段**退回字级裸拼 + 打日志，其余正常带标点 |
| 去口水已有的"保留<50%就整段不删"保底（`script_clean.py:161`） | 继续生效，对齐在它之后 |
