## 三个核心问题，逐个回答

### Q1：会不会影响选片？ → 会，幅度中等（你的担心是对的）
- 新版 **22 条** vs 旧版 **24 条**。
- 新版里 **16/22 条**和旧版"选的是同一段"（时间重合>50%）；**6 条**是新版才有或边界明显不同。
- **结论**：把分句从"按停顿猜"换成"用火山语义句"，**确实改变了选片**——约四分之一的片子边界/取舍变了，总数 24→22。新选题标题质量看着是正常甚至更聚焦的（如"评测优先级>训练""1-5分拆成是非二分类"），不是变差，但**它确实是一个会动选片的改动**，不能当"只影响字幕"。

### Q2：真实文案/字幕质量怎么样？ → 标点真带上了，但"90%"只兑现了一半（火山的锅）
- ✅ **标点**：21 条文案/字幕都带逗号句号，断句自然、可直接读。
- ⚠️ **书面数字（90%/5倍）不稳**：**火山自己的 ITN 时灵时不灵**。同一条里都能看到——"在**95%**以上的场景"（书面化了）紧挨着"只解决**百分之三十**、**百分之二十**""差**五倍到十倍**"（没书面化）。
  - **这不是我们代码的问题**：我们忠实保留火山给的文本，火山给中文数字我们就显示中文数字。需求里"数字显示成 90%"这条，**取决于火山 ITN，目前只部分兑现**。
- ⚠️ **ASR 错字仍在**："低代码"→"低发"、"Anthropic"→"爱马仕"、"Claude Agent SDK"→"cloud agent sdk"。因为去口水是"只删不改"，纠错是后面 `srt_fix` 阶段的事，本次没动。

### Q3：原生句↔字级 对齐靠不靠谱？ → 95.5%，失败的那条也不断流
- **21/22 成功**（`_align_stats.json`）。
- **1 条失败**：clip_12「打分别用**1~5分**」——文本里的 `1~5` 这种**区间号（~ / - / 到）**我的数字块识别没覆盖，于是**整条降级回字级裸拼**（没标点，但照常出片、不报错）。
- **这正是真实数据的价值**：假数据测不出"1~5"这种写法。修复很小（数字块识别加上区间分隔符），预计能把 95.5% 推到 ~100%。

## 顺带验证（澄清一个我自己的疑虑）
