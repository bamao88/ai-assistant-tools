# 需求：转写保留火山原生语义信息（句界 / 标点 / 书面数字）

> 读者 = 产品经理。讲清楚**为什么要改、改了有什么好处、改哪里、怎么验**。轻技术。
> 状态：**需求已提，代码改动随本轮一起做（待火山实跑验证）**。日期：2026-06-16。

---

## 一、背景：现在的分句是"靠停顿猜"的，不是语义

字级线第一步是**分句**（把一串带时间戳的字，切成一句一句）。现在的做法：

> **两个字之间的停顿 ≥ 0.5 秒，就在这里断句。**（纯代码算法，不调 AI、不靠人工）

这是个**启发式**——靠"说话人换气的停顿"来猜句子边界。问题：
- 说话人**长换气**：一句话中间停了一下 → 被切成两半。
- 说话人**语速快不停顿**：两句话连着说 → 被并成一句。

对"粗选片"够用，但句界不准会让后面的脚本边界、去口水也跟着不准。

## 二、关键发现：火山其实**直接给了语义句**，但被我们丢了

火山 seedasr 转写返回的**原始结果本来就带语义信息**，但中间的转换/解析把它**拍平成纯字数组**，丢掉了三样有用的东西：

| 火山原本返回 | 是什么 | 现状 |
|---|---|---|
| **utterances（语义句）** | 火山已经按**语义**切好的一句一句，每句自带起止时间戳 | ❌ 被拍平丢了，我们只能靠停顿重新猜 |
| **标点** | 逗号句号问号（开了 `enable_punc`） | ❌ 被当"无时间戳占位"过滤掉了 |
| **书面数字 ITN** | "百分之九十" 自动写成 **"90%"**、"五倍" → "5倍"（开了 `enable_itn`） | ⚠️ 整段文本里有，但逐句/字幕没用上 |

**一句话**：火山已经把"语义句 + 标点 + 数字书面化"都算好递给我们了，我们却把它拆成纯字、又自己用停顿去拼回句子。**用它原生的，比我们猜的好得多。**

## 三、需求

1. **分句优先用火山的原生语义句**（utterances）：句界更准、更接近"人理解的一句话"。
   - 火山没给 utterances 时（或换了别的转写源），**自动降级回"按停顿切句"**（保底，不会断流）。
2. **保留标点**：字幕和文案带上逗号句号，读起来更顺、更专业。
3. **用书面化数字**：文案/字幕里显示"90%""5倍"，而不是"百分之九十""五倍"。

## 四、收益

- **句界更准** → 选片边界、去口水都更稳（少切半句、少并句）。
- **字幕 / 文案更干净专业** → 带标点、数字写成阿拉伯数字，直接能用，不用再人工修。
- **不增加成本** → 这些信息火山**本来就免费返回**了，只是之前被丢了，不用多调一次。

## 五、改哪里（技术落点，每条配大白话）

| 改动 | 大白话 |
|---|---|
| `transcribe/backends.py` 解析火山结果时，**额外保留 utterances（句+时间）和标点** | 接火山结果的那一步，别再只抠字、把句子和标点也收下来 |
| 转写输出（words.json）**新增 `sentences` 字段**（原生语义句） | 转写产物里多存一份"火山切好的句子" |
| `transcribe/segment.py` **优先用 `sentences`，没有才按停顿切** | 分句那一步：有现成的语义句就直接用，没有再退回猜 |
| 字幕/文案文本**优先用带标点、ITN 的版本** | 出字幕时用带标点和阿拉伯数字的那版文字 |

## 六、验证 & 边界

- ⚠️ **本轮代码就绪，但要等下一次火山实跑才能验证**：我们手上的转录文件是**已经拍平后**的（句界/标点早没了），测不出效果。需要用火山 key 重新转一遍才能看到原生语义句。
- **向后兼容**：旧的拍平文件、或火山没返回 utterances 时，**自动降级回停顿切句**——不会因为这次改动断流。
- 这次只改"转写保留 + 分句优先级"，**不动选片/去口水/切片**逻辑。
