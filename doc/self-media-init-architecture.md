# 自媒体账号项目初始化

`self-media-init` 把新账号的空文件夹或已有零散资料整理成可开始运营的项目。它负责基础建档与交接；实际博主研究、写作、内容准备和发布由对应能力承接。

在目标项目调用 `$self-media-init`，说明平台、内容方向和已有资料；也可以明确要求新建某个路径。目标目录属于旧账号时，必须先明确新账号放在哪里。仅要求检查则保持只读。

## 三种使用方式

| 方式 | 结果 |
|---|---|
| 新建 | 盘点资料后建立最小项目，不要求先有完整定位 |
| 补齐 | 复用已有库、规则和 ID，只补缺口 |
| 检查 | 报告缺口与下一步，不改文件 |

新项目默认本地文件，不安装数据库服务、不绑定飞书、不自动配置四个子 Agent。已有数据库/协作表格继续作为主库，避免两套账。新账号不继承模板来源项目的身份、平台限制或私人工作线。

## 文件如何分工

- `skills/self-media-init/SKILL.md`：从盘点、建档到检查交接的工作流与能力路由。
- `references/data-contract.md`：数据归属、ID 关联、状态和去重；执行时适配为目标项目的 `DATA.md`。
- `references/acceptance.md`：完成检查、验证层级与维护者行为场景。
- `assets/project/`：配置、项目入口、定位、台账与交接模板；需适配，不整包覆盖旧项目。
- `agents/openai.yaml`：Codex 展示名称和默认调用提示。

账号运营数据全部留在用户选择的项目。Skill 不保存账号业务数据，也不执行一键建库脚本；由 Agent 先读取已有结构再选择创建或补齐哪些文件。

## 数据如何连起来

对标账号关联外部内容样本，样本和自有资料启发选题，选题形成作品，同一作品可以有多条平台发布记录。数据快照关联到具体样本或发布，复盘再引用这些证据。快照是“某时点看到的成绩”，不能拿最新值覆盖历史。

配置只存标识和路径，定位长文单独维护；新模板的 AGENTS.md 直接维护，不声明为 YAML 编译产物。已有项目若采用生成机制，按其原机制修改事实源与生成文件，不强制迁移。

## 能力接入

可按需衔接 content-creator-research、platform-fetch、content-topic-planning、source-longform-writing、content-production-prep、content-package-create、Agent-Publish、content-operations-ledger。须检查真实安装路径与平台支持；账号研究按平台与证据选择分支，不跨平台照搬指标。缺工具时可先用用户资料建档，接入状态与真实执行状态分开记录。

源文件位于 tools/skills，登记在 registry.yaml。Claude 与 Codex 由仓库 sync-skills.py 按 registry 的 hosts 安装同一源目录，避免两份 Skill 漂移。

## 完成边界与维护

初始化完成不表示已有对标结论、平台登录有效、内容发布成功或账号定位得到验证。交接要说明现在能开展什么、仍缺什么，以及第一轮验证的假设、产出、反馈与复盘时点。

更改模板字段时同步修改数据契约；更改后续能力时核验对应 Skill。验证至少包含 Skill 格式、工具清单和模板文件关系；模板检查不能代替真实账号输入、Agent 全流程和用户产品验收。此次验证记录见 `doc/plan/self-media-init-plan.md`。
