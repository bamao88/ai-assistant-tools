# 转录标准流程（六环第①环 · 01）

> 这是「把视频/音频转成逐字稿」这一步的**固定标准流程**。以后做转录（六环主链的第①环 `01`），就走这一条，别再每次想命令、调网络。已验证 **44 秒到 2.2 小时**的素材都能稳定跑通。

## 一、怎么用：一行命令

```bash
/Volumes/ExtSSD2601/AI_Assistant/tools/engines/video-slicer/transcribe-01.sh <视频或音频路径>
```

就这一行。中途可能弹**一次** Mac 管理员密码框（第①步要改本地网络路由），输一次就行——**VPN 不用关**。

跑完会在**视频旁边**生成一个 `transcript/` 文件夹，里面两份东西：
- `words.json` —— 每个字带毫秒时间戳的字级词表（下一环②选片 / 字幕要吃的就是它）。
- `transcript.txt` —— 全文纯文字，方便你直接读。

想把结果放到别处，加第二个参数指定目录：

```bash
transcribe-01.sh <视频路径> <你想要的输出目录>
```

## 二、这一行背后自动做了什么（5 步）

| 步 | 在干嘛（大白话） |
|---|---|
| ① **自动开本地分流** | 把转录要碰的几个网站（火山、阿里、上传站 uguu/0x0）的流量，钉到你家本地宽带出口，绕开海外 VPN。等价于「手动关代理」，但代码层做、**VPN 照开**，不影响你平时翻墙开发。 |
| ② **抽音频** | 把视频扒成一条小的单声道 mp3（2 小时的也就 ~45MB）。 |
| ③ **上传** | 把 mp3 传到公网临时空间 uguu.se（失败自动换 0x0.st），拿到临时链接。走本地出口，所以大文件也稳。 |
| ④ **云端转录** | 把链接交给**火山语音**（主），火山失败自动切**阿里**。边转边等，2 小时音频约 8 分钟。 |
| ⑤ **出结果** | 写 `words.json` + `transcript.txt`。 |

## 三、为什么要这么绕（一句话原理）

你的 Mac 平时挂着海外 VPN（东京出口），调火山/阿里这种**国内**服务会从海外绕一圈回国内——又慢又容易被拦。**之前 2.2 小时那条就是卡在「上传」这步**：上传站走了海外出口，45MB 大文件传不动、超时失败。

这套流程的关键就是：**把整条链路（上传 + 调接口）都钉回本地出口**，复刻你「关代理能跑通」的那条路，但不用真关 VPN。

## 四、故障速查

| 现象 | 怎么办 |
|---|---|
| 弹管理员密码框 | 正常，第①步开本地分流要改路由表，输一次即可。 |
| 报「上传失败 / 传不上去」 | 八成是本地分流没生效。脚本每次都会自动开，**直接重跑一次**通常就好。 |
| 想确认分流真生效了 | `engines/route-bypass/scripts/publish-network-preflight.zsh transcribe status`，看 IP 都走 `en1` 之类本地网卡，不是 `utun*`。 |
| 别用 `--uploader oss` | 阿里 OSS 上传通道的凭证 **2026-06 已过期、已停用**，默认 public 就够。续期后写回 `var/credentials/aliyun.env` 并设 `OSS_CHANNEL_EXPIRED=0` 才恢复。 |
| 字幕跟声音对不上 | 那是另一条已知问题（逐字稿时间漂移），不在本流程范围，见 `doc/bug/字幕音频5秒错位-words时间漂移`。 |
