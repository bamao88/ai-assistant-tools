# OpenClaw 和 Claude Code 是两种不同的 AI 协作范式

Peter Steinberger 在 PSPDFKit 干了 13 年，烧完了自己。2025 年 4 月，他重新摸了一下代码，发现世界变了——AI 已经能处理那些让人窒息的重复性管道工程。他造了一个叫 Clawdbot 的东西，后来改名 OpenClaw，三个月拿下 GitHub 24.7 万颗星。2026 年 2 月 14 日，情人节，他宣布加入 OpenAI。

与此同时，Anthropic 的 Claude Code 在终端里安静地跑着。没有 24 万星，没有 WhatsApp 群组，没有 5000 个社区 Skill。它只做一件事：读你的代码库，改你的代码库，跑你的测试，循环直到通过。

这两个工具我都用，它们解决的是完全不同的问题。但如果你只看表面——"都是 AI Agent 嘛"——你会错过一个更有意思的问题：我们到底想让 AI 在什么层面接管我们的工作？

---

## 两种工具的核心定位

用一句话概括两者的差异：

> Claude Code 是你雇的一个顶级程序员，它只写代码，但写得极好。OpenClaw 是你雇的一个全能私人助理，什么都能帮你跑腿，但你最好确认它跑的腿是对的。

这不是褒贬之分，而是**设计哲学**的根本差异。

---

## Claude Code 的核心设计

Claude Code 的核心信仰是 **Bash is everything**。它给模型配了一台本地电脑，拥有文件系统的最高权限：

1. 读文件用 `cat` 命令
2. 搜代码用 `grep` 正则检索
3. 跑测试用 `pytest` 框架
4. 提交用 `git commit` 工作流

没有花哨的 UI，没有消息平台集成，整个交互界面就是一个终端。这听起来很原始，但恰恰是它强大的原因。

这里面有一个非常精妙的设计叫**渐进式披露（Progressive Disclosure）**。Claude Code 不会一次性把整个代码库塞进上下文窗口——那会爆掉。它按需搜索，用 `grep` 和正则表达式实时检索，而不是预先构建向量数据库做 RAG。

---

## OpenClaw 的五大核心模块

OpenClaw 有五个核心模块，各司其职：

| 模块 | 职责 | 类比 |
|------|------|------|
| Gateway | 接收所有外部请求 | 前台接待 |
| Agent | 理解意图并调度任务 | 项目经理 |
| Skills | 插件工具箱（5000+） | 工具库 |
| Channels | 连接各消息平台 | 通信系统 |
| Nodes | 在本地设备执行操作 | 执行工人 |

它支持多模型动态路由——简单任务用便宜的模型，复杂任务调 Claude 或 GPT。

---

## 安全性对比

安全性方面的差异不容忽视：

- **OpenClaw 的风险**：Cisco 的 AI 安全研究团队测试过其第三方 Skill，发现存在数据窃取和提示注入风险——Skill 仓库缺乏足够的审核机制来防止恶意提交
- **Claude Code 的保护**：在沙箱环境中运行，权限是显式和细粒度的，有专门的安全基础设施和定期审计

> 开源生态的老问题：自由带来的不只是创新，还有攻击面。

---

## 我自己的用法

我自己是这样分配的：

**写代码时**开 Claude Code，因为它对代码库的理解深度是 OpenClaw 根本比不了的——Opus 4.6 的推理能力加上 Context Compaction 机制，让它在大型重构任务中几乎不会把代码搞坏。

**日常碎片化任务**——在 Telegram 里让 AI 帮我总结一篇论文、设置一个提醒、查一下航班——这些事情 Claude Code 根本不是为此设计的。OpenClaw 的消息平台集成和 Skill 生态在这里碾压。

```bash
# Claude Code 的典型用法
claude "把认证模块从 session 迁移到 JWT，
        保持所有测试通过"
# 然后去喝杯咖啡
```

## 范式对比总结

| 维度 | Claude Code | OpenClaw |
|------|-------------|----------|
| 核心范式 | 深度控制 | 广度调度 |
| 使用界面 | 终端 | 聊天软件 |
| 覆盖领域 | 编程 | 全能 |
| 扩展方式 | 无插件 | 5000+ Skill |
| 安全机制 | 沙箱+细粒度权限 | 社区审核 |
| 适合用户 | 开发者 | 所有人 |

选择哪个，取决于你的问题是"我需要有人帮我把这段代码改对"，还是"我需要有人帮我把生活理顺"。

这两种需求都是真实的。而这两种工具，恰好代表了 AI Agent 从"信息检索"走向"任务执行"这场范式转移中，两条最清晰的路线。
