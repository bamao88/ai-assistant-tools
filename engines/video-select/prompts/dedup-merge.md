# 提示词 · 批量去重/合并（dedup-merge）

> ②选片·流程二之后的批量去重步骤的提示词。代码（`video_select/dedup.py`）整篇读入当 system prompt。
> 思路来自 videocut-zh「多候选 → 去重合并」，但**落点在流程二之后**：等每条选题都跑出了「实际切什么内容」，再对整批做内容级去重，比基于粗区间判断更准。

## 你的任务 · 对整批切片做去重/合并

下面给你**一整批已生成的切片候选**，每条含：序号 `idx`、标题、一句话论点、实际选段原文（这条最终要剪进视频的内容）。
请通读整批，找出**讲同一个观点 / 内容高度重叠**的切片，给出处理动作。目标：让最终这批切片**彼此不重复、各自独立成立**。

## 判断标准

- **高度重叠 / 同一观点** → `merge`：把这几条合并成一条。合并后从中选/拟一个最好的标题与论点（标题仍守原标题硬要求：带 AI/产品名、留悬念、≤20 字）。
- **被另一条完全覆盖、且更弱** → `drop`：删掉弱的那条，理由写清被谁覆盖。
- **独立、不重复** → `keep`：保留。
- 拿不准是否重复（只是话题相邻但论点不同）→ **倾向 `keep`**，不要过度合并（宁可留两条独立的，也不要把不同观点强并成一条）。

## 铁律

- **只对给你的真实 `idx` 操作**，不要编造序号。
- **不要改写选段原文**：你只决定「哪些合并、哪些删、哪些留」，不重写内容；合并后的选段由代码按你指定的 `idx` 取并集，你不用自己拼。
- 每条切片**只能出现在一个动作里**（要么 keep、要么 drop、要么属于某个 merge 组）。没提到的默认 keep。

## 输出（严格 JSON，无 markdown）

```json
{"actions":[
  {"type":"merge","idxs":[3,9],"title":"合并后的标题","one_argument":"合并后的一句话论点","reason":"两条都在讲同一个观点"},
  {"type":"drop","idx":14,"reason":"被 #2 完全覆盖且更弱"},
  {"type":"keep","idx":1,"reason":"独立观点"}
]}
```

`merge.idxs` 至少 2 个；合并组里 `idxs` 的第一个默认作主条（标题/论点以你给的 `title`/`one_argument` 为准）。只输出这个 JSON 对象。
