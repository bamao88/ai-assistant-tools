# persona: zh_main（张和 自媒体主号 · 招生破圈向）

> 两阶段选段共用的「编辑判断知识」。引擎通用，张和特定内容隔离在此文件。
> 换号/换博主：复制本文件改内容，引擎 `--persona <name>` 即可，不动代码。

## 这是谁

张和的一场口播 / 答疑。说话人里「张和」是主讲（host），其余是学员提问/闲聊。
切片只用张和原声当素材，学员的话一律不进切片。

张和的独家流量锚（能挂就挂进标题）：前小米 AI 实验室早期员工 / AI 出海公司 CEO / 一线用 Claude Code + Codex。

## 根本认知

切片不是「把逐字稿按话题分块」，而是「用张和的原话当素材，重新立一条短视频选题」。
判断标准永远是「陌生人刷到会不会停下来、看完记不记得住、想不想了解训练营」，不是「张和讲到了什么」。

## 选题闸：每条候选必须同时过这 5 关，过不了就不出

1. **独立可懂**：抽掉课堂内部语境后，零背景陌生人能看懂吗？（残留「第二步/咱们人不多/评论区打一下/上一期回放」这类现场语境的，要么换 in 点切掉，要么放弃。）
2. **单一论点**：这条只讲一个观点。张和把好几件事连着讲时，拆成多条，或只取最锋利的一段，不要一条塞 3 个点。
3. **值不值得切 = 看「反认知度」，不看「内不内行」**。判断标准是这个观点够不够反认知/戳痛/有冲击，而不是名词内不内行。⚠️ 常见误区：把「专有名词=内行=低流量」——这是错的。Claude Code、Codex、Karpathy、DeepSeek、腾讯、a16z、YC 这类专有名词/权威人物/机构，本身就是**搜索词、话题词、自带流量池**，是资产不是负债。真正该闸掉的只有「既没名词、又不大众、又不反认知」的纯冷门机制（某 CLI 怎么配、skill 内部结构、自研某平台架构）。
4. **价值一句话说清**：能用一句话说出「观众看完得到什么」。说不清=选题没立住。
5. **炸点可前置**：逐字稿里有没有一句张和原话，反认知或戳痛点，能当 0-3 秒钩子。把 in 点切到这句话前面，砍掉它前面的软铺垫。

## 标题/钩子硬要求（学竞品爆款，否则白瞎流量）

- **每条标题必须挂至少一个「流量锚」**：{自带流量的专有名词（Claude Code/Codex/Karpathy/DeepSeek/腾讯/a16z/YC…）| 权威人物或机构 | 具象数字+反差（如「3 个月」「80% 程序员」「全扔了」）| 身份标签（普通人/转型者/老板）}。题里有强名词就必须顶到标题最前，别翻译掉、别模糊化（反例：讲 Claude Code 却写「一个载入史册的产品」）。
- **句式默认疑问 / 反问 / 反认知断言，禁平陈述**。同赛道高赞几乎全是疑问句。反例（陈述）「AI Native 是一把手工程」；正例「为什么 AI Native 做不起来？十个有九个老板没亲自下场」。
- title 给最终钩子式标题（不是话题陈述）；hook_line 仍是逐字稿里张和真原话。

## in/out 点纪律（定切片边界用）

- 口播是张和原声，改不了内容，但能选 in/out。
- **in 点**：切到 hook_line 那句之前，丢掉「他现在就是…可能还没那么完美」「对吧那么第二步」这种软开场。
- **out 点**：论点说完就收，不要拖到他转下个话题。
- **允许跳接**：一条候选可由 2-3 个不连续片段拼成（中间砍废话），但拼接后逻辑要顺、按时间顺序。

## 数量纪律

一场挑 6-12 条精的即可，按大众流量潜力高→低排序。低流量 insider 话题除非特别锋利，否则不出。宁缺毋滥。
