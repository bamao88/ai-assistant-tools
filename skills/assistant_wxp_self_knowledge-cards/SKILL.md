# 八毛知识卡片

本包独立完成卡片制作。沿用宝玉方法的分析→大纲→逐页图文构想→风格组合→提示词流程；内容拆分吸收机器坏人作品调研中的阅读目的、材料关系与图文分工判断。所有执行方法、模板、画风资料与代表样例均在本目录；不要加载、调用其他 Skill，也不去外部资料目录寻找执行步骤。

第一版的阅读节奏和趣味可借鉴；v3 是历史作品选定版，画风仍非最佳。不要把单篇选择扩张成全局默认，不为了优化重写整套内容。

## 1. 恢复输入

读取本轮原文、用户确认的内容与反馈，区分新制作、修改、只做大纲、复盘。缺少真正阻塞的材料才询问；已经授权的制作和选择不重复确认。用户只要求复盘时不生图。

在八毛内容工作室项目（`/Volumes/ExtSSD2601/AI_Assistant/assistant_wxp_self`）内制作时，已有作品从 `state/content_index.yaml` 定位，复用 `content/items/<content_id>/`；新作品 ID 用 `WXP<YYYYMMDD>_<HHMMSS>_<SEQ>`，登记 drafted。同一内容不另建ID。项目文件是本轮输入与交付位置，不是方法依赖；在其它目录使用时按用户指定位置保存。

## 2. 分析内容

读本包 [内容分析框架](references/workflows/analysis-framework.md)，写 `analysis.md`：内容类型、读者已有理解、本次阅读目的、素材与来源、材料关系、可视化机会。先定整篇目的和解释深度：本篇回答哪个问题、需要哪些前提、哪些细节不展开。再把相关材料组成解释单元，逐一说明读者此前知道什么、借哪个例子或依据推进、读完能多理解什么，最后决定同屏或跨页。知识密度看建立了哪些有依据的关系、差别与判断，不按术语数或字数衡量。不做钩子评分、固定人群套画风或互动诱导。

选适合的组织策略，可组合，不强制每次输出三套方案：

| 策略 | 适合 | 组织方式 |
|---|---|---|
| A 故事驱动 | 个人经历、认识变化、体验 | 依据实际经历保留改变理解的过程 |
| B 信息密集 | 教程、比较、知识清单 | 依据前提、比较、并列或证据关系组织 |
| C 视觉优先 | 画面主导的情境、介绍或感受 | 让动作、对照、表情与停顿承担表达 |

三种策略是可选视角，不是固定篇章顺序。试排页数过多时，先检查解释深度和范围，移出次要分支、实现细节与旁支问题，不用连续拆页容纳所有知识；调整范围时保住主线的必要前提与因果关系，不能只删短句子。页数由收敛后的内容关系与手机阅读决定；一个问题可以跨几页，一页也可以并置多个事实或动作。用户指定页数时优先调整范围与分组，不缩字硬塞，也不机械按字数切片。

需要重新组织的知识解释内容，先写能脱离图片独立读懂的 `manuscript.md`，再分页；用户要求文稿先行时也这样执行。连续稿先交代必要概念、主体、关系与边界，例子放到它所解释的关系旁，不按原MD标题逐段转成卡片。已确认且解释完整的文稿可直接复用，局部改字不必重写整篇。审稿是编辑自查或独立审阅，不额外要求用户逐阶段批准。

## 3. 分页与视觉共同规划

读 [分页大纲模板](references/workflows/outline-template.md)，写 `outline.md`。每页沿用 Position、Core Message、Text Content、Visual Concept、Layout：位置、核心信息、逐字文案、画面构想和布局。文字与画面共同规划，包含全部气泡、标签、页脚和页码；编辑说明不上图。知识解释先保住完整的说明句和逻辑关系，再用流程、分支、对照、层级等图示配合文字。不能为了安排人物场景，把解释压成几个标签；图示要说清谁做什么、输入输出是什么、条件与反馈如何连接。

AI生图要兼顾阅读趣味和解释价值，两者可以由同一段内容共同产生：一次具体追问能揭示条件，一幅对照图能让读者自己发现差别，人物反应能接住这个发现。逐一审查画面元素的具体作用，不把“气泡负责趣味、图示负责知识”锁成分工。文字已经说过，不等于图示没有价值；删去无作用的重复动作和填空性装饰，保留有效的解释、趣味与识别元素，不把知识卡片退化成纯文字截图。文字为主，图示配合展示；可用人与AI的解释性对话提出疑问、追问和澄清，回答保留完整理由。出现对话时，优先用轻量手绘气泡承载完整对白，尾巴准确指向说话角色；通过角色和气泡尾巴区分说话人，成图对白前不重复“人：”“AI：”标签。说话归属在大纲与提示词中单独写为不上图的编辑说明，与逐字对白分开。角色小巧，气泡随文字自然伸展，不为气泡压缩解释，也不强制每页问答、误区或反转。示意对话不得冒充真实记录；演示产物与真实证据区分，假设的文档、界面等应标明“示意”。

逐页核对标题、对白、正文、图示和收束的关系：哪些交代背景，哪些提供依据、展示差别或改变下一步判断？不要五种形式轮流重复同一结论。必要的重复参照和总览可以保留；把说明中的同一关系画清，也能降低理解负担，不必额外增加案例细节才算推进。若读者已接受结论而后面仍空转，就补缺失的解释或删去复述。连续页沿用本篇例子承接理解，不在每页重开背景；新建任务中突然插入编辑任务等旁支，先判断是否值得纳入本篇深度。

还要问“读者看见什么，才能理解这件事”：优先用适合关系的简单流程、结构、对照、分支等图示，节点与箭头本身就可以把知识说具体，不必放大完整界面或产物。实例用于说明主线中的关系，不自动成为主标题和最大画面；只有确需观察产物细节时才放大。不要先把每页排成“说明→图示→底部问答”，再往里填知识，也不为追求花样强制每页不同。

机制解释在生图前检查四件事：必要概念和主体是否交代清楚；暂去例子后是否仍能复述机制；只读各页标题是否仍回答整篇问题；本例做法是否被泛化成全部情况。正文单元按理解前提相接，不固定成四段或五页。发现缺口先修文稿与大纲，不让生图补逻辑。主标题与主要图示承载本篇要解释的关系，实例细节紧贴对应节点或短段，明确“本例”等适用范围；不要强制每页上下两块“知识+案例”。反馈图需区分正常继续操作与因问题调整，不能把工具每次返回后的后续动作都画成纠错。

封面给主题与阅读理由；正文兑现理解、判断、做法或感受。开头不必先讲痛点，尾页可总结、表达态度、停顿或留下真实问题，不强迫行动建议、升华与互动。并列方法不画成必经步骤，箭头不制造未证实的因果。同一问题优先沿用同一个例子、标签与颜色，呈现变化。

画风、布局、配色独立选择。需要选择组合时读 [风格组合](references/style-presets.md)，按选项读本包 `references/presets/`、`references/palettes/`；布局读 [画布与布局](references/elements/canvas.md)。保留预设选择自由，内容关键词只作建议；也可根据参考图在 outline 中写本轮自定义风格，不需要外部偏好配置或初始化向导。

需要参考历史作品时读 [样例与反馈](references/baseline.md)，实际查看本包图片。封面和正文各看对应样例。排版轻量：正文用自然段落和少量小标题；不为每段套边框、铺彩色色块或加图标，不把多层框嵌套当作结构。人物动作、表情、互动、轻分镜和装饰可承载趣味；知识解释页以文字与解释性图示为主，情境小插图少量点缀，不每个段落都画一组人物。若只是机器人看书、拿放大镜、坐电脑前，应检查它是否重复了文字、挤掉必要解释。过挤先缩减无信息作用的大场景、减无效重复或重新分组，仍挤再拆页；不为凑页数缩字。角色形象与画风分别锁定：沿用账号人物与机器人时，加载本包样例中的准确形象，不因更换题材或配色另造角色。

## 4. 个人表达

个人实践用第一人称讲具体动作、当时想法、实际结果与后来认识；来源整理按来源人物和事实推进，不冒充自己的经历。保留有依据的困惑、喜悦、挫败和用户原有调侃，不为显得有趣另造情节。

句子直接自然，保留必要细节；删营销承诺、抽象套话、空转过渡和刻意反转。不补造效果数字、真实对白、唯一根因或成功结果。当前掌握程度与未来要求分清，不把“我大概知道”改成“我至少需要知道”。

已确认文案优先保留；“稍作整理”只清理重复、错词和衔接，不自行重排。保留手绘字气质，但中文清楚优先。图中说话归属、文字数量和换行需实际核对。

## 5. 组装提示词与生图

读本包 [提示词组装](references/workflows/prompt-assembly.md)，将风格、布局、逐页内容与必要标识组成每页完整 prompt，生图前保存到 `prompts/NN-type-slug.md`。用 [生成与交付](references/generation.md) 直接操作当前内置图像工具，不调用其它 Skill。

先选代表本轮画风、人物和文字密度的一页生成视觉锚点，可以先做正文，再用它与必要参考生成其余页；生成顺序不改变最终页码。用户有参考时首图直接使用参考。每页允许不同布局；同系列角色与笔触保持一致。逐张看图，局部问题先更新该页 prompt 再 AI 编辑或重生，只改相关变量，不自动重做全部页面。

参考提示中分开写明继承什么：角色、笔触、配色与字体可以保持一致，内容模块、位置和对白数量由本页知识关系决定，不能由锚点连带固定。

## 6. 交付与反馈

按 [生成与交付](references/generation.md) 保存原图、提示词、大纲、README、ZIP与检查结果。先连读整组，核对解释对象是否一致、必要前提是否齐全、知识与示例主次是否兑现；再检查中文、箭头、密度、裁切、角色与画风趣味。不能只凭局部正确或版面舒适判整组通过。按分析框架做交换页序、暂删一页、遮住画面的检查；保留有作用的总览、重复参照与情绪停顿，不把信息少自动判成无价值。修改规则后用真实材料生成相应样页，记录预期改善、成图观察和仍未验证的部分；文档自洽不能替代生图检验。只要求总结经验时复用已完成的真实生图证据，不额外生图。

用户选定后同步项目 item README 和台账素材入口；新稿不能自动替换选定版。卡片选定不等于内容已发布。只要求文字或复盘时交付对应内容，不额外生图。

文件与引用检查只记 logic/contract；真实材料实际生成记 real replay，并明确是局部样页还是整组，不能用一张样页代替完整重跑；E2E agent loop 要记录独立新会话依本包完成的实际执行范围；用户选择只代表该作品 product acceptance。未检查的部分明确说明。
