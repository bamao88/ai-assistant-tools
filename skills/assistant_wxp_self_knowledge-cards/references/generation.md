# 生成、修改与交付

本文件完整说明工具与交付方法。直接使用当前会话提供的内置图像生成/编辑工具（image_gen 能力），按它的实时 schema 调用；无需加载其它 Skill、运行外部脚本或准备付费 API。没有可用工具时说明缺口，不自动换付费后端或用代码绘图。

## 生成前

完成本包 outline，并依照 [提示词组装](workflows/prompt-assembly.md) 保存每页完整 prompt。包括具体任务、图片参考各自用途、画风、布局、准确中文、图意及保留项；不要只写“同上”。参考图先实际查看。

需要重组的知识解释，先完成并审阅连续文稿，再做分页与prompt；只读标题、暂去例子仍有主线，才能进入生成。文稿缺概念、主体或逻辑时先修上游，不能寄希望于换一种画法解决。内部审阅无需另向用户申请批准。

当前接口的常见字段是 `prompt`、`referenced_image_paths`、`num_last_images_to_include`，以后以当次实际工具说明为准：

- 无参考的新图仅给 prompt，不带无关历史图。
- 本地图作参考或编辑目标时，传真实绝对路径；说明每张是待改图、风格、人物还是正文布局参考。仅在文字里写路径不等于已传图。
- 仅当目标无本地路径时按工具说明纳入最近图片，使用能覆盖目标的最少数量；两个参考机制互斥。
- 编辑必须纳入待改图；全部目标无法覆盖时补齐后再做，不编辑猜测的图片。
- 比例用 prompt 说明。本系列可沿用约4:5；新任务按要求。不要向工具传不存在的 model、quality、size、output_path 或 CLI 参数。实际尺寸需在生成后检查。

## 生成与系列一致性

先选一张有代表性的卡片生成视觉锚点；通常需要同时检验人物互动和文字密度时，可先做正文，不必从封面开始。有用户参考时从参考开始。其余页传入锚点，并按本轮需要补充适用的正文或封面参考，分别写明用途。历史样例不是新题的默认画风；封面字号与布局不强加给正文。最终文件仍按阅读顺序编号。

按当前工具允许的方式逐页或分组生成；有前后参考依赖时先等锚点完成，不为了并行启用其它智能体或工具链。按工具返回的运行标识与等待方式继续，不猜结果或文件路径。及时展示实际成图。

## 修改

先改该页 prompt，再用图像工具编辑或重生。示例：

```text
图1是待修改卡片，图2只供人物造型参考。
仅修改：[明确位置与问题]。
正确内容：[逐字文字或准确的信息关系]。
保留：[其余文字、布局、角色、色彩、手绘笔触、表情互动和页码]。
不要改动本次修改范围之外的文字与图示；新增或调整气泡仅使用已列明的对白。
```

不能保证像素级不变，每次重看整张。漂移时回到较好的母版，只改相关变量；不要为纠错不断重画整组。代码仅用于文件复制、尺寸/完整性检查和打包，不画图、拼版或覆盖错字。

## 输出位置与文件

- `analysis.md`：内容分析、材料依据与未知项。
- `manuscript.md`：需要重组的知识解释或用户要求文稿先行时，保存分页前的独立连续稿；已有合格文稿可复用并记录位置。
- `outline.md`：整组策略及逐页图文大纲。
- `prompts/NN-type-slug.md`：每页实际完整提示词、参考图角色、修改记录。
- `NN-type-slug.png`：本轮交付图片，复制自工具实际返回位置。
- `README.md`：预览、版本状态、ZIP与检查结果。

旧版 01.png、copy.md、prompts.md 可继续保留，不为格式统一迁移历史作品。新版本另存；修改已选版时按授权备份。项目素材入口有选定版就继续保留，待用户选择新稿后再切换；无选定版可链接待审稿并标明状态。没有发表事实不改已发布状态。

## 检查

### 用实际成图检验方法修改

影响知识拆分、图文组织或提示词的修改，不能只检查规则是否写进文件。用户授权制作或测试时，按更新后的本包方法实际生成有代表性的样张，再看修改有没有体现在图里；本轮仅要求文字复盘时不额外生图。以具体问题选择测试页，不必每次重画整组。

在既有analysis/outline和检查记录中简要说明三件事：改前的具体问题；这次期望出现什么可观察变化；成图实际出现了什么、仍有什么不足。测试内容组织时，尽量沿用已认可的角色、画风与阅读密度，便于看清内容变化。不要通过换画风掩盖解释问题。

检查内容是否向前推进：读者先知道什么，得到什么例子或依据，最后能解释什么关系；标题、对白、正文、图示和结尾是否连续同义复述；为了增加知识是否塞入没有展开的旁支；图示是否与正文中的主体、条件和动作相符。教学假设或绘制的产物示意要能辨认，不能冒充真实截图或执行证据。

图示声称的差别必须在图里可见。暂时遮住“越界”“被截断”等结论标签，检查边界、缺失或方向等现象是否确实画出；正常表格旁边加红圈不等于展示了问题。若细小裁切反复画不清，改用同一知识关系的清楚参照，例如排版边界与超出的末列，不靠继续添加标签宣称已经解释。修改后重新核对整张，保存未达预期的尝试及具体原因。

单张样图能检查规则是否落实及本页是否存在明显问题，不能证明整组节奏、长期生成稳定性或真实读者理解已经改善。保留旧图与实际prompt，先处理成图里发现的具体问题，再记录结果；仅单页生成就写“单页实际生成测试”，完整新材料流程才记整组real replay。独立E2E agent loop与用户product acceptance仍需各自证据。

### 成图与文件核对

先按阅读顺序审整组的解释对象与知识/示例主次，再核对局部：主标题是否仍在回答整篇问题，主要图示是否兑现了该页关系，案例是否扩展成另一篇教程。不能只检查错字、裁切、箭头和风格，就宣布整组讲清楚；内部审阅与用户理解反馈分别记录。

逐页核对全部文字、额外气泡、说话归属、箭头/编号、主语、裁边、字号和角色。与参考比较画风、表情互动和趣味，不能仅以装饰减少判为改进。整组检查阅读目的、材料关系、同屏对照、跨页承接、封面承诺和页码。尤其核对角色是否与既有参考一致，说明句是否被擅自缩成标签，人物场景是否挤掉信息，原文图示中的主体、节点、箭头和条件是否丢失。重复参照、总结重组或情绪停顿按实际作用保留，不把少字或重复自动判为问题。

检查实际图片尺寸、文件可打开、ZIP顺序和内容一致。OCR若可用只作辅助。桌面目视、真实手机阅读、读者理解与用户验收分别记录；缺哪层就说明，不预填通过。
