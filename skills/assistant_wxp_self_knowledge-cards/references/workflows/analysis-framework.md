# 内容分析框架

保留原方法的内容类型、受众、阅读价值、可视化机会与整组组织分析；知识拆分按机器坏人作品调研校正。下面已包含执行所需判断，不需要加载其他 Skill 或外部研究报告。

## 1. 内容类型、读者与阅读目的

先说明读者已经知道什么、还不清楚什么，现有材料能让他多理解、判断或感受到什么。它是工作说明，不必写成成品文案。类型用于辨认材料，不自动决定画风、页数或顺序。

| 内容类型 | 阅读目的可能是什么 | 材料要求 |
|---|---|---|
| 个人经历 | 理解我的认识如何改变，产生共鸣 | 任务、动作、结果、改变理解的发现 |
| 概念解释/比较 | 理解关系，区分边界 | 必要前提、相同参照、可对照的维度 |
| 方法/教程 | 知道何时尝试、如何做与判断结果 | 输入、动作、结果、限制与必要失败分支 |
| 并列观察/清单 | 看见不同侧面，查找或判断 | 各项有一致观察尺度，不伪造先后 |
| 消息/访谈/感受 | 得知消息、理解他人经验或感受 | 来源归属、具体细节、当事人的态度 |

封面应清楚给出主题与阅读理由，正文要兑现这个承诺。经历分享可以保留未解问题，感受分享不必改成教程。没有依据时，不补效果数字、夸张排名或“必看”等身份话术；不做钩子星级、收藏预测或评论诱导。

### 解释深度与篇幅一起决定

写明本篇要回答的问题、读者理解所需的前提、用哪个例子讲到哪一步，以及哪些相邻问题暂不展开。每个细节都要问是否服务本次目的；原文有，不等于卡片必须保留。

试排明显过长时，首先收窄解释深度与范围。删的是次要分支、重复举例和实现细目，不是因果连接与必要解释。不要一遇到拥挤就继续加页，也不要缩字号或把长句压成术语。先决定内容值不值得讲到这一步，再决定是否分页。页数不是预先固定的全局配额，但应作为深度合理性的反馈。

例如解释“Skill怎样被Agent使用”，要保留发现/选择、加载、执行与检查；YAML语法、所有安装路径、配套脚本逐个用法可以另篇展开。若本篇要教安装，那又应重新按操作目标选择内容，不能沿用这个删减清单。

### 先让文稿独立成立，再进入分页

需要重组的知识解释先写 `manuscript.md`：用连贯段落讲清必要概念、主体分工、关系与适用边界。它不是原文摘要、页码列表或生图提示词，也不需要先写成一篇很长的文章。沿用已确认且完整的文稿时不重复造稿；只修改局部文案时不扩大任务。

先明确整篇在解释什么、例子只是帮助理解哪一环。机制说明可以暂时隐藏例子，检查主线是否仍完整；这不意味着正式稿应删去例子。案例分析、亲历故事或作品观察本来就以实例为对象，不强套“例子必须缩小”。

文稿自查或独立审阅后再分页：定义在依赖它的解释之前，谁判断/谁执行/什么结果回到哪里说清；例子里的具体做法不泛化成一般要求。修正文稿缺口后，才能给生图模型安排图形。此项是内容质量检查，不是新增用户审批环节。

## 2. 梳理素材和可信边界

把事件、当时理解、后来判断、可尝试做法、未知问题、他人材料分清。标记是编辑工具，不要求成品出现分类标签。

- 事件保留任务、动作、结果，不补真实对白、次数、成功结果。
- 后来才知道的原因，不提前塞给过去的自己；一次观察不升级为唯一根因。
- 做法写明适用条件与怎样判断，不把几种排查方向写成必然有效的固定步骤。
- 他人的访谈、引用和宣传保留来源，不改成自己的亲测。
- 漫画可以演示抽象情境，但不能伪装成真实聊天记录。
- 为解释机制绘制的假设文档、界面或结果要标明“示意”，不能冒充本次实际执行的产物；真实产物才承担相应证据作用。

## 3. 先组织关系，再分页

分三个层次：整篇的阅读目的→几组相关材料→单张的图文安排。中间的解释单元可以占一页或多页，不直接从原稿字数切片。

| 材料关系 | 组织选择 | 检查重点 |
|---|---|---|
| 前提→后续理解 | 先建立概念，用固定例子逐次增加关系 | 不每页更换比喻，让读者重新认识对象 |
| 对照 | 相同维度并置；复杂时先分别解释，再合看 | 两边是否真的在比较同一件事 |
| 判断→依据 | 给具体例子、差异或产物，必要时展开几页 | 不能只有结论与点头赞同的角色 |
| 事件→发现 | 保留改变认识的动作与结果 | 不是只记录发生顺序 |
| 并列 | 使用一致尺度，可以按重要性排序 | 不画成必经步骤或因果链 |
| 疑问→回应 | 接住自然追问，必要时用对话展开 | 不为放角色虚构无信息量的问题 |
| 局部→总体 | 展开后重新分组、并置或放回同一过程 | 重复能否增加关系或查找价值 |
| 内容→态度/预告 | 用表情、动作、文字或停顿转换感受 | 不强迫空泛升华或行动号召 |

三种原有策略仍可使用：A故事驱动、B信息密集、C视觉优先。按材料选或组合，不要求三份方案；故事不必先痛点，知识不必先结论，画面主导也不等于少文字。

### 每个解释单元怎样让理解前进

在已有分组中简短记下三件事，不另做一套策划：读者到这里已经知道什么；哪个事实、例子、对照或可见结果让他继续理解；读完后能解释什么差别、关系或判断。这些是编辑说明，不是要求每页打印的标题。只有结论和术语、没有推进依据时，先补解释材料，不靠增加角色或字数填空。

知识密度看读者建立了多少有依据的关系，而不是这一页塞了多少事实。充分文字应保住理由和必要条件；旁支事实即使正确，也可能分散本次问题。趣味同样可来自跟着例子发现差别、追问出新条件、看到下一步发生变化；气泡、图示和表情可以共同参与，不把它们限定为“对白只逗趣、图示才解释”。内容不需要每页制造误区、反转或问答，清楚的并列与有作用的停顿也成立。

例如上一页已讲“工具写出Word并返回结果”，下一页可解释“结果如何成为下一次判断的依据”：主图用工具→模型→条件→继续操作/交付的简单反馈关系，Word检查方法附在对应说明中。只有本页确实要教读者观察排版缺陷时，才放大标明示意的越界表格。不要让标题、问答、段落和结尾都只重复“生成不等于完成”，也不要把机制页变成表格修复教程。后续动作可能是正常继续检查，也可能是因问题调整，不能全画成失败重试。

## 4. 决定同屏还是跨页

同屏便于并置，翻页便于分阶段呈现。先问这一页要完成哪一种理解或感受，再决定内容数量。

- 同一比较的关键差异尽量同时可见；前提较多时，先解释对象再合看。
- 发现、追问、反应需要逐次展开时，可以用几页共同讲一个问题。
- 已解释的动作可以在一页汇总成清单，不为了“一点一页”拆散。
- 中间页可以依赖前文；不要求每页重新交代全部背景。
- 重复例子、标签和颜色有助于突出变化；删的是无作用的复述，不是所有重复。
- 页数不预设2—10或九页。手机上读不清时先减无效重复与版面占用；整组页数偏多先收窄范围和解释深度，保住主线前提，再重新分组或局部拆页，不缩小正文硬塞。

调研中的实际安排：四项发布自查放在一张；下载功能追问连续三张；香蕉例子多页逐次增加关系；同一音乐请求放在一张里比较两种回应；年份与问号单独承担预告停顿。借鉴这些选择的理由，不复制题材、文案或作者形象。

## 5. 给画面分配任务

先按需要解释的关系选简单图示：先后动作可用流程图，组成与信息范围可用结构图，同维度差异可用对照图，跨主体调用/返回可用交互图，条件与继续动作可用分支或反馈图。图形种类没有数量配额，适合时可连续使用同一种；避免雷同靠每页推进不同理解，不靠换花样。只有关系确实需要时才加节点、边或层次。

标题、正文与主要图示应服务同一个解释对象。讲机制时，通用关系是主级；实例可直接填入通用结构或紧贴节点，另用“本例”“例如”或适用范围说明，不能因例子更具体就让它占据最大版面。需要看见实际细节才能判断时，再放大产物；不要每页另搭一套“通用知识区+案例区”。

| 内容需要 | 画面可承担的任务 |
|---|---|
| 两人理解不同 | 演出各自关注什么、行动和反应 |
| 机制或概念边界 | 用有依据的输入、约束、关系和同一参照展示 |
| 效果差异 | 保留相同尺度的实际产物或比较对象 |
| 尴尬、疲惫、喜悦 | 表情、动作、距离、分镜和停顿 |
| 总体关系 | 图、轴、分组或过程；箭头含义明确 |
| 作者身份与语气 | 角色、署名、轻装饰与贯穿元素 |

人物和装饰可以提供趣味、情绪与识别，不要求每一笔都新增知识。知识解释页应保留支持理解的完整句子，并用图示组织关系。情境插图和信息图示分开判断：机器人拿放大镜只能演示“在检查”，不能代替“检查什么、依据什么、结果怎样回到执行”。有需要时保留一两处小插图，但不让每个解释单元都长成大幅人物场景。原文带图时先查看其关系结构，确认转绘没有丢失节点、箭头、作用主体或条件。图示不是技术证明，截图也不自动证明效果或因果。画风与布局依据本轮表达选择，不按人群标签自动分配，不把机器坏人的角色或蓝白外观变成我们的固定样式。

## 每个图示先问：它有必要吗？

说明这个元素如何帮助理解或提供具体的阅读趣味，例如使概念更直观、让读者发现差别、体现角色反应或形成停顿，不能只泛称“更生动”。同一元素可兼有多种作用，不要求每个元素同时完成所有任务，也不要求每页都有角色。文字可以独立讲清，不等于配图不必要；例如用同一文件的配置/正文分层、实线信息流与暂未加载区，可以帮助读者看见“文件里有什么”和“模型此时知道什么”的区别。只重复机器人在看书等动作或同义名词，且没有具体趣味作用的图可省略。流程图、对照图也不自动有价值，需结合本页解释任务判断；不要把必要性审查执行为整组纯文字化。

优先保留难以仅凭顺序段落看清的对应、分支、反馈、空间关系或实际证据。必要的图示用尽量轻的形式；短的目录层级可直接缩进文本，简单映射可写成对齐的短句，无需每项画一个文件图标或彩色大框。人物对话优先用小角色配自然手绘气泡，轮廓和尾巴明确说话关系，不反复画大幅角色场景。

## 解释性对话与文字主线

知识解释优先让文字本身说清观点、依据与例子，图示把文字中的关系变得可见。可以采用“人与AI”的提问、追问、反驳或澄清，让回答承担真实解释；不写只有“原来如此”“交给我吧”的空对话，不为放人物压短回答。对白优先放进轻量手绘气泡，尾巴准确指向说话角色，气泡大小随完整文字自然伸展；气泡内不加“人：”“AI：”前缀，归属单列在不上图的编辑说明中。问答可以推进知识，图示也可以带来发现的趣味；气泡用于对话，不把普通正文全部框起来，也不强制每页安排问答。

机器坏人样本中，需求图的每个节点配有解释句，Chatbot对照给出具体请求和回应，清单页文字独立完整；也有大幅情境插图。我们借其文字、例子与关系相互对应的方法，依用户要求选择文字为主，而非照搬统一图文比例或每页问答。

整理真实经历时不得编造对白。为解释已有知识创作的对话，需要明确是教学示意，不能做成伪聊天截图或声称真实发生。若正文已经解释清楚，就不再复述一遍同义对话。

## 输出：analysis.md

保留简洁记录，已有明确输入不重复扩写：

```markdown
# 内容分析
- 内容类型：
- 读者已有理解与本次阅读目的：
- 深度边界：讲到哪一步、必要前提、明确不展开的旁支：
- 核心信息与封面可承诺的范围：
- 文稿依据与上游修正：新写或复用哪份连续稿；必要概念、主体、边界有无缺口
- 素材、来源、事实/判断/未知边界：
- 解释单元与关系：先不填页号；逐组写已有理解→推进它的例子/依据→预期新理解
- 同屏/跨页理由：需同时比较什么，需逐次经历什么
- 可视化机会：关系、情境、产物、表情、停顿、固定参照
- 组织策略与视觉方向：按需要选A/B/C或组合，理由来自内容
```

## 编辑检查

1. **交换两页**：可互换的并列项不必删；本想表达因果却随意可换时，检查关系是否成立。
2. **暂时删一页**：是否损失事实、前提、总览、情绪、来源或节奏？不要只按字数判断价值。
3. **遮住画面**：理解、证据、感受或识别是否损失？反过来，只看图会不会得出错误关系？
4. **核对承诺**：全文是否交付了理解、判断、做法或感受？“提到了”不等于解释清楚；教程需可操作，经历不必有圆满答案。
5. **查同义复述**：标题、对白、正文、图示、收束分别在推进什么？保留承担新关系、比较或总览的重复，删除已经接受结论后继续空转的复述。
6. **用具体问题检查理解**：读者能否说明例子中的关键差别，或依据已给条件判断下一步？写出本篇可检查的问题，后续对照成图；作者自评不代替真实读者理解测试。
7. **只读标题、暂去例子**：知识机制篇的标题是否组成解释主线，暂去示例后是否仍能说清关系？再放回例子，是否帮助理解对应关系，而非带入第二个教学主题？案例本身就是主题时不套此检查。

这些判断综合既有33篇341张机器坏人图卡研究与归纳，以及本次测试的用户反馈和编辑诊断，不是作者公开的内部工作流，也未证明某种分页会提高互动。新纳入的方法是待检验的工作规则，仍需真实成图与用户反馈验证，不能用规则写完代替效果确认。
