# 口播脚本文字风格

## 适用边界

本技能处理 WXP 口播稿里**说出口的文字**。先由任务本身确定内容、事实和结构，再用本技能检查这段话是否像 WXP 自然讲出来的。

- 适用：本人出镜口播、旁白、短视频讲述和提词器中的台词。
- 不适用：文章、笔记正文、标题、封面文案、纯屏幕字幕或一般个人写作。它们各自按目标载体写。
- 其它文字若明确要求“借鉴口播脚本的文字风格”，只迁移朴素、直接、有个人判断的语气，不把口播格式当作该载体的格式。

不要用风格修改补写不存在的经历、结果或感受；不要因为想让稿子顺口就改变用户已经确认的事实和判断。

## 讲述姿态

- 个人实践用第一人称讲真实工作：当时要解决什么、自己做了什么、如何判断、实际看到什么。保留还没想明白的地方，不套固定的“挫折—反转—顿悟”故事。
- 来源材料和访谈内容以来源人物的动作、观点及真实回应推进。WXP 没有参与的事，不硬加“我更在意”“我觉得值得保留”等第一人称点评。
- AI 可以是工作流里的协作者。讲清它承担了哪些整理或执行，WXP 保留了哪些判断、取舍和发布责任；不把 AI 的内部步骤说成自己逐条手动完成。
- 优先讲具体动作和观察，少堆抽象判断。可以直接给自己的收获、做法和有依据的建议，不替观众制造焦虑或安排感悟。
- 保留材料里真实的困惑、挫败、喜悦或轻微调侃；不额外编笑话、俚语和夸张情绪来表演“人味”。

## 口播文本规则

- 开头尽快说清这段分享要讲的具体结果、问题或用途。若原始口述已经自然地用“分享几个我觉得……”进入，优先保留，不强改成冲突式钩子。
- 每个口播单元要能自然一口气说完。句子可以短，但不要为了短视频感把完整信息拆成碎片，也不要自动压缩成浅层的 60 秒稿。
- 每句话增加一个新信息。删除“你看这个流程”“这里很关键”“接下来我给大家看一下”这类不承载内容的舞台词。
- 讲屏幕或文件时，说清观众需要理解的意义：它证明什么、WXP 检查什么、下一步会发生什么。除非论点依赖实现细节，不口播文件路径和工具参数。
- 技巧和经验分享用真实场景推进；例子数量按内容需要决定，不为整齐凑点，也不连续堆一串同义例子。
- 效率数字必须对应具体工作，例如整理、初稿、粗剪、字幕或画面组装所节省的时间，不把人的判断也算成被自动替代。
- 用户给了原话、顺序或语气参考时，保留其信息和表达意图。参考别人的口播只学节奏与叙述距离，不复制口头禅、场景或结论。

## 避免的表达

- 刻意反转：没有真实对比时，不套“不是 A，而是 B”“真正重要的是……”来制造起伏。
- 替观众下诊断：不把自然的经验分享改成“新手最怕……”“一个误解会越滚越大”之类焦虑开头。
- 过度承诺：“彻底解放双手”“一键搞定”“不用判断”“全自动替我完成”。
- 机器腔：抽象词堆叠、泛泛总结、为了换词而换词、金句化口号、解释自己接下来要讲什么。
- 内部过程泄露：不把用户反馈、素材选择说明或“为了这次演示”写进公开口播。

## 改写流程

1. 锁定不能改变的事实、例子、顺序、个人判断和边界。
2. 找出念稿感、空转衔接、刻意反转、营销味和无法自然说出的句子。
3. 用 WXP 的动作、判断或观察到的结果直接叙述；保留真实反应，不补写经历。
4. 把稿子读出来检查。太费气或像书面提纲的句子再拆开或简化；同时确认信息没有被拆没。
5. 交付口播文本时，保留用户要求的结构和时长。对其它载体只借鉴语气，不套用本技能的口播格式。

## 反馈沉淀

当用户指出口播“不像我说话”“念稿感重”“太营销”时，先改当前稿，再判断是否是可复用的口播偏好。只有反复适用的偏好才写回本技能；单篇事实和素材调整只留在当前内容。

文章表达问题交给 `article-expression-polish` 或该文章所属的写作流程；笔记正文按相应平台文案要求处理。不要把这些反馈扩成“WXP 通用个人表达风格”。

## 口播改写例子

这些例子用于判断问题，不要机械套用。

| 不太合适 | 更合适 |
|---|---|
| 新手用 Codex，一个很麻烦的情况是：一个小误解会在长对话里越滚越大。 | 分享几个我觉得 Codex 对新手来说很好用的小技巧，可以增加你在使用 AI 时的容错率。 |
| 这个流程最重要的，是中间加了一个人工确认门。 | 我在中间加了一个确认步骤。候选稿过一遍以后，再让它继续剪。 |
| 我不会跟它说先转录、再选片、再生成时间轴。 | 我会把长视频交给它，让它先整理出可以剪的候选。 |
| 这不是让 AI 替代我，而是让我和 AI 协同工作。 | 我把判断留给自己，后面的剪辑执行交给 AI。 |
| 你看这个流程。 | 我先看候选稿，在 MD 里打勾打叉。 |
| AI 可以帮我完成选题、脚本、粗剪、字幕、框架页、变速、遮名和发布物料。 | 这类执行工作里，我通常讲三件：找片段、做字幕、组装画面。 |

## 和其它技能配合

其它技能生成 WXP 的口播台词时，可以用本技能检查文字是否自然可说。脚本结构、画面、拍摄和发布仍由对应技能处理；文章或笔记正文没有明确要求借鉴口播语气时，不调用本技能。
