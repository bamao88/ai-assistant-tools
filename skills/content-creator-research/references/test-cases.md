# 场景与验证说明

维护或评估合并后的账号研究入口时使用。以下是行为场景，未执行就不能写成测试通过；静态文档检查不证明真实采集或研究质量。

| 请求与输入 | 应有行为 | 重点核对 |
|---|---|---|
| “简单看看这个公众号做什么”，附两篇全文与主页截图 | 轻量了解，复用已给材料 | 无强制登录、十表或固定样本门槛；说明只读了这些资料 |
| “深拆这个新号”，公开作品少、粉丝少 | 按问题分析可读作品 | 不按粉丝、赞粉比或篇数拒绝研究；范围与结论匹配 |
| 比较三个账号，其中一个停更、一个只有字幕 | 保留各对象，统一可比部分 | 不把停更当无价值，不声称看过字幕之外的画面 |
| 只要求分析封面，给了图片和公开赞藏评 | 封面专项观察 | 不输出完整商业报告，不以互动代替点击率或因果 |
| 要求某视频号公开作品全量 | 按分页能力读取并核对覆盖 | 页数上限不等于全量；阻塞仍保留原目标并说明恢复条件 |
| 某篇正文失败，其他材料足够回答定位 | 继续可完成的定位研究 | 不为成功率门槛重抓全部；不隐藏失败影响 |
| 仅给“家居账号供给有哪些”，未给具体博主 | 有来源的赛道供给研究 | 不凭空凑选题、不把本轮未见写成赛道空白 |
| 完成研究后“顺便帮我发评论”，评论内容/对象未定 | 将追加请求交相应互动入口并处理缺失信息 | 研究阶段无写操作；不会把研究授权当评论发送授权 |
