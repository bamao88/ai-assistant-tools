# 内容发布包制作

通用能力：账号定位、事实、素材与输出位置遵循当前项目；项目已有专属入口时优先沿其规则衔接。

## 边界与交接

本 Skill 把已有内容做成可用于平台发布的文字与本地物料，完成点是**发布包已生成、已核对、可交给发布执行**。它不打开平台后台，不上传，不保存草稿，不点击发布。

- 用户要求完整文章（如“把这个 YouTube 视频写成文章”“写一篇公众号文章”）时，由 `source-longform-writing` 负责来源阅读、文章结构与正文；本 Skill 只在文章已有或用户另要标题、封面文案、笔记正文、平台配文时介入。提到“公众号”本身不等于平台文案请求。
- 任务需要完整发布包且原始素材、脚本、成片或图片版本散乱时，先用 `content-production-prep` 整理来源与版本；单独改标题或正文不因此强制建 item。
- 需要专门的节目或账号封面时，调用对应封面 Skill；本 Skill 负责封面文案与发布包里使用的最终文件路径，不把平台上传当成封面制作。
- 用户同时要求“做内容包并发布”时，先完成本 Skill 的产物与校验，再交给 `Agent-Publish` 按本次授权执行。发布 Skill 只复核和填写，不重新创作已确认文案。

## 输入与事实

先确认目标作品、素材来源、目标平台和账号语境、用户已确认的标题/正文/封面、不能改的事实与授权边界。现有内容已经满足要求时，只补缺口；不要因为要产新包而覆盖已锁定的标题、脚本或画面。

缺少成片、源稿或事实依据时，回到素材整理或请用户补充。数字、身份、案例、工具名、体验结果与效果承诺只能来自可追溯材料；不把候选节目、内部原型或低层验证写成已上线、真机或真猫使用事实。

## 按请求范围制作

- **单项请求**：只起标题、改正文、写封面文字或做一张封面时，读取必要素材与对应规则，直接交付该项。可在脑中形成核心判断，不强制创建 `core_brief.md` 或完整发布包，也不运行无关平台校验。
- **完整发布包**：用户要求发布物料齐全、多平台文案，或发布 Skill 因缺包交接过来时，执行下面的完整步骤，落盘并校验。

## 产物与步骤

1. **写 core brief。** 按 [core brief 合同](references/_core-brief.md) 形成平台无关的核心判断、事实边界、标题种子、封面标题种子、正文素材和关键词候选池。已有 `core_brief.md` 时核对后复用。
2. **写标题与封面文案。** 发布标题说明对象和点击理由，封面文字适合缩略图，两者可互补但不机械复制。小红书先读 [标题规则](references/xiaohongshu-titles.md)；其它平台按对应模板及当前平台限制写，不能把小红书公式当通用标题法。用户已定标题时保留，只有事实错误或平台硬限制才提出必要修改。
3. **展开平台字段。** 使用 [平台模板](../platform-publish/assets/templates/) 和 [平台规格](../platform-publish/assets/platform_rules.yaml)，从同一 core brief 为每个目标账号写 `publish_<account>.md`。正文保留分段，话题/关键词放独立字段，来源、声明和内部备注不得混入发布正文。用户明确要求同步同一作品时沿用已确认文字，仅为平台限制做必要适配并记录差异。
4. **准备本地封面与卡片物料。** 仅在任务需要且素材/专门 Skill 可用时生成或选择图片。公众号 AI PM 账号的封面 kit 与使用条件见 [封面制作说明](references/gongzhonghao-cover.md)；小红书长文卡片见 [卡片制作说明](references/xiaohongshu-cards.md)；其它账号按其专门封面规则。图已生成仍需核对图中文字、尺寸、裁切与包内路径。
5. **校验并交付。** 单文件运行 `engines/publish-prep/check.py <publish_file> --platform <platform> [--form article|video|newspic]`；多平台再运行 `engines/publish-prep/check_bundle.py <item_dir>`。校验失败时区分平台硬限制和模板建议：硬限制必须改，用户明确确认的同步文案与模板偏好冲突则记录例外，不能声称校验通过。交付用户可直接审阅的标题、正文与封面预览，并说明包的位置及未解决的事实/素材缺口。

公众号原生贴图（小绿书）使用 [贴图模板](../platform-publish/assets/templates/publish_gongzhonghao_newspic.md)：`article_type: newspic`、标题、有序本地 `images` 与纯文本说明。图片1–20张，首图就是封面，不使用普通文章 `theme`、独立 `cover` 或 AI PM 文章封面 kit。交付前核对顺序与首图裁切；评论和 `cover_info` 选项见 [公众号发布合同](../platform-publish/references/gongzhonghao.md#原生贴图发布包与命令)。发布包校验可从 `article_type` 自动识别，也可传 `--form newspic`。制作入口仍不调用平台 API。

上述命令路径相对 `/Volumes/ExtSSD2601/AI_Assistant/tools/`。工具的模板、规则和封面 kit 目前仍保留原路径，避免破坏现有引擎与历史发布包；这些路径只是底层资源位置，不把发布 Skill 重新变成内容制作入口。

## 停止条件

只要求起标题、改正文、做封面文案或准备内容包时，交付相应成品后停止。不能因为目标平台已明确就打开后台、创建草稿或提交。用户确实要求发布时，先交付或核对已生成的包，再由 `Agent-Publish` 处理账号、发布机、页面和最终提交权限。
