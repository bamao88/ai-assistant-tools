# 内容制作准备

通用能力：账号定位、事实、素材与输出位置遵循当前项目；项目已有专属入口时优先沿其规则衔接。

把一个具体作品从零散材料推进到“来源可追溯、版本明确、下游制作能接手”。本技能管理作品（item）的素材与制作过程；平台文案与发布包由 `content-package-create` 负责，平台执行由 `Agent-Publish` 负责。

项目已有专属制作 Skill 时，从项目入口执行，复用本技能的素材、版本与已确认决定管理约定，不另建平行流程。

## 入口与责任

- 选题已经确定，材料或版本散乱、制作输入未齐、需要组织剪辑/转写/设计时，使用本技能。
- 用户还在选择做什么时，使用 `content-topic-planning`；只改一项标题或正文时，直接使用 `content-package-create`，不强制创建 item。
- 用户已要求发布且素材齐全时，直接交给 `content-package-create` 补齐发布包，再由 `Agent-Publish` 执行；只有制作材料存在缺口时才回到本技能。
- 本技能负责来源清单、素材归属、制作计划、版本、状态、已确认决定、下游输入与本地质检，不重新决定已确认的核心观点或临时在平台页面里创作文案。

## 已确认决定与本次授权

用户确认过的内容标记为 `locked`。沿用当前会话已明确的目标、素材、账号、停止点和授权，不把每个制作阶段变成一次重复确认。

用户明确要求修改某个已确认内容时，该指令就是本次修改授权：直接在要求的范围内更新，保留旧版本，记录变更和受影响的衍生产物。不能因为旧版本被锁定，就要求用户再次“解锁”。

新需求没有要求修改上游内容时，优先通过剪辑、字幕、封面或平台字段完成。例如已拍摄口播的正文关键词调整，不应自动变成重写口播或重录。只有缺失的素材选择、互相冲突的决定、明显成本取舍或对外动作授权会影响下一步时，说明具体冲突并补问；依赖答案的部分暂停，其它已授权工作继续。

只在需要用户决定时展示可判断的实际内容、版本与取舍。既有材料已经确认或任务授权自主制作时，完成必要制作与质量检查后继续交接，不增加固定确认轮次。

## 状态与版本

| 状态 | 含义 | 处理方式 |
|---|---|---|
| `draft` | 尚未确认的草稿 | 在任务范围内继续修改 |
| `review` | 有具体内容需要用户判断 | 展示内容并说明待决定项 |
| `locked` | 用户已确认的当前版本 | 保留；用户的新修改指令可更新该版本 |
| `derived` | 从已确认材料派生 | 可重生成，保持来源与版本一致 |
| `superseded` | 被新版本替代 | 保留追溯，不作为当前输入 |

在 item 的 `README.md` 或已有项目索引记录当前材料、版本、状态、确认依据、来源与待办；已有同等记录时复用，不复制第二张状态表。新版本不要静默覆盖旧版本；更新当前引用，并标记需要重新制作或核对的字幕、封面和发布包。

## 1. 复用或创建作品目录

先读项目已有目录与数据规范，复用稳定作品 ID、索引和原件。用户提供现成目录时沿用其组织方式；没有规范时，建立清晰的作品目录。正式材料不要长期只留在下载、临时剪辑或工具缓存目录。

推荐结构按需采用，不为目录齐全制造空文件：

```text
content/items/<content_id>/
  README.md
  source_manifest.md
  production_plan.md
  scripts/
  transcripts/
  assets/
    raw/
    work/
    qc/
  publish_assets/
    <account>/
      video.mp4 / images/ / cover.jpg
  core_brief.md              # 发布包制作阶段生成或复用
  publish_<account>.md       # 各账号发布字段的唯一真源
```

已有项目的 `<platform>` 素材目录仍可复用，发布包引用具体文件；同一平台的多个账号分别维护 `publish_<account>.md`。不为采用示例目录搬动已有原件或破坏引用。

## 2. 补齐制作输入

在 `production_plan.md` 或项目现有计划中记录本轮制作目标、形态、材料清单、已确认决定、不能改的事实、隐私边界、下游任务与停止点。只补现有记录缺口，不把已有 `core_brief.md` 的核心判断再维护一遍；发布阶段由 `content-package-create` 复用这些输入形成或补齐 core brief。

- **视频**：区分计划脚本和实际录制内容。已拍摄视频的现场口播是内容事实来源；脚本是计划来源。录屏、口播、B-roll、参考资料和封面候选登记到来源清单。
- **图文／卡片**：整理文案、分镜、图片顺序、参考资料与已确认结构；视觉调整不自动改变核心表达。
- **文章**：整理源稿、提纲、正文和引用素材；全文起草、来源判断或表达润色交给对应写作能力。

来源、授权或版本不明时如实标注缺口；不能用旧脚本冒充最终转录稿，或把内部候选素材写成已确认成品。

## 3. 编排下游制作

调用前定位并读取对应真实 Skill，明确输入路径、当前版本、已确认决定、本次允许修改的范围和输出位置。

| 需求 | 下游能力 |
|---|---|
| 本地视频逐字稿、字幕、关键帧 | `video-content` |
| 剪辑、成片、字幕、滤镜、封面帧 | `video-clip` |
| Markdown 转卡片图 | `markdown-to-cards` |
| 来源型长文写作 | `source-longform-writing` |
| 平台标题、正文、封面文案与发布包制作/校验 | `content-package-create` |
| 平台上传、草稿、发布与分发 | `Agent-Publish`，仅在用户要求平台执行时交接 |

下游产物写入作品内，或在作品清单中记录实际位置。记录输入版本，更新当前产物引用，检查是否影响其它已完成材料。平台发布不属于本技能的执行职责。

## 4. 检查实际产物

按任务检查实际文件与可见效果，报告实际完成的验证层级；文件存在、命令退出成功或文档清单齐全，不能替代成品质检。

- **视频**：实际打开检查时长、画面、字幕、声音同步、结尾、黑屏与遮挡；确认转录稿和字幕来自最终视频，发布包引用同一版本，必要时记录 SHA256。
- **图文／卡片**：检查图片尺寸、顺序、缩略图文字、边距、清晰度，以及文字和画面是否冲突。
- **文章**：检查当前正文与素材版本、图片路径、链接、图注、来源和隐私边界；平台字段另由发布包制作校验。

未实际播放、查看或核对的部分明确标为未验证。只有仍需用户决定的审美、表达或素材选择才进入 `review`，不为已经授权且可自行判断的技术检查重复索要确认。

## 5. 交接发布包制作

素材版本就绪后，交给 `content-package-create`，提供作品目录、最终素材路径、已确认内容、目标平台账号及剩余缺口。该技能生成或复用 `core_brief.md`，并为每个账号生成和校验 `publish_<account>.md`。

**标题、封面文案、发布正文、摘要、话题和关键词只在对应 `publish_<account>.md` 维护。** 本技能不再要求另写一份 `title.txt`、`description.txt` 或 `tags.txt`。下游工具确需这些文件时，从当前发布包生成派生导出，注明来源与版本；导出文件不能独立编辑。字段变更先更新发布包，再重新生成导出。

不同账号或平台的素材可以分别存放，发布包必须指向确切文件与版本。正文、话题、来源说明和内部备注按发布包模板放在各自字段，不能混成一段公开正文。

用户只要求制作准备时，到约定的本地交付停止。用户同时要求平台上传、草稿或发布时，由 `Agent-Publish` 沿用本次已明确的目标账号、作品和授权推进；本技能不授予或扩大最终提交权限。缺少授权时，交接已有材料并明确待决定的具体动作，不自行进入平台。

## 6. 写回与完成

更新作品当前状态、实际产物、待办及项目原有索引。收到后续平台执行结果时，记录真实阶段、账号、链接与证据；草稿、待人工提交、已定时、已公开分别记录，不用素材准备完成冒充发布完成。

项目已有 `content-operations-ledger` 或专属台账入口时，将结果交回同一套发布记录与数据维护流程，不在作品目录再建一本可写运营总账。

本轮完成需要满足：来源和当前版本可追溯；下游输入及已确认决定清楚；已授权的制作任务达到约定停止点；实际质检及未验证部分有记录；平台字段需要时已交给发布包唯一真源；剩余缺口与下一步负责人明确。
