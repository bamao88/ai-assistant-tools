# 内容选题

通用能力：账号定位、事实、素材与输出位置遵循当前项目；项目已有专属入口时优先沿其规则衔接。

目标是让用户能决定做什么、为什么先做、内容讲到哪里、下一步补什么。使用任务与项目提供的定位、受众、目标、偏好和材料；背景与资料如何获取遵循项目说明。只有缺失信息会实质改变判断时才补问。

## 按任务选择执行范围

- **找题／重选**：执行完整流程，提供有实质差异的方向及取舍。
- **评价／比较**：围绕给定候选补依据，再判断适配与优先级。
- **深化单题**：保留选题意图，解决角度、依据、范围或表达路径的缺口。
- **处理反馈**：明确反馈改变了什么，修订相关选题；单题意见不自动成为所有内容的规则。

## 加载方法

读取 [研究与判断方法](references/ideation-framework.md)，以及本次主要内容类型。它们分别提供通用方法与类型差异，不要求所有任务加载全部资料。

| 类型 | 主要判断 | Reference |
|---|---|---|
| SEO | 搜索者想完成什么，值得用什么页面回答 | [SEO](references/content-types/seo.md) |
| 图文／视频 | 为什么值得看，画面或叙事如何兑现 | [图文／视频](references/content-types/visual-social.md) |
| 长文 | 为什么值得深入读，有什么材料支撑展开 | [长文](references/content-types/longform.md) |

按内容目标选择，而非只看平台名。搜索导向长文以 SEO 为主、长文为辅；跨类型候选分别说明价值，再按本轮目标比较投入。

需要浏览推荐流、关注流或平台搜索找题时，按需读取 [平台巡看](references/platform-scout.md)，把采集证据带回下述判断流程；不另设每日巡看 Skill。

## 执行步骤

流程参考 SPARK：收集信号、扩展角度、形成自身贡献、比较取舍、验证与反馈。

### 1. 研究内容机会

确定本轮目标与最关键的信息缺口，研究能影响决定的材料。记录来源及实际读取范围，提炼具体需求、兴趣、问题或内容机会。

**产出：**有来源的发现，或明确标记的探索假设。

### 2. 展开不同角度

从发现中生成有差别的内容方向，说明给谁看、讲什么、增加什么。区分主题、角度、形式与标题；只有题目措辞不同不算新方向。

**产出：**能够比较的候选，而非栏目或标题清单。

### 3. 判断内容能否成立

结合已知定位与类型标准，检查受众价值、自身贡献、证据、表达路径和范围。对照既有内容，判断新增、延伸或更新是否有必要。

**产出：**内容能兑现什么，以及尚缺哪些材料。

### 4. 比较优先级

分别判断价值、证据可信度、制作准备度，再结合目标、时机和投入解释推荐顺序。值得研究但暂时做不了的题可以保留；没有合适候选时说明原因。

**产出：**推荐、备选或暂缓的理由，以及会改变判断的新证据。

### 5. 交付选题决定

按 [交付模板](references/templates.md) 输出与请求深度匹配的比较或单题简报。高投入且关键假设未明时，提出最小补证动作；收到真实反馈后修订相应判断。

**完成标准：**用户看得懂取舍，后续制作知道要兑现什么、依据在哪里、缺什么。选题交付不自动进入正文制作或对外发布。

方法署名与依据见 [sources.md](references/sources.md)，仅维护时读取。
