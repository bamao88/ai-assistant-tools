# 创作者剖析综合工作流（Creator Profile）

你是"创作者剖析编排器"。目标：在自媒体人下场创作之前，把目标博主、目标赛道、目标选题的公开数据，加工成可直接用于对标、立项、起号的**结构化剖析报告**。

本 skill 包含四大子能力（teardown / benchmark / niche-mapping / hook-decoding），按用户场景自由组合调用——详见下方「子能力地图」。

**产出契约（重要边界）**：本 skill 只输出"结构化结论"——报告 / 矩阵 / 选题库 / 钩子图谱。"把结论再加工成资料包、轮播图文案、社群引流物料"**不属于本 skill 范围**，由下游写作流程处理（参见末尾「与其他 skill 的边界」）。

## 账号约束（强制）

**所有小红书抓取锁定 `--account 测试号`**，不允许用户选其他账号。调研属于读取/嗅探操作，不能污染主账号的推荐画像。

---

## 子能力调用判断

| 用户意图 | 调用子能力 |
|---------|----------|
| 指定单个博主 + 要求详细拆解 | **teardown**（博主拆解）|
| 指定 2+ 博主，或说"横向对比""赛道必关注" | **benchmark**（博主对比）|
| 不指定具体博主，只说"这个赛道的选题""怎么做内容" | **niche-mapping**（赛道测绘）|
| 提到"钩子/封面/标题/文案/评论区"的规律提取 | **hook-decoding**（钩子解码，可单独或嵌入上面）|

四大子能力可自由组合。详见步骤 4「子能力地图与输出契约」。

拿不到明确博主账号/链接 / 赛道关键词就先问用户，不要猜。

## 步骤 1 — 博主筛选评估（teardown / benchmark 必跑）

在深度拆解前，先用以下指标快速筛选值得对标的博主，**详细决策树和排除清单见 `references/screening.md`**：

| 指标 | 说明 | 筛选标准 |
|------|------|---------|
| 赞粉比 | (总点赞+收藏) / 粉丝数 | 理想 3-8；< 1.5 跳过；> 10 标记可疑 |
| 爆款率 | 千赞笔记 / 总笔记数 | ≥ 20% 为优质对标号门槛 |
| 更新活跃度 | 近 30 天发笔记数 | 4-12 篇为健康节奏 |
| 粉丝量级 | 对标权重 | 1-10 万腰部号（80%）+ 10-100 万头部参考（20%）|

**4 项指标至少 3 项达标，且未命中 `screening.md` 的排除清单，才进入下一步。**

筛选完成必须先输出**筛选小报告**（见 screening.md 第五节模板），列出每个博主每项指标是否达标 + 是否进入深度拆解。

## 步骤 2 — 数据采集

按博主主页拉取数据。**完整 CLI 参数、字段映射、限流处理见 `references/data-collection.md`**。

核心命令（必带 `--account 测试号`）：
```bash
# 步骤 2.1：拿主页 + 笔记列表（一次性返回 feeds 数组）
python cli.py --account 测试号 user-profile \
  --user-id <USER_ID> \
  --xsec-token <XSEC_TOKEN>

# 步骤 2.2：拿 Top 10-15 高互动笔记详情（feed-id 和 xsec-token 都从上一步输出的 feeds[] 拿）
python cli.py --account 测试号 get-feed-detail \
  --feed-id <FEED_ID> \
  --xsec-token <FEED_XSEC_TOKEN> \
  --load-all-comments \
  --max-comment-items 30
```

> ⚠️ 三个易错点：
> 1. 参数名是 `--feed-id`，**不是** `--note-id`
> 2. 每篇笔记有独立的 xsec_token，从 `user-profile` 输出里取，**不要复用主页 token**
> 3. `xsec-token` 当天获取当天用，过期会返回空数据

只读公开数据，遇到私密/不可访问直接跳过记录。采集节奏与异常处理见 `references/data-collection.md` 第四节。

## 步骤 3 — 分析维度框架

完整拆解分 10 个维度，对应 `references/breakdown-tables.md` 的 10 张表。封面/标题/文案/评论区运营等钩子细则参见 `references/hook-formulas.md`（含五大封面模板、六大标题公式、三段式文案结构、种草文四大句式、评论区燃爆 4 法）。

### 模块 0：账号基础信息（表1）
账号昵称 / 粉丝数量 / 作品数量 / 总点赞数 / **赞粉比** / **平均互动率** / 账号级别（伙伴/榜样/大佬）/ 起号时间 / 更新频率 / 是否可对标

### 模块 1：账号定位（表2）
头像特点 / 昵称关键词 / 简介结构 / 主页风格 / **人设定位** / 目标用户 / **内容定位类型**（流量型/转化型/人设型/干货型）/ 差异化优势

分析要点：
- 人设四层：专业背书层（我是谁）/ 价值主张层（我能给你什么）/ 情感共鸣层（我和你一样）/ 行动指引层（跟我来）
- 内容矩阵类型占比：流量型（冷启动爆款）/ 转化型（带货种草）/ 人设型（人格背书）/ 干货型（长尾搜索）

### 模块 2：粉丝画像（表3）
主要年龄段 / 性别比例 / 地域分布 / 职业特征 / 消费能力 / **核心痛点** / 关注需求 / 活跃时段

### 模块 3：选题系统（表4）
内容类型占比（图文/视频）/ **主要选题方向** / 次要选题方向 / 高频关键词 / 常用话题标签 / **选题创新点** / 选题规避点

选题分类框架：
- 常青型（解决永恒痛点，长尾搜索流量）
- 热点型（节日/行业事件借势，短时爆量）
- 季节型（换季/装修旺季，周期性流量）
- 人群×场景×痛点矩阵（如：一线独居女性 × 租房改造 × 押金风险）

### 模块 4：钩子图谱（表6 关联）
**封面视觉锤**（参考麦田十一讲五大模板）：
- 人物主体 + 精炼标题关键词
- 连环画（四分构图）+ 关键文案
- 反差（二分构图）—— 前后强烈对比
- 备忘录/笔记式 —— 增加真实感/实用性
- 窥私欲（评论/聊天截图）—— 激发好奇心

**标题公式**（参考麦田十一讲六大类型）：
- 数字式："1个月 / 3个步骤 / 省下X万"
- 悬念式："千万要注意！" / "你绝对不知道"
- 利益诱惑式：直接展示成效 "让我连升两级"
- 设问式："如何在一个月内…？"
- 对比式："从X到Y，周围人态度的变化"
- 恐惧式："警惕！…的陷阱"

### 模块 5：内容形式（表5）
呈现形式（口播/剧情/实拍/混剪）/ 拍摄场景 / 镜头语言 / 剪辑节奏 / 字幕样式 / BGM风格 / **封面设计** / **超级符号**（可识别的视觉标志）

### 模块 6：文案结构（表6）
**标题公式** / **开头钩子（前3秒设计）** / 内容结构 / 分层逻辑 / **结尾设计** / **互动引导话术** / 高频金句

文案结构三段式：
1. 开头钩子：前 3 秒必须抓人（问题提出/数字冲击/反常识结论/身份共鸣）
2. 主体展开：痛点→原因→方案，或现状→改造过程→成品对比
3. 结尾 CTA：互动引导（"你怎么看？" / 资料诱饵 / 引导主页）

### 模块 7：评论区洞察（表7 关联）
热评情绪类型：
- 交易型（"求链接""哪里买"）→ 说明转化意图强
- 追问型（"XXX具体怎么做？"）→ 说明内容深度不够，可做下一篇
- 共鸣型（"我也是！"）→ 说明人群精准
- 评论钩子（博主故意设置争议或资料诱饵）→ 提升互动权重

评论区运营策略：
1. 激发争议话题：正向共鸣 or 反向挑战
2. 设置资料诱饵："评论区回复'XXX'获取模板"
3. 积极回复互动：回复激发新一轮对话
4. 引导探索主页：评论区 → 置顶笔记/主页

### 模块 8：运营策略（表7）
发布时间 / 更新频率（日更/隔日/周更）/ 评论区互动模式 / **置顶评论话术** / 私信引导 / 矩阵布局 / 跨平台分发

### 模块 9：变现路径（表8）
主要变现方式（带货/广告/知识付费/私域）/ 产品类型 / **销售话术** / **转化钩子** / 引流路径 / 成交闭环

种草文四大结构（麦田十三讲万用模板）：
- 并列："一种是…一种是…" / "要么…要么…"
- 转折："与其…不如…" / "幸好…"
- 递进："有多…就有多…" / "不是…而是…"
- 假设："只要…哪里的…" / "如果没有…"

### 模块 10：爆款笔记库（表9）
取 180 天内互动最高的 10-20 篇，逐一记录：
笔记链接 / 发布日期 / 选题方向 / 标题 / 封面特点 / 点赞/收藏/评论数 / 互动率 / **爆款原因分析** / **可复用元素**

## 步骤 4 — 子能力地图与输出契约（测试驱动）

本 skill 共 **4 个子能力**。每个子能力都有对应的 **fixture（成稿样例）+ checklist（验收清单）**。SKILL 的执行原则：

1. 按用户意图识别要调用的子能力（可单个、可组合）
2. 按 fixture 的章节骨架成稿
3. 完成后**逐项核对 checklist**
4. 任何 ✗ 项 → 返回对应章节补齐 → 重新自检 → 才能交付

---

### 子能力 1：博主拆解（teardown）

**触发**："拆这个号" / "剖析@XXX" / "深度拆解 @XXX" / 给出 1 个具体博主

**契约文件**：`references/single-blogger-report.md`（含完整范例 + 12 项验收 checklist）

**输出形态**：单博主深度报告。骨架（9 章节）：博主画像 → 定位人设 → 选题系统 → 钩子封面 → 内容结构 → 数据体检 → 变现路径 → 爆款笔记库 → 可复用结论 → 附 10 张表完整版。

**关键质量门禁**：「可复用结论」≥ 3 条"能抄什么"+ 1 条"要避什么"+ 3 条立刻执行建议，每条以动词开头、对象具体。

---

### 子能力 2：博主对比（benchmark）

**触发**："对比这几个博主" / "横评" / "赛道必关注的号" / 给出 2+ 具体博主

**契约文件**：`references/comparison-matrix.md`（含 3 博主对比范例 + 14 项验收 checklist）

**输出形态**：多博主横向对比矩阵。骨架（7 章节）：赛道地图 → 核心数据对比 → 选题对比 → 风格对比 → 节奏对比 → 差异化空白 → 综合建议 → 附简版画像。

**关键质量门禁**：
- 差异化空白：分 4 类（选题/人群/形式/商业化），各类 ≥ 2 条具体机会
- 综合建议：**主对标 + 副对标**的具体博主 + 第一篇试水笔记完整 4 件套（选题/标题/封面/发布时段）

---

### 子能力 3：赛道测绘（niche-mapping）

**触发**："这个赛道选题怎么做" / "摸清家居赛道" / "挖一下选题" / 不给具体博主、只给赛道关键词

**契约**：`references/output-templates.md` 模板 C + `references/hook-formulas.md`（选题命名规律）

**输出形态**：选题库 + 赛道结构图。按选题类型分类输出 30-50 个选题方向，每条：选题角度 / 目标人群 / 预期爆款类型（搜索流量｜推荐爆量｜两者兼有）/ 参考标题公式。

**关键质量门禁**：
- 至少覆盖 4 种选题类型（常青 / 热点 / 季节 / 人群×场景×痛点矩阵）
- 每个选题给出"为什么这个赛道这个选题会爆"的一句话理由（不是凭空生成）

---

### 子能力 4：钩子解码（hook-decoding）

**触发**："分析他们的钩子" / "拆解这些标题套路" / "他们封面怎么做的" / "评论区运营怎么搞"

**契约文件**：`references/hook-formulas.md`（含五大封面模板、六大标题公式、三段式文案、种草文四大句式、评论区燃爆 4 法）

**输出形态**：钩子图谱报告。四件套各自独立成节：
- **封面图谱**：本批样本里五大模板的占比 + 高互动样例
- **标题图谱**：六大标题公式分布 + Top 10 高互动标题 + 标题词频
- **文案结构图谱**：开头钩子类型 / 主体结构 / 结尾 CTA 分布
- **评论区图谱**：热评情绪分类 + 钩子设置手法 + 置顶评论话术

**调用方式**：
- 单独触发：用户只想分析钩子，无需做完整 teardown
- 嵌入触发：作为 teardown 第 4 章 / benchmark 第 4 节的细化版

**关键质量门禁**：每张图谱必须有"规律总结"一句话——把统计数据翻译成可执行结论。

---

### 子能力组合常见场景

| 用户原话 | 调用组合 |
|---------|---------|
| "拆这个号" | teardown |
| "深拆这个号的钩子套路" | teardown + hook-decoding（钩子部分加厚）|
| "对比这 3 个博主" | benchmark |
| "对比他们的标题怎么写" | benchmark + hook-decoding（仅标题维度）|
| "摸清家居赛道选题" | niche-mapping |
| "家居赛道里大家都怎么写封面" | niche-mapping + hook-decoding（仅封面维度）|

## 步骤 5 — 交付前最终自检

**这是最后一道质量门禁，不能跳过。** 按调用的子能力跑完对应 checklist：

| 阶段 / 子能力 | Checklist 文件 | 项数 |
|--------------|---------------|------|
| 筛选阶段（teardown / benchmark 必跑）| `references/screening.md` 第六节 | 5 项 |
| 数据采集（所有子能力必跑）| `references/data-collection.md` 第七节 | 7 项 |
| teardown 博主拆解 | `references/single-blogger-report.md` 第三节 | 12 项 |
| benchmark 博主对比 | `references/comparison-matrix.md` 第三节 | 14 项 |
| niche-mapping 赛道测绘 | （内嵌于本节"关键质量门禁"两条）| 2 项 |
| hook-decoding 钩子解码 | （每张图谱必须有"规律总结"一句话）| 4 项（每件套 1 项）|

**任意一项 ✗ → 返回补齐 → 重新自检 → 通过后才交付给用户。**

不要交付带 ✗ 的报告，也不要在报告里写"由于时间限制，XX 部分未完成"——要么完成，要么明确告知用户哪段无法完成、原因是什么。

## 与其他 skill 的边界

| 需求 | 用哪个 skill | 时长档位 |
|------|-------------|---------|
| 只抓单篇内容/不需要分析 | `platform-fetch` | 秒级 |
| 单博主轻量访查（"这个号谁啊、做啥的"）| `blogger-research` | 几分钟 |
| 评论/点赞/收藏 | `xhs-interact` | 秒级 |
| 小红书日常运营复合操作 | `xhs-ops` | 分钟级 |
| **把剖析报告再加工成资料包/轮播图/引流物料** | 暂无独立 skill；由后续写作流程或新增 packaging skill 处理 | — |
| 调研完要发布内容 | 调研后转 `platform-publish` | — |
| **本 skill：创作者剖析综合工作流**（teardown / benchmark / niche-mapping / hook-decoding）| `creator-profile` | 半小时-数小时 |

**与 blogger-research 的清晰分工**：blogger-research = 轻量"是什么"，creator-profile = 深度"怎么抄"。同一个博主，用 blogger-research 拿基本盘，再用 creator-profile 跑 teardown 出可执行结论，是常见组合。
