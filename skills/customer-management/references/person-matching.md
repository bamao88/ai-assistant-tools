# 人员匹配（找人 / 比对总表）

把"问卷登记 / 私戳线索 / 聊天里提到的人"对上**总表行**或**群成员**时的字段约定。
**核心教训（2026-06-25 复训核对）**：只用「真名 + 手机」匹配会大面积漏掉真实老学员——
判"总表查无"的 7 人里 6 人其实都在表里，是匹配口径太窄。

## 为什么只用真名/手机会漏

总表行的身份字段经常不全或不是你以为的形态：
- `微信名称` 存的常是**微信昵称**（"小璐""Jack Zheng""木轶"），不是真名，搜真名搜不到。
- 总表行**普遍缺微信号 alias**（`donglu_1029` 这种），而问卷/线索给的恰恰是微信号。
- `手机号` 可能**为空**、**多号顿号分隔**、或与问卷**差一位/完全不同号**（录入误差）。
- 几期可能为空 → 不能靠几期反查。

刷新后的群成员文件
`knowledge_base/client/raw/chat/members_<roomid>_chatroom.json`
**比 `mac/wechat/state/dashboard.json` 富得多**（dashboard 只有 displayName）。每个成员含：

| 字段 | 例 | 匹配价值 |
|---|---|---|
| `wxid` | `wxid_d0v29xnfog0x42` / `kwon0707` | **主键**，对上后直接 join 总表 `wxid` 列 |
| `微信号` | `donglu_1029` / `rikka_chen` | ★问卷/线索填的"微信账号"多是这个，最有效的桥 |

| `群昵称` | `Rika` | 群内显示名，覆盖率低 |
| `显示名称` | `_sr7-4期-4.5期` | 备注名优先的合成显示 |

## 匹配顺序（宽口径，逐层 union）

对每个待匹配的人，**所有线索 OR 命中即算同一人**，别在单一字段上较真：

1. **手机**（标准化只留数字）严格相等 → 强匹配。
2. **微信号 / wxid** 全等 → 强匹配（问卷"微信账号"先按微信号比，再按 wxid）。
3. **真名 / 别名 / 微信号** 出现在群成员任一名字字段（`备注名/昵称/微信号/群昵称/显示名称`）的子串 → 候选。
4. 拿到群成员 `wxid` 后，**回查总表 `wxid` 列**确认是否已在表（多半在，只是行不全）。

> 找"查无"的人：先在**群成员文件**里用上面字段找到 wxid，再用 wxid 回总表——
> 而不是反过来在总表里搜真名。

## 期次 / staff 的旁证

`备注名` 是助理手打的强信号，直接采纳：
- `…-三期` / `…-4.5期` / `…-5期延期9月` → 定/补几期。
- `…-学员` → 是学员（即便没期次号）。
- `张和老师弟弟` / 明显家属/同事 → **疑似 staff，别当线索也别当学员**，核对后进 `staff_exclude.json`。
