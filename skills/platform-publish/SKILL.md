## 工作流程

**步骤 1 — 判断目标平台。**
看用户表述定位到上表的一行。不确定就问，不要猜。

**步骤 2 — 发布前先做本地网络前置门。**
所有平台发布都先走本地网络分流，不把登录、上传、写草稿、提交审核等发布动作交给 Tailscale exit node 或代理出口。不同平台的域名/IP 不一样，但动作统一：在任何会访问平台网页、API、上传入口、草稿接口的命令前，先运行 `publish-network-preflight` 对应平台的 `apply`。

```bash
/Volumes/ExtSSD2601/AI_Assistant/tools/engines/route-bypass/scripts/publish-network-preflight.zsh <platform> apply
```

平台参数：

| 目标 | platform |
|---|---|
| 小红书 | `xiaohongshu` |
| 微信公众号 | `gongzhonghao` |
| 视频号 | `shipinhao` |
| B站视频 | `bilibili` |
| 抖音视频/图文 | `douyin` |
| 知乎/掘金/CSDN/百家号/思否/头条文章草稿 | `article-drafts` |

`apply` 会重新解析当前平台域名的最新 IPv4、把新 IP 钉到本地网关路由，并刷新受控 `/etc/hosts` 块（目前小红书上传关键域名需要）。如果 IP 变了，重新跑同一条 `apply`；不要手工改 `/etc/hosts` 或手工 `route add/delete`。如果 `apply` 因管理员权限或路由校验失败而失败，停止发布，先解决网络前置门，不继续打开发布页、上传素材或提交。

**步骤 3 — 读对应的 reference。**
一次只读一个 reference。reference 里有完整的 CLI 路径、账号选择、平台专属前置步骤、子命令、失败兜底。**不要凭记忆拼命令** —— 照着 reference 抄。若 reference 与本文件冲突，以本文件的“本地网络前置门”为上位约束；reference 只能补充平台域名/账号/发布细节，不能跳过网络门。

**步骤 4 — 执行并结构化汇报。**
报告：发到了哪个平台/账号、是草稿还是已发布、草稿链接或 media_id/publish_id、需要用户手动确认的后续动作。

## 多笔记发布顺序

用户给出一组待发布内容时，按队列逐条执行：一次只打开/上传/提交一条，确认该条成功并写入状态记录后，才进入下一条。禁止为了省时间把多条真实账号笔记放进一个后台批量循环里一次性提交；发布流程当前依赖浏览器状态、网络分流和平台审核反馈，批量并发或无人值守循环会放大失败并造成误报。

小红书视频发布有额外稳定性门槛：在 `测试号` 跑通本地网络分流与 host 探测、上传进度推进、封面、标签、发布按钮可点击链路前，不得对真实账号执行 `publish-video` 或自动点击最终发布按钮。真实账号任务只能按 `references/xiaohongshu.md` 的逐条流程执行。

## 一稿多发（多平台）

用户要求"同时发小红书 + 公众号 + 知乎"这类一稿多发：

- **拆成多次独立发布**，每个平台各自读自己的 reference、各自走完整流程，不要试图一条命令处理混合目标。
- 各平台对内容形态要求不同（小红书图文需配图/长文需卡片图、公众号需封面图、文章直传走 Markdown/HTML，今日头条当前走浏览器编辑器），按各 reference 的要求分别准备。
- 逐平台汇报结果；某个平台失败不影响其他平台，明确列出成功与失败。

## 与其他 skill 的边界

- **抓取/调研内容**（搜笔记、拉文章、看博主、扒字幕） → `platform-fetch`
- **博主调研报告**（拉博主全部笔记 + 分析） → `blogger-research`
- **评论 / 点赞 / 收藏** → `xhs-interact`；**登录 / 切号** → `xhs-auth`
- **小红书复合运营工作流**（边搜边发边互动） → `xhs-ops`

## 安全与确认总则（各 reference 另有平台细则）

- **真实发布是对外动作**：除小红书长文"正式模式"、小红书视频在测试号稳定且用户明确确认后的逐条 `publish-video`、以及其他 reference 明确放行的正式模式外，默认只到"草稿/填好待用户手动点发布"，不替用户点最终发布按钮。
- **先 dry-run / 测试模式**：文章直传必须先 `--dry-run`；公众号优先 `--dry-run` 预览；小红书"测试模式"绝不调用 `click-publish`；视频号默认保存草稿，明确确认正式发布/定时发布才加 `--publish`。
- **不编造内容**：标题、正文、话题、封面必须来自用户提供的真实素材，缺信息先补齐再发。
- **账号要选对**：多账号平台先列账号、与用户确认后全程固定，不中途换号。
