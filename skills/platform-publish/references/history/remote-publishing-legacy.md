# 通过另一台电脑发布

本文件只负责“哪台电脑访问平台、如何交接素材和控制会话”。账号选择与 Cookie/扫码恢复统一见 [_accounts-and-sessions.md](_accounts-and-sessions.md)；项目机器和 profile 是可覆盖的偏好，按本次实际选择记录。字段填写和验收以 [_execution-quality.md](_execution-quality.md) 为准，平台动作以各平台 reference 为准。

## 电脑分工与适用条件

| 角色 | 职责 | 网络 |
|---|---|---|
| 控制机 | 运行 Agent、准备发布包、发控制指令、收集证据 | 保持 Agent 所需网络/VPN |
| 发布机 | 保存待上传素材、运行可见浏览器、发起平台上传 | 使用满足平台访问要求的本地网络，不依赖控制机代理 |

已授权发布机优先复用。只有一台电脑且网络正常时允许本机模式，不强制购买或设置第二台电脑。对需要两种网络的已配置环境，默认采用双机，不再先穷举平台动态域名分流、关闭 Agent 所需 VPN 或换 Agent/API 提供商。

浏览器在发布机并不自动证明上传未走代理；检查发布机代理、路由及真实素材进度。系统代理关闭不能单独排除 VPN/TUN；局域网控制连通也不等于互联网上传正常。同一原文件在发布机成功而控制机缓慢，能支持使用发布机，但不能未经对照便断言 VPN 是唯一根因。

## 连接与权限

1. 从项目配置/交接记录确认目标电脑、系统用户、局域网地址和素材目录；不能凭相似设备名连接另一台电脑。IP可能变化，重新连接时核对主机身份。
2. 复用已授权 SSH 会话或专用密钥。新增远程命令执行权限需明确授权；按当前工具安全规则完成必要确认，已有同范围授权不重复询问。SSH密钥不授予平台发布权限。
3. 私钥留在控制机，公钥放在发布机；按已批准范围限制来源和转发。来源IP变化导致拒绝时先核对，不自动解除限制。凭据不进入发布包、日志或截图。
4. 浏览器调试接口只监听发布机 loopback，经 SSH 隧道访问；不把未认证调试端口直接暴露给局域网。隧道只承载浏览器控制，不把发布机平台流量转回控制机 VPN。
5. 屏幕共享用于看真实画面、系统文件框或身份确认。若脚本控制已经可用，直接使用，不再重复尝试不稳定的远程组合键或中文粘贴。

**三种状态分别报告：**电脑连接是否可执行脚本、平台账号是否已登录、这条稿件是否允许提交。GG已登录而SSH未授权时，只说明缺电脑控制权限。

## 素材交接与路径

Mac之间优先复用用户已授权的苹果文件共享（SMB）。建立本批次独立目录，传输视频、封面和文案，并核对大小、数量及校验和；不要把 Cookie 或私钥打包进素材。

- 控制机源路径：制作与检查发布包。
- 控制机SMB挂载路径：传输及核验。
- 发布机绝对路径：浏览器原生文件输入实际读取。

这三类路径不能混用。脚本即使在控制机运行，浏览器上传参数也必须指向发布机文件。工具如果先在控制机做 `exists/realpath` 检查，再把同一个路径交给远端浏览器，就存在路径适配缺口；先核实调用方式，不能虚构远程参数。读取、上传和校验应指向同一份素材，转换副本要单独记录。

## 浏览器会话与登录

优先附着已确认账号、可调试的现有页面，记录发布机、profile、调试端口及实际target。不能只按端口推断账号，也不能把旧target移用于新会话。

普通Chrome未建立可用连接时，先检查已有浏览器控制能力；Chrome 144+ 可评估经用户允许的 auto-connect，不能假设旧端口脚本能直接附着，也不能断言只能新开浏览器。接管实现尚需实测。保留已有上传/编辑页；测试另用独立可见profile。正式稿件不得为了切执行器直接重启、清空或重复上传；需要迁移时先查提交状态与重复稿件。

正式浏览器已登录则直接复用；确认平台登录失效后，可将该正式账号的授权 Cookie 恢复到本次选定的正式profile，核对创作后台身份后继续。无合适凭据或平台要求认证时在该环境请用户扫码；测试只用独立测试profile和测试Cookie。两台Mac登录同一Apple/Google账号不证明平台会话共享；导入后当前可用也不证明重启复用，验证层级按共用账号规则分别记录。

## 持续连接与浏览器许可

连接 Chrome 前检查当前入口能否完成本轮需要的页面清单、精确绑定、上传、字段/话题、封面、声明、排期、首屏/全页截图、审计、独立提交、回执和精确页面收尾。只核对本轮会使用的能力及真实函数参数；测试/只读任务不因此获得提交权限。发现缺项先在不连接浏览器的准备阶段解决，不边发布边换临时控制脚本。

一次连接后，所有步骤、页面绑定切换和原位补救都通过持有同一连接的持续运行入口完成。调用错误、缺少操作分支或截图函数参数错误属于控制入口问题，不证明 Chrome 掉线；保留有效连接并使用当前运行时已有能力处理，不为补一个命令退出再启动。工具维护结束后也应按这个契约验收，而不是只证明单个控件可用。

Chrome 开启远程调试不等于永久允许后续所有新客户端。首次连接等待许可时保留这一连接请求；不能因脚本等待超时就连续新建请求，造成多次许可弹窗。确有关闭事件、底层连接错误或在原连接只读检查确认失效后，才重新连接，并核对原 target、账号和页面阶段。已有会话不能跨回合继续持有时，如实记录这一限制，不承诺以后永不再授权。不得通过关闭 Chrome 安全校验或扩大调试端口暴露范围消除弹窗。

## 每次执行与恢复

- 先检查连接、账号、远端文件和当前页面阶段，再调用对应平台的逐步操作。
- 上传完成才进入后续阶段；网络等待和页面处理依据实际状态，不以固定睡眠或退出码作为成功。
- 控制连接断开时先重连并检查原页，浏览器可能仍在上传；不自动重传。
- 有效期已过的定时值不能原样提交。检查当前时区与时间，按授权重新安排；测试表单时间不写成正式排期或平台定时成功。
- 收尾保存字段和截图，明确停在何处。断开控制连接与关闭浏览器是不同动作；保留未完成页，不批量关闭远端Chrome。
