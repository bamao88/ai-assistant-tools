# 小红书发布：本机现有 Chrome

仅使用本台电脑中用户已经打开、已经登录的日常 Chrome。先读并执行 [本机 Chrome 会话门](_local-chrome.md)，在 `before_connect`、`before_upload`、`before_submit` 分别核对同一份任务会话契约；任一阶段发现脚本专用配置、另一台电脑或会话变更，按该 hook 报错并停止。

不运行平台 CLI 的登录检查、启动器或投稿命令，不新建独立配置，不导入 Cookie。登录判断来自这个 Chrome 的真实页面。页面要求短信、扫码或本人确认时保留原页，请用户在原页完成登录；不换环境继续。

## 接管与身份核对

1. 从当前本机 Chrome 的浏览器清单选择用户日常配置，记录真实浏览器/配置标识；Google 配置名不能替代平台账号身份。
2. 优先接回本条现存页面。需要新标签时，只能在已绑定的同一个 Chrome 配置内打开。
3. 入口采用已存在实现和历史真实页面中的 `https://creator.xiaohongshu.com/publish/publish`。优先从当前已登录小红书页面的“发布”入口正常进入创作后台；创作后台发生单点登录跳转时，允许在同一配置中完成正常站内导航。
4. 导航仍显示实际登录控件时，请用户帮助登录。不要用脚本凭据检查替代页面判断，也不要仅凭一次创作后台跳转断言所有 Chrome 配置都未登录。
5. 在创作后台核对项目/本条要求的账号名称及原生 ID，记录页面证据；目标不符时停止，不能按脚本 slot 或其它项目默认账号继续。

仅验证接管时，只打开后台、核对身份及稿件状态，不选择文件、不填写、不存草稿、不提交。已发布或已提交的作品先查管理页，不为验证接管重复发布。

## 发布包与类型

读取同一作品的 `core_brief.md`、`publish_<account>.md`、已确认素材和最新提交授权。按 [素材规格](../assets/platform_rules.yaml) 校验；账号和发布权限以当前项目及用户指令为准。

- 已确认的 Markdown 卡片图片属于图文，按顺序上传，不改走原生长文模板。
- 原生长文只在发布包/用户明确选择该形态时进入，逐步核对模板、正文、下一步后的描述和封面。
- 视频使用已确认成片和封面；图文使用已确认的有序图片。
- 平台文件选择器不接受某种格式时记录实际提示，不以改后缀冒充支持。2026-10-22 的网页图文选择器不支持 GIF；需要更换为合成视频等形态时，以本次用户授权范围为准并同步发布包，不能静默改形态。
- 标题按小红书 20 单位上限和发布包校验规则处理；超限回到内容包按原意改写，不机械截断。平台当前页面计数为最终检查依据。

## 在原页逐项填写

1. 上传一条作品的全部素材，观察平台进度、文件解析及错误，确认素材顺序。视频处理完成后再进入后续检查；超时保留现场，不自动重传。
2. 填写标题和正式正文，保留用户确认过的换行与空行。正文、来源、话题和内部备注分别映射；先聚焦正确编辑区再执行页面支持的清空/替换，避免整页全选或重复追加。
3. 关键词逐个选择平台真实话题联想，核对实体数量与名称。联想失败时先检查已成功项，只补缺失项，不整组重插。历史观察的实体为 `a.tiptap-topic`，具体控件以当前页面为准。
4. 自定义封面实际上传、保存，等待编辑弹窗关闭，再检查发布页缩略图。按页面提供的 3:4、1:1、4:3 等比例检查裁切，确保文字与主体完整；打开编辑器不等于保存成功。
5. 来源记录不自动授权“引用笔记”、@作者或其它可选关联。只有本条明确要求时才关联他人笔记；平台必填转载/来源字段仍按要求填写。署名与原链接不自动拼入正式正文。
6. 小工具/小程序挂载按本次任务要求在发布页逐项查看；核对工具名称、归属和预览，再确认已挂载。若用户明确允许找不到时不挂载，记录实际未找到后继续；否则保留现场并说明缺口，不能伪称已挂载。
7. 内容类型声明沿用已确认默认“虚构演绎，仅供娱乐”，本次另有指令时覆盖；按完整选项文字选择并失焦读回，不依赖序号。内容类型、原创身份与权利状态分别核对，不能因 AI 封面自动改声明，也不能把该默认当原创授权。
8. 核对可见范围、自动关联活动和即时/定时设置。自动推荐活动不等于已关联；确实关联时记录名称并确认符合本条授权。日期时间输入后失焦读回完整值，不能沿用历史测试日期。

## 提交前与结果

按 [执行与质量](_execution-quality.md) 保存当前视口、首屏外关键区域及字段读回证据。核对账号、素材、封面、标题、正文段落、话题、来源/声明、工具、活动、可见范围、定时时间和最终按钮状态。弹窗未解决、封面未保存、证据缺失或会话 hook 未通过时停止在原页。

- `manual-submit` 或仅验证/填表：保留当前页，不点击发布、定时发布或保存草稿；保存草稿也必须在任务授权内。
- 已有明确 `agent-submit` 授权且检查通过：在原页独立点击最终提交一次，不运行上传与提交合一的旧入口，不重复索要已具备的许可。
- 结果未知：先到同一 Chrome 的稿件管理页查重，不能自动重试。平台接受提交只表示提交完成；审核中、定时待公开和实际公开分别记录。
- 成功后仅关闭对应作品的任务发布页；保留其它未完成平台页面及用户原有标签。记录平台回执、账号、时间和实际浏览器绑定；每轮为全部未完成页面重设保留标记。

旧实现与历史验证仅在 `history/xiaohongshu-legacy.md` 留存，不是执行入口。此文档更新不证明新的本机 Chrome 接管或最终提交已完成真实验证；验证层级必须按本轮真实操作报告。
