# 跨案例经验：研究重心如何随产品改变

这些例子来自用户过往研究稿和提供的参考文章。它们说明**怎样选择追问方向**；再次研究相同产品仍须重读原始资料，不能把旧稿当事实原点。

| 案例 | 全貌中最该追深的机制 | 查证动作与教训 |
| --- | --- | --- |
| **[GeoGames / GeoSports](/Volumes/ExtSSD2601/AI_Assistant/assistant_wxp_ai8zu/knowledge_base/morning_briefs/research/2026-09-28-geogames-direction.md)** | 五道同题、成绩分享和每日新题怎样使玩家把结果发进群，又愿意第二天回来；创始人的体育受众和嘉宾出题怎样给循环供给。 | 核官网玩法、访谈里的创始人实操片段、商店和用户评论，再查早期帖子与出题嘉宾自己的发布；将首周触达、后来月活、Pro 与广告收入放回各自日期和定义。不能把演示当成自己的亲测，也不能把创始人首发渠道当成产品长期自然传播的全部。 |
| **[AbMaxx](/Volumes/ExtSSD2601/AI_Assistant/assistant_wxp_ai8zu/knowledge_base/morning_briefs/research/abmaxx/research.md)** | 照片分析如何成为可演示的获客入口；买 UGC 的低利润尝试怎样转向股权创作者长期供素材，再用于广告；付费入口与训练、营养体验能否接住新用户。 | 从访谈追创始人原帖、付费页截图、商店评论、版本和 RevenueCat 同步记录；逐条区分“伙伴实际做过”“创始人给别人建议”和“研究者推断”。一次转载页的 View source 指到无关原帖，说明二手经营细节须逐篇反查。全貌研究与运营专题合看才接近本案的完整问题。 |
| **[Higgsfield](/Volumes/ExtSSD2601/AI_Assistant/assistant_wxp_ai8zu/docs/research/2026-09-28_higgsfield-workflow-learning.md)** | 官方描述的广告多变体工作流如何组织模型、工具、素材引用和人的审核；质量、成本和失败恢复为何成为产品能力。 | 对齐官方产品指南、团队技术访谈、客户案例与各自发表日期，重建公开可见的输入→规划→生成／编辑→审核路径；本次没有账号亲测或完整生产任务轨迹，须把公开设计原则和自己提出的参考实现分开，不用一次演示推断当前所有任务的内部路由。 |
| **[Clay](</Volumes/ExtSSD2601/AI_Assistant/assistant_wxp_ai8zu/knowledge_base/morning_briefs/feedback/reference_inputs/2026-09-14-user-shared-reading/articles/01_Clay是如何通过讲故事和叙事手法实现2亿美元ARR的？丨Peter Kang.md>)** | 高自由度 GTM 产品为何需要教育、社区和客户作品传播；叙事、销售与产品怎样互相支撑。换 CTO 视角则追 Claygent 大规模运行中的等待、背压、成本与评估。 | 参考文章指出 Peter Kang 的长访谈和团队日常动作；[另篇技术稿](/Volumes/ExtSSD2601/AI_Assistant/assistant_wxp_ai8zu/agents/content_write_agent/blog_output/2026-07-27_clay_agent_scale.md)指向 Jeff Barr 的原演讲。不同素材回答不同问题，不能只因高 ARR 标题就把所有增长归功于故事，也不因技术分享就把公司写成架构清单。 |
| **[Encharge](</Volumes/ExtSSD2601/AI_Assistant/assistant_wxp_ai8zu/agents/topic_select_agent/research/2026-09-11_latiao-jiala/articles/39_每天深扒一个海外赚钱AI产品(8)--- Encharge.md>)** | 创始人的增长经验如何进入产品定位、预售、内容与 SEO；AppSumo 一次性收入怎样改变现金、用户结构和未来经常性收入。 | 辣条加辣的文章从创始人 Reddit AMA 找线索，并实际试了流程构建器。再写时应返回创始人问答、当时定价／活动页和可见产品流程，区分作者亲测、创始人说法与二手归纳；不能把 $990K 终身许可销售额当 MRR。 |
| **[Anthropic 工程实践](</Volumes/ExtSSD2601/AI_Assistant/assistant_wxp_ai8zu/agents/topic_select_agent/research/2026-09-11_latiao-jiala/articles_extra/51_Anthropic 工程实践：如何设计一个能跑数小时的多智能体编程系统.md>)** | 真问题、旧方案失败、生成器与评估器的分工、实验对照、模型能力变化如何改变系统设计。 | 技术转述提供检索入口；追工程师原文、代码或演讲，核实用的是哪代模型、何种任务和评估标准。讲清为何架构改变以及代价，不凭示意图补内部实现。 |
| **[Rob 的独立开发者工作方式](</Volumes/ExtSSD2601/AI_Assistant/assistant_wxp_ai8zu/knowledge_base/morning_briefs/feedback/reference_inputs/2026-09-14-user-shared-reading/articles/02_月入2.2万美元，不早起、不卷自律：他是怎么工作的？丨Starter Story.md>)** | 特殊作息、旅行停留周期和“先处理客户，再进入深夜开发”怎样构成一人公司的运营能力。 | 访谈可证明本人如何描述节奏与取舍；若任务是研究他的**产品**，仍须另查产品、客户、收入、留存和支持流程。人物研究要把特质连到具体选择与结果，不能用生活方式代替产品研究。 |

这些案例共同留下两条判断：**产品是什么，决定该追哪种机制；研究越深，事实关系和来源边界也会变化。** 产品简单时运营值得多写，技术复杂时要进入任务、系统和评估，创始人的个人资产能解释选择时则研究人。每次先画全貌，再按本案证据和解释力决定深度。
