# 初始化完成检查

以真实生成/复用的项目文件为依据。检查失败先修复可修复项；需用户信息或外部工具的项留在交接中，不伪造就绪。

## 基础检查

- 目标目录确属该新账号或既有账号，未在旧号中混入新号身份。
- 配置可解析；paths 中的非空本地路径可定位；每个新增文稿/报告路径确实存在。
- 台账表头与数据行可解析；同类 ID 唯一，非空关联能找到对应记录/平台账号。
- 模板已结合输入整理；没有示例事实冒充业务数据。未知项显式保留，不强求填齐。
- 对标内容、自有素材、自有作品区分；原始资料保留，数据与结论有来源和时间。
- 定位与配置各有唯一事实源；生成文件尊重原项目生成规则。
- 已有项目没有被重置或产生第二套主库；再次运行相同输入不新增重复实体。
- 能力路径可访问并已读相应说明才称“已接入”；已接入不等于登录有效或真实链路已验证。
- `START-HERE.md` 说明缺口、责任、下一步及就绪程度；第一轮实验的假设、产出、观察方式和复盘触发点明确。

## 完成程度

| 程度 | 可以依赖什么 | 尚不能据此声称什么 |
|---|---|---|
| 基础建档 | 材料有位置、未知项有记录、文件能读取 | 已有对标结论、账号定位已验证 |
| 可开始调研/内容实验 | 用户、方向假设与下一步清楚，必要输入可取得 | 已抓取成功、发布成功或起号有效 |
| 工具真实验证 | 实际操作有输入输出和证据 | 未测试的其他平台/账号也可用 |

汇报区分静态/logic-contract 检查、真实输入回放 real replay、完整 Agent 工作流 E2E agent loop、用户产品验收 product acceptance。未完成的层级写未完成；仅解析模板不能叫真实输入跑通。

## 维护者检查场景

修改 Skill 后按改动范围检查以下行为；这些是场景说明，未执行不能记为通过。

1. 空目录 + 明确平台：建立最小底座，留下真实缺口和首轮实验。
2. 零散文件 + 对标链接：原件保留，对标只记 link-only/candidate，指标不虚构。
3. 已有库 + 用户手工规则：复用事实源，不覆盖、不重复初始化。
4. 相同资料再次输入：保留原 ID、原索引和原始路径，不复制同一记录。
5. 平台未定 / 没有抓取技能：建中性本地底座，明确未接入能力，不强制服务安装。
6. 同一作品发两平台：两条发布记录分别关联平台账号和指标；上传草稿不等于 published。
7. 当前目录是旧账号：先确认新目标目录，不把旧定位/凭据/私人工作线带入新号。
8. 用户只要求检查：只出缺口，不改文件。
