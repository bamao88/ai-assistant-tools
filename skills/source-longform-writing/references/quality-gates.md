# 质量门

## 方向确认门

动笔前，先在内部完成选题判断。用户没有明确要求直接写时，只把判断通过后的方向卡交给用户确认。

内部先回答：

- 用户最新目标是什么；
- 允许和禁止使用哪些来源；
- 这篇文章写给谁；
- 文章到底讲什么；
- 主来源里最值得精读的模块是什么；
- 这个模块是否有足够上下文独立成文；
- 读者读完会更清楚什么具体对象、机制、系统、产品变化或组织实践；
- 哪些内容不应该写；
- 素材是否足够，风险和缺口在哪里。

这些问题回答不清时，不要让用户帮忙填表。继续调研、缩小题目、换角度，或者说明这个来源暂时撑不起一篇清楚的文章。

给用户看的方向卡默认只保留：

```text
选题：
文章摘要：
大纲：
```

“文章摘要”要接近正式摘要，直接说文章讲什么，不写成写作计划。大纲只说明大概会讲哪些部分、思路怎么推进、材料是否够，不写成初稿。核心读者、素材基础、不写什么、风险和缺口默认内部处理；只有会影响用户判断方向时，才在方向卡后补一两句话。

如果有多个可行方向，可以给 2-3 个候选。每个候选都要包含选题、文章摘要和大纲，不能只给标题。

如果用户最新要求和项目记忆冲突，跟随用户最新要求。冲突会影响结果时，说明覆盖关系。

## 标题规则

公众号长文不要套用短视频或小红书标题限制。

好的长文标题通常包含：

- 来源、人物、公司或对象
- 数字、规模、具体变化或具体问题
- 冒号或后半句，给读者一个打开理由

避免：

- “用 AI Coding 做产品”这类内部标签式标题
- 因为封面标题要短，就把文章标题也压短
- 把平台配文直接复制成文章标题

如果用户给了确定标题，除非违反平台硬限制，否则原样使用。

## 表达清理交接

文章最终表达清理只交给 `article-expression-polish`，本技能不维护第二套通用表达规则。若问题是账号特定的文章口吻，使用该账号的文章风格依据；`assistant_wxp_self_spoken-script-style` 只负责口播脚本文字。若问题是通用文章表达问题，更新 `article-expression-polish`，再回到文章修改。

当来源结构、事实、标题立场和来源边界已经稳定后，使用 `article-expression-polish` 处理：

- 最终润色或顺中文
- 机器腔、翻译腔或表达不自然
- 减少空转衔接、元叙事、多余拆句和对话残留
- 发布前语言清理

交给 `article-expression-polish` 前要保留：

- 来源层级和引用
- 事实、姓名、日期、数字、引用、链接、代码块
- frontmatter（文章元数据）和输出路径
- 标题立场和小节顺序，除非用户要求调整

表达清理后，再检查事实、归属和不确定性边界有没有被改动。

## 反馈迭代门

用户反馈不是局部补丁指令。每次收到反馈后：

- 先判断反馈影响的是事实、结构、角度、表达还是素材。
- 重读全文，找出所有受影响的位置。
- 联动修改标题、开头、小节顺序、段落和素材说明，而不是只改用户点名的一句话。
- 不把用户反馈、修改理由、上一轮讨论或解释性自辩写进文章。
- 如果反馈能沉淀为通用写作偏好，更新对应 skill 或风格文件；不要只在当前文章里临时修。
- 修改后重新检查文章是否仍然像一个独立内容载体。

当用户指出选题、对象、文章类型、摘要、大纲或开篇方向不对，或者明确要求“重写”“不要基于当前文章改”，回到来源和方向确认门。重写时只保留已确认的标题、主来源、事实、引用、输出路径和方向，不沿用旧稿段落顺序、表达惯性和已经被否定的框架。

## 结构检查

文章应通过这些检查：

- 首屏有新信息，不只是来源介绍或“这个很重要”
- 首屏已经出现文章要精读的对象、问题或变化，不把讲者、标题、术语和背景连续堆成介绍段
- 每个小节都直接推进标题承诺的问题，且有知识或经验增量；不能仅以同属一个宽泛领域为由，把收费业务、个人工具、平台演示等不同对象拼成未经来源支持的连续过程
- 定义简短，并在读者需要时出现
- 例子解释中间的因果链，不只是证明结论
- 访谈稿保留了支撑判断的真实经验、追问和反馈；没有把“尝试这样做”“我也拿不准”等来源限定改写成确定的方法论
- 章节数量和分量服从材料，不用整齐的章节掩盖内容浅，也不用额外总结替代来源细节
- 新增来源被织入知识点，而不是孤立堆在段落里
- 结尾回到材料的意义，不写励志口号
- 正文不出现调研过程、对话过程、修改过程或对用户反馈的回应

## 输出形态

使用项目提供的输出路径和 frontmatter（文章元数据）。如果项目没有固定格式，使用：

```markdown
---
topic: "来源主题"
title: "文章标题"
date: YYYY-MM-DD HH:MM
type: "official_reading/podcast/company/technology/people/trend"
series: ""
abstract: |
  ...
keywords:
  - ...
---

正文直接开始。除非发布包要求，不要在正文里重复写 H1 标题。
```

## 最终交付

最终回复前确认：

- 用户指定标题时，确认使用的是原始标题，没有擅自改写
- 确认来源列表和被排除的来源类型
- 确认输出文件路径
- 确认是否已经完成 `article-expression-polish` 表达清理
- 如果是 WXP 或其它有个人口吻要求的账号，确认是否已经按该账号的文章风格依据收口；不默认调用仅适用于口播的风格 Skill
- 内容稳定后，确认标题、摘要、正文、图片/GIF/字幕图、图注和素材位置是否已经一起整理
- 只有跳过的检查会影响结果时，才说明
