# AI时代，比技能更重要的是什么

你有没有想过，我们花了这么多年精心培养的那些"专业技能"，可能在这个时代正在成为最不值钱的东西？

大家都在抢着学提示词工程、学AI产品设计、学机器学习基础。公众号每天推送"AI时代必备的十个技能"，求职培训班的广告打的是"三个月转型AI PM"。但如果我告诉你，这些技能本身并不是问题所在——真正让人在AI时代脱颖而出的，是一种比任何技能都更底层的东西呢？

我最近听了Max Schoening在Lenny's Podcast上的一次访谈。Max是Notion的产品负责人，这个人不太好用一个标签定义：他做过Google的PM，在Heroku管过设计团队，在GitHub当过VP of Design同时还自己写代码，创过两次业，现在带着Notion的产品和设计团队。这次对话让我对一个问题想了很久——在AI把几乎所有技能都变成可替代品的时候，人的不可替代性到底从哪里来？

**Vibe Coding带来了更多软件，但没有带来更好的软件**

Max在访谈里说了一句话，我觉得说到了点子上：AI工具的普及，带来了数量上的爆炸，而不是质量上的飞跃。过去一年多，写代码的门槛几乎归零了。任何人坐下来打几句话，就能在几分钟内跑起来一个应用原型。

这让我想起一件事。我在带学员做AI Coding实战的时候，经常看到一个现象：大家学会了用Claude Code、用Cursor之后，第一反应都是很兴奋——"我能做东西了！"确实，产出速度是以前的十倍二十倍。但过了一个月，很多人会陷入另一种困境：他们做出了很多东西，但好像没有一个真正有价值。代码能跑，功能也有，用户就是不用。

这和Max说的现象是完全吻合的。他说现在互联网上涌现出海量的软件，但大多数东西本质上是在解决不存在的问题，或者用最平庸的方式解决了一个真实的问题。工具降低了执行门槛，但工具无法替你回答"这个值不值得做"和"做成什么样子才是对的"这两个问题。

所以这个悖论就出来了：工具越强大，能动手的人越多，能做出有价值的东西的人却没有同比例增加。甚至某种程度上，更多人能做东西，但真正好的东西反而更难被看见，因为信噪比更低了。

这里有一个问题让我一直在思考：门槛降低对谁的帮助是最大的？直觉上说是普通人。但实际上，门槛降低之后，那些原本就有清晰判断力的人受益更大——因为他们的判断力可以被更快地执行出来了。门槛降低对判断力的重要性不是削弱，而是放大。

**"Agency"：这个词在这个语境里是什么意思**

Max在整个对话里，反复强调一个词：agency。

这个词翻译成中文有点麻烦，字面上是"能动性"或"主体性"，但这两个词听起来都很书面，不够准确。我理解的agency，是一种特定的心理状态和行为模式的组合——你看到一个问题，你觉得这个问题值得解决，然后你真的去解决它，而不是等别人告诉你该怎么做。

不是"我会什么"，而是"我想做什么、我敢做什么、我主动去做了什么"。

这个区别，在AI时代之前也存在，但没有现在这么关键。以前，一个没有agency的人也可以在某个岗位上做得不错，因为岗位本身会给他规定好工作内容，他只要把规定的事情做好就行。技能是可以和agency解耦的。

但现在不一样了。当工具极大地降低了执行成本之后，岗位的边界本身就变得模糊了——因为你随时都可以越过原来的边界，去做那些以前做不了的事。在这种情况下，那些有agency的人，会自然而然地往外扩张，用工具做越来越多的事；而那些只是在等待被分配任务的人，工具再好，他们的输出也不会有质的变化。

Max举了一个例子，是关于Notion内部团队的。他们的设计师和PM，很多都开始用Claude Code把设计稿直接变成可以跑的原型。这不是公司强迫的，是他们自己要这么做。这就是agency——看到了一个可能性，主动去探索它，不需要被人推着走。

我认为这背后的逻辑其实很简单：有agency的人，工具对他们来说是加速器；没有agency的人，工具对他们来说只是多了一个可以用但不知道用来干嘛的东西。

**"第一个10%免费了"——这对产品人意味着什么**

Max说了一个我觉得很好的框架。他说，现在每个项目的第一个10%，几乎是免费的。

他说的是这样一种现实：以前，你想验证一个想法，光是让它变成一个可以点击的原型，就需要设计师、工程师花几天时间。这个成本本身，就会让很多想法在起步阶段死掉——不是因为想法不好，而是因为验证成本太高，根本来不及验证。

现在，这个成本接近于零了。你脑子里有个想法，花两三个小时，一个可以实际运行的初版就出来了。这对创业者、对产品人来说，是一个根本性的变化。

但这也带来了一个新问题：第一个10%免费了，剩下的90%怎么办？

那90%，是把粗糙的原型打磨成真正有用的产品，是找到合适的用户，是在用户真实的使用场景里发现问题并一轮轮迭代，是建立信任、建立口碑、建立商业模式。这些事情，AI工具的帮助是有限的。它们需要的，是你对用户的理解、对行业的判断、对产品品质的审美，以及，足够强的agency，让你不只满足于那个漂亮的原型。

这和我在带学员的时候观察到的现象完全一致。AI Coding工具出现之后，大家做出东西的速度确实快多了，一个月时间，以前三个月才能交付的东西，现在能做出来了。但问题在于，很多学员做完原型之后就停下来了——他们不知道下一步应该做什么。找用户测试？怎么找？听到反馈之后怎么判断哪些有用哪些没用？这些问题的答案，没法靠工具给出来，靠的是你的judgment和主动出击的意愿。

**"Tiny Core"——真正伟大的产品为什么如此稀有**

Max提到了一个我很欣赏的产品哲学，他称之为"tiny core"——每个真正伟大的产品背后，都有一个极简的核心机制，这个机制是产品的灵魂，所有其他功能都是围绕这个核心展开的。

他举了几个例子：iPhone的核心是多点触控屏，它让手机从按键交互变成了触摸交互，这不只是技术细节，而是整个交互范式的转变；GitHub的核心是Pull Request，它把代码审阅这个行为从私下的邮件来往变成了公开的、有记录的、可协作的流程；Notion的核心是block结构，把内容从固定格式解放出来；Dropbox的核心是菜单栏图标，把文件同步这个行为变成了无感知的后台过程。

让我深思的是，这些"tiny core"之所以伟大，不是因为它们技术上有多复杂，而是因为它们背后有一个极度清晰的判断：这个问题最核心的障碍是什么，最简单的解法是什么。这种清晰度，在AI时代依然稀缺，甚至会变得更稀缺，因为工具让堆砌功能变得更容易了，反而更难克制自己只做那个tiny core。

我在做AI产品的时候，经常看到的一个问题是：大家一旦发现工具能做很多事，就会想塞进去很多功能，结果做出来的东西功能全面但没有灵魂。一个真正有品味的产品人，不是会做什么都做，而是有能力在所有可以做的事情里，挑出那一件最重要的事情，然后把它做到极致。这种品味，不是技能，是判断力，是审美，也是agency——你要有主见，才能抵御住"这个也可以加"的诱惑。

**设计师在终端里写代码：这件事的真正含义**

Max提到，他花了大量时间让Notion的设计师开始在终端里写代码，让PM直接构建原型而不是写PRD。很多人第一反应是：这是在让设计师转型工程师吗？

他的回答很清楚：不是。目的不是让设计师变成工程师，而是让设计师获得直接验证想法的能力。以前设计师提出一个方案，需要工程师来实现，两个角色之间有一个天然的信息损耗。当设计师自己能把想法做出来，他们就能更快地在实际的环境里判断它好不好用，而不是在Figma里想象它好不好用。

这让我想起一件事。我在训练营里一直强调的一个判断是：AI时代对产品经理的要求，是成为真正的通才——需要什么就学什么，按项目学习，从上往下学，而不是先把所有基础打好再来做事。这和Max说的是同一个方向。

但这里有一个很深的障碍，不是技术上的，而是心理上的。很多设计师听到"去学写代码"，第一反应是恐惧——我不是程序员，我会不会搞错？这种恐惧，归根结底，是缺乏agency。有agency的人，面对这种情况的反应是：好，我先试试，出错了就修。没有agency的人，面对同样的情况，会问：我能先看一些教程吗？有没有标准的方法？

这不是能力上的差距，是态度上的差距。但这个态度上的差距，在AI时代会被放大成结果上的巨大差距。

**"SaaSpocalypse"为什么是被夸大的恐惧**

有一种很流行的观点：AI时代，所有SaaS产品都要死，因为AI可以帮你生成任何软件，你不需要订阅任何工具了。

Max对这个判断的态度，是认为它被严重高估了。他用了一个概念叫Jevons悖论——历史上，每一次让某种资源变得更便宜的技术出现，反而会带来这种资源消费的大幅增加，而不是减少。蒸汽机让煤炭使用效率大幅提升，结果煤炭消耗量不降反升，因为使用场景暴增了。

AI让软件开发变得更便宜，软件的数量不会减少，只会更多。需求不会因为供给变得容易就消失，反而会因为门槛降低而涌现出更多以前被压制的需求。

这让我觉得，对大多数在职的产品人和开发者来说，"AI会取代我的工作"这个恐惧，本身就是被夸大的，或者说，是对错了方向。真正值得担心的，不是AI会不会取代你的具体技能，而是在所有人都用上AI工具之后，你有没有那种能让你持续发现值得做的事情、并且主动去做的能力。

这就回到了agency。技能是可以被学会的，可以被模仿的，可以被AI替代的。但一个人主动发现问题、主动提出方案、主动推进事情的内驱力，这是很难被复制的。

**我的思考：我们花了太多时间在错误的维度上焦虑**

我在这个访谈里反复感受到一个让我有点坐不住的结论：大多数关于"AI时代我需要学什么技能"的讨论，都在回答一个错误的问题。

这几年，我见过太多人把大量精力放在技能的横向铺排上——学Python，学提示词工程，学AI产品设计，考各种证书。这些事情本身没有问题，但如果背后的动机是"我需要用更多技能来证明自己的价值"，那方向就偏了。技能的积累可以给你更多可以做事的工具，但它无法给你那个让你决定要去做什么的内核。

Max讲了一个很小但很有力的观点：Notion内部有些人，当AI工具开放之后，他们的产出是原来的三倍五倍。这些人有一个共同特点，不是技术背景最好的，而是最不需要别人推着走的。他们有想法，有主见，自然而然地把工具变成了加速自己的东西。而另一些人，工具用得也不差，但输出没有显著变化——因为他们在等待被分配任务，而任务的分配跟不上工具的进步速度。

我在自己的实践里也感受到这个差距。AI Coding工具出现之后，我确实做了更多东西，但让我的输出真正有价值的，不是我用了什么工具，而是我对"哪些问题值得解决"有自己的判断，并且有足够强的意愿去执行。工具只是把这个判断和意愿，变成了更快的现实。

回过头来看，这其实是一个很久远的道理，只是在AI时代被放大了。Steve Jobs说过，生活中你所看到的一切，都是比你更不聪明的人做出来的。他说这话的意思是：做事的门槛没有你想象的高，大多数人只是没有那个"我去做"的冲动。

AI把门槛压低到了历史最低点。但每个人都有了工具，不代表每个人都会用。用工具的能力，变成了门槛最低的东西。而真正决定输出质量的，是你是不是那种会主动去用、主动去尝试、主动把想法变成现实的人。

这就是Max说的agency比skills更重要的核心含义：skills是你有什么，agency是你用它干什么。前者越来越容易被获得，后者越来越稀缺，也越来越值钱。

对我自己来说，这个访谈最让我有收获的一点，是它让我重新想清楚了：我在带学员做AI产品的时候，真正想传递的不是具体的工具用法，而是一种做事的态度——看到一个问题，不是问"我能做吗"，而是先动手去试，在试的过程里发现自己的边界，然后把边界往外推。这是很难靠课程直接教的东西，但它恰恰是最重要的。

在每个人都可以用AI工具做东西的时代，真正稀缺的，是那个知道自己想做什么、并且真的会去做的人。

你觉得呢？欢迎在评论区说说，你认为在AI时代最难被替代的，是什么。
