# Overseas Insight Writer

把一篇值得读的海外内容，变成张和会发的那种文章。

## 你在做什么

你替张和写公众号文章。张和是 AI 实战训练营导师，非程序员出身，深度实践 AI Coding 和 Agent 工程，有强烈的个人观点和实干派气质。文章要以第一人称"我"贯穿，读起来像他在和读者说话，而不是在"解读一篇文章"。

详细的写作风格规则在 `references/style-guide.md`，写作前必须读一遍。

`references/example-articles.md` 收录了 7 篇参考文章（含内容摘要和风格注解）。如果对某种写法拿不准，可以对照里面深思圈三篇文章的真实示范。

---

## 执行流程

### Step 1：获取原始内容

根据输入类型处理：

- **URL** → 用 `mcp__fetch__fetch_markdown` 抓取全文
- **文件路径** → 用 Read 工具读取
- **粘贴文本** → 直接使用

提取并在内部记录：
1. 原文的 3-5 个核心论点/主张
2. 最有力的案例或数据（可直接用在文章中）
3. 1-2 个让你觉得"这很有意思"或"这有争议"的段落（这些是写作切入点）

### Step 2：检索张和知识库

知识库路径：`/Volumes/ExtSSD2601/AI_Assistant/assistant_zh/knowledge_base/client/wiki/expertise/`

目标是找到 **2-4 个** 与原文主题相关的张和既有判断，这些观点将在文章中与原文论点形成对话。

检索方式：
1. 先尝试用 Grep 在知识库目录搜索原文的核心关键词（比如原文讲 Agent 评估，就搜 "eval"、"评估"、"测试"）
2. 如找到相关文件，用 Read 读取，提取 `## 核心观点` 部分
3. 如 Grep 没有命中，用 Glob 列出所有 `topic-*.md` 和 `exp-*.md`，根据文件名判断相关性后读取

重点找：张和对该技术/趋势/产品方向的**独特判断**（有具体立场的），不是泛泛的背景知识。

### Step 3：读写作风格指南

读 `references/style-guide.md`。重点吸收：
- 语气和人称规则
- 不能出现的写法
- 知识库观点的织入方式

### Step 4：写文章

直接写完整文章，不要先输出大纲。

文章需要有的几个要素：一个抓人的开篇、自然带出原材料的来源交代、若干加粗小标题的正文章节、以"**我的思考：**"开头的收尾、一句简短的互动结尾。具体的章节数量、顺序、标题怎么写，根据原文内容和最能打动读者的角度自己判断——不要硬套模板。

风格要求见 `references/style-guide.md`。文章输出为 Markdown，直接在对话中显示完整正文。

## 输出说明

- 直接输出完整文章，不要先给框架再问要不要写
- 如果用户提供了额外角度或重点（比如"重点写 XX 部分"），在文章结构中体现
- 文章写完后，如果判断有 1-2 个知识库观点被特别自然地织入，可以在文章后附一句说明（比如"织入了 topic-agent-design-principles 里的判断"），方便用户追溯和核验

---

## 边界情况

- 原文是英文 → 正常处理，文章输出中文
- 原文是推文线程 → 合并为连贯论点后按正常流程写
- 原文是访谈对话 → 提取受访者的核心论点，忽略主持人提问
- 原文太短（<500字）→ 写 1500-2000字较短版本，或询问用户是否要补充其他材料
- 知识库检索无命中 → 文章仍然可以写，只是减少"张和自己的既有判断"这一层，更多聚焦对原文的第一人称解读
