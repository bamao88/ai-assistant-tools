# 在AI时代，agency比技能更值钱——Notion产品负责人的这个判断，让我坐立不安

你身边有没有这样的人：AI工具人人都在用，他用得比谁都溜，快捷键背了一堆，Prompt模板存了好几百条，每周还在追最新的模型评测报告——但真正做事的时候，一旦遇到稍微模糊一点的问题，就开始等。等需求变清晰，等老板拍板，等别人告诉他该怎么做。

我在训练营里见过太多这样的人了。不是能力不够，是那种"想要先搞清楚再动手"的本能让他们在一个充满不确定性的时代一直踩不上节奏。

最近我在 Lenny's Podcast 上听到一期对话，让我有点感慨。Notion 的产品负责人 Max Schoening 说了一句话，我听完之后脑子里一直在转：

**在 AI 时代，agency（主动性/自主行动力）比 skills（技能）更重要。**

这句话听起来很虚，但 Max 这个人说这句话是有分量的。他之前在 GitHub 当 VP of Design，同时自己写代码；在 Heroku 主导过设计；在 Google 做过 PM；是两次创业的创始人。他现在在 Notion 干的事情，是让设计师和 PM 们都开始在终端里 prototype、开始自己 ship 代码。他是那种自己上手、推着别人上手的人。

所以当他说 agency 比 skills 更重要，我想把这件事掰开来仔细说说。

---

**技能可以学，但 agency 是一种底层操作系统**

Max 在对话里提出了一个我觉得非常准确的观察：AI 把学技能这件事的边际成本降到了几乎为零。你想学写代码，Cursor 帮你写；你想学做设计，Figma AI 帮你搞；你想学分析数据，Claude 帮你出框架。

这带来了一个悖论——当所有人都能快速获取技能的时候，技能本身就不再是护城河了。

真正拉开差距的是什么？是在你还没搞清楚"我该学什么技能"之前，就已经开始行动了的那种人。

我在训练营里反复观察到一件事：同样是零编程背景的 PM，两个月下来，差距不在于谁学了多少 AI 工具，而在于谁第一周就跑去装 Claude Code 并且开始做东西了。那个人通常是班里交付最多、也最敢接新需求的人——不是因为他技能更好，而是他对"不确定"的容忍度更高，在还没有完整地图的时候也敢迈步。

这就是 agency。

Max 把它描述为一种"先动手，边做边想"的本能。在 AI 时代，这种本能的回报率被放大了十倍——因为 AI 让你的第一步的成本极低，试错成本极低，但不行动的机会成本反而更大了。

---

**"前10%是免费的"——这句话背后藏着一个巨大的战略机会**

Max 提到一个非常有意思的判断：现在每个项目的前 10%，几乎是"免费"的。

什么意思？就是一个项目的最早期——验证想法、做 prototype、出第一版 demo——这些事情，AI 可以帮你快速完成。以前需要一个工程师花两周时间才能搭出来的 proof of concept，现在可能两三天、甚至一天就能出来。

这改变了产品开发的逻辑。

以前大家在立项的时候非常谨慎——因为一旦投入，就是真金白银的研发成本。所以大量的时间花在前期的讨论和论证上，用来回答"这个方向值不值得投资"。

现在这个前置成本消失了。你可以把那些讨论中的假设直接 build 出来，用真实的 prototype 代替 PPT 来验证。

这在 Notion 内部已经是一种工作文化了。Max 说他们有一个 prototype playground，设计师和 PM 可以直接用 Claude Code 把 Figma 里的设计稿转成可以跑的代码。不是给工程师看需求文档，而是直接拿出一个能点击的版本。

我自己也有类似的感受。我现在的工作节奏里，几乎每天都在用 Claude Code 把各种想法直接跑出来，然后再决定值不值得往后走。这不是要替代研发，而是让判断的质量更高——你是在看真实的东西，不是在脑子里模拟。

但这个红利不是自动兑现的。你要有足够的 agency，才能在"想法还不完整"的时候就开始。大部分人的习惯是，等想法成熟了再做；而 agency 强的人，是把做本身当成"想清楚"的手段。

---

**vibe coding 制造了更多软件，但不是更好的软件**

对话里有一个让我印象很深的判断，Max 说得非常直白：vibe coding 这波浪潮，让软件的数量爆炸了，但软件的质量并没有同步提升。

这个观察是准确的，而且它指向了一个很重要的机会缺口。

vibe coding 的本质是：用 AI 把你脑子里的想法快速变成可以运行的代码，不需要你懂任何工程细节。这当然是好事，因为更多人能够把想法实现出来了。但问题是，大量这样产出的软件，是"能用"，但不是"好用"的。功能堆叠，体验粗糙，没有内在的产品哲学。

这就是为什么 Max 特别强调他的一个理论：**"tiny core"（微核心）**。

最伟大的产品，往往有一个极其简单、极其精准的核心体验。iPhone 的多点触控、GitHub 的 Pull Request、Notion 的 Block 系统、Dropbox 的菜单栏图标——这些都是 tiny core。把这个核心体验做对了，其他一切才有意义。

vibe coding 的问题是，它太擅长生产"功能"，但太不擅长产生"哲学"。软件的核心体验是什么？谁在什么场景下用？用了之后的感受是什么？这些问题，AI 给不了答案——你得有产品直觉，有对用户的深度理解，有愿意把"够用"扔掉、坚持追求"对"的那种执念。

这让我想起我一直说的一件事：AI 降低了工程师门槛，让所有人都能 build，但产品的品质门槛其实没有降低。甚至因为竞争更激烈了，反而提高了——你能快速做出来已经不是优势，关键是你能做出值得用的东西。

所以会 vibe coding 的人会越来越多，但做出真正好产品的人还是稀缺的。这个稀缺性，恰恰藏在 agency 和产品直觉里，而不是在工具使用技能里。

---

**"SaaSpocalypse"（SaaS末日）的故事，被大家过度渲染了**

前一阵子流行一种论调：AI 会把所有 SaaS 都干死，因为以后每个人的 AI Agent 都能帮你做专属软件，用不着 Notion、Slack 这些通用工具了。

Max 的观点是：这个判断太简单了。

他提到一个概念——**杰文斯悖论（Jevons Paradox）**：历史上每一次某种资源的使用效率提高，通常反而导致这种资源总消耗量增加，而不是减少。因为效率提高扩大了使用场景。

AI 让软件开发更容易，不一定意味着需要的软件变少，反而可能是需要的软件变多了。当一个会计也能自己做内部工具，当一个销售 rep 也能自己 build 一个跟进系统——这些需求以前因为成本太高根本不会发生，现在反而变成真实的市场。

但这里有个关键：成为赢家的，不是那些功能堆积的大而全工具，而是那些有清晰 tiny core 的产品。人们不会为平庸买单，但会为"恰好解决了我那个最痛问题"的东西反复续费。

Notion 能在这个时代继续增长，Max 的逻辑很简单：他们在 AI 这件事上不是在"加功能"，而是在重新问那个 tiny core 的问题——AI 时代的 Notion，核心体验是什么？这个答案他们还在找，但他们知道这个问题比"AI 要怎么集成进去"更重要。

---

**Notion 内部怎么跑得快："drive it like it's stolen"**

Max 分享了 Notion 的一个内部文化关键词，我觉得翻译成中文最接近的大概是："当成偷来的车开"——也就是说，毫无保留地使用，不要害怕坏，不要小心翼翼。

这背后的逻辑是：在 AI 加速的时代，犹豫和保守的成本比以往高得多。团队应该默认往最快的路径走，保持高速迭代，而不是过度分析。

他们让设计师和 PM 们真正开始写代码、在终端里 prototype，不是把这当成一个技能培训项目，而是把它当成一种新的工作默认状态。你不用成为工程师，但你要能够不依赖工程师就能把想法跑出来。

我非常认同这个思路，因为我在训练营里一直在推的也是同一件事。我在 4.5 期里直接要求所有学员，不管是不是技术背景，都要能自己把一个 AI 产品 demo 跑出来。不是为了证明 PM 能取代工程师，而是为了让他们有能力在对话中拿出真实的东西，而不是用 PPT 描述一个想象中的产品。

很多人第一次打开 Claude Code 的时候会有一种恐惧——这不是我该懂的东西。但当他们第一次把东西跑起来之后，那种感觉是完全不同的。那不是技能的提升，那是 agency 的激活。他意识到自己可以做他以前认为做不到的事。

这就是 Max 在 Notion 内部努力创造的那种文化时刻。

---

**设计师的角色正在发生一场安静的革命**

这期播客里还有一段讨论我觉得很值得单独聊聊：关于设计师在 AI 时代的角色。

Max 自己就是设计出身，但他在 Notion 的做法是推着设计师们进终端。他提到了 Bret Victor 那个经典演讲"Stop Drawing Dead Fish"——设计师不应该只是在画静态的原型，应该能直接 build 动态的、活的系统。

这不是新观点，但 AI 让它变成了现实。以前让设计师写代码是很大的成本，现在有了 Claude Code，一个设计师可以用自然语言描述他想要的交互效果，AI 帮他写出来，他只需要判断"对不对"。

这种变化的深意是：设计师不再只是"产出设计稿"的人，而是"产出真实系统"的人。他的判断力和审美依然不可替代，但他行动的半径被大幅扩展了。

同样的逻辑也适用于 PM。我一直说，以后 AI 产品经理能独立完成从零到 70% 的 demo，剩下的 30% 才需要工程师介入做稳定性和上线。这不是在说 PM 要变成工程师，而是说 PM 的 agency 半径必须大幅扩展。

一个不能独立 build 的 PM，在 AI 时代的价值会被系统性低估。这是一个残酷但真实的判断。

---

**"为这个时代而生"不是鸡汤，而是一个可证伪的命题**

Max 在播客里引用了圣经里以斯帖记的一句话："也许你来到王国，正是为了这样的时候。"

我不是要让这件事变得过于戏剧化，但这句话指向了一个真实的问题：AI 带来的这波范式转变，你是把它当成外部的噪音在旁边看，还是当成你的时机在里面跑？

这个问题没有标准答案，但它有行为答案。你现在装了 Claude Code 吗？你用它 build 过一个完整的东西吗？你上周有没有因为某个想法太兴奋，直接跑去做了，而不是先找人讨论？

这些细节，比你的简历更能说明你的 agency 水平。

---

**我的思考：在工具民主化的时代，agency 才是真正稀缺的东西**

听完 Max 这期对话，我想说一件有点反直觉的事。

过去这两年，大家花了大量时间学工具、学模型、学提示词——这些都对，但我越来越觉得，这些都不是最关键的变量。最关键的变量，是那个人在拿到工具之前就已经有的那种"我要去做"的驱动力。

AI 在做一件很有意思的事：它在把执行技能这件事变成商品。就像工业化把手工技能变成了流水线产品一样。当执行技能变成商品，稀缺的就是判断力和行动意志。

在 PC 时代，你要会用 Excel 才能处理数据；在云时代，你要懂 SaaS 工具才能团队协作；在 AI 时代，你要有 agency 才能真正受益于 AI 的能力放大效应。

这是一场关于底层操作系统的更新，而不只是一次技能迭代。

我一直在训练营里强调的那句话是：你要成为生产者，而不只是消费者。消费者会用 AI 工具很爽，但生产者用 AI 工具做出东西。这两者之间的鸿沟，就是 agency。

Max 说，他在 Notion 最有成效的事情，不是推出了哪个功能，而是当他看到一个设计师或 PM 第一次在终端里跑起来了自己的代码——那一刻他们看向世界的眼神变了。他们开始相信自己能做以前做不到的事。

这就是 agency 的激活时刻。它一旦被激活，就不容易再关上。

我们在接下来这两年会看到一个很明显的分化：有 agency 的人，会用 AI 把自己的能力边界持续往外推；没有 agency 的人，会用 AI 把以前的事情重复得更快，但始终在同一个边界里打转。

这场分化不是技能决定的，是心态和行动模式决定的。

所以我真正想说的是：别老想着该学什么技能了。先问问自己——上周你有没有因为一个想法，不等确认不等拍板，自己直接动手去试？如果没有，那才是最值得去解决的问题。
