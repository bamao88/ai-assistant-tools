# 技能会过时，主动性不会

我认识一个 PM，能力挺强的，Figma 玩得很溜，需求文档写得很规整，跟研发对齐也顺畅。去年 AI 浪潮起来之后，他开始焦虑。他问我：是不是要去学 Python？要不要刷 LeetCode？要不要考个 AI 相关证书？

我说：这些都不是你最需要补的东西。

他有点困惑。

这个对话让我想了很久。因为这类焦虑我在训练营里见得太多了——大家都在问"我该学什么技能"，却没人在问"我该用什么心态去面对这个时代"。这两个问题看起来相似，其实完全不同。

最近我在 Lenny's Podcast 上听了 Max Schoening 的一次访谈。Max 是 Notion 现任的产品负责人，在这之前做过 GitHub VP of Design、Heroku 的设计主管，还是两次创业者。他在 AI 时代让设计师和 PM 开始写代码、跑原型、用 Claude Code 把 Figma 直接变成可运行的产品——这套打法已经在 Notion 内部取得了很具体的成果。

这场对话让我对一件事确定了许多：在 AI 时代，真正稀缺的不是技能，而是**主动性**（agency）。

---

**主动性和技能，不是一回事**

Max 在对话里提出了一个我觉得非常击中要害的区分。他说，大多数人在 AI 时代问的问题是"我该学什么"，但这个问题本身就问错了。技能是工具，工具会被替代；主动性是你跟工具之间的关系模式，这个东西模型替代不了你。

所谓主动性，简单说就是：你看到一个问题，你愿不愿意主动去解决它？你有没有那种「不管用什么手段，这件事我要搞定」的冲劲？

这个描述听起来有点虚，但它在 Notion 内部有非常具体的体现。Max 说他们在内部推动设计师和 PM 拥抱 AI 工具的时候，发现进展最快的人，从来不是学过编程的那些，而是那种「反正有问题我就冲」的人。这类人一旦发现 AI 能帮他们搭原型，马上就动手了。而那些更焦虑、更犹豫、更想先弄清楚「我会不会用错」的人，往往就卡在起点。

这让我想到我在训练营里反复观察到的一个现象。同样参加一个五天的 AI Coding 密训，进展差异最大的分界线从来不是编程基础，而是那个人在遇到第一个报错的时候，是马上复制进去问 Claude，还是停下来等别人来给他答案。

主动性，就是那个"我先冲再说"的本能。技能可以在冲的过程中快速积累，但主动性本身是个元能力——它决定了你到底会不会动起来。

---

**前 10% 免费了，你打算用来干什么？**

Max 在对话里提出了一个让我觉得很有意思的观察：现在每个项目的前 10% 是免费的。

什么意思？他说，在 AI 时代，原来需要两三个工程师花两三周搭出来的探索性原型，现在你一个人用一天就能搞出来。这不是说质量一样，而是说「这件事有没有价值」这个问题，你可以用极低的成本得到一个初步答案。

这个变化对产品开发的节奏影响是根本性的。原来那套「先立项 → 再排期 → 再开发 → 再测试 → 再上线」的流程，它的第一步就是一个巨大的过滤器——很多想法因为「排期太贵」而死在起点。但现在前 10% 免费之后，这个过滤器消失了。

你可以在一个下午把五个方向全部试一遍，然后选出最有感觉的那个，再投入真正的资源。

我自己在做产品的过程中也越来越明显地感受到这一点。用 Claude Code，我能在一个早上搭出一个有完整交互逻辑的 demo，然后下午直接拿给目标用户测试。这种速度在两年前是不可能的——那时候一个 demo 最快也得一个工程师搭三天。

但这里有一个关键问题 Max 没有明说，但我想补充：前 10% 免费了，不代表你就会去用这 10%。还是要有那个"让我先试一把"的主动性，才能把这个能力真正用起来。很多人知道可以这么干，但就是没动——这就回到了主动性的问题。

---

**软件数量爆炸，质量并没有**

Max 提到了一个让我觉得非常冷静的判断：AI 出现之后，软件的数量确实在爆炸式增长，但质量没有同步提升。他把这个现象叫做"vibe coding 时代的副产品"——更多的软件，更多的糙货。

这个观察和我自己看到的情况完全吻合。我们现在看到大量创业团队能在一两周内上线一个产品，但这些产品里有相当一部分的体验是混乱的：交互逻辑不对，边界情况没处理，用一次就不想用第二次。

Max 的判断是，这个「质量缺口」本身是一个机会。因为用户对好软件的期待并没有随着软件数量的增加而降低。恰恰相反，当到处都是糙产品的时候，一个真正打磨过的产品反而会更显眼。

这一点我非常同意，而且我觉得背后有一个更深层的原因：AI 降低的是执行成本，但没有降低「知道什么是好的」的判断力成本。你可以让 AI 帮你写代码，但你能不能判断这段代码生成的体验是不是对用户来说足够流畅，这个判断力 AI 没有办法替代你。

这恰好呼应了我一直在讲的一个事：AI 时代对产品经理最重要的能力，不是学会写代码，而是培养一种对好产品的敏感度，同时具备推动它真正落地的意志力。前者是品味，后者还是主动性。

---

**"Tiny Core"：伟大产品的核心其实很小**

Max 在对话里分享了一个他叫做"tiny core"（微核心）的理论，这个概念让我听完之后沉默了一会儿。

他举了几个例子：iPhone 的多点触控、GitHub 的 Pull Request、Notion 的 Block、Dropbox 的任务栏图标。这些产品为什么能成为伟大产品？不是因为功能多，而是因为它们都有一个极其清晰、极其简单的核心机制，这个机制本身就解决了一个真实的、以前没被解决的问题。

iPhone 的多点触控，让人第一次用手指直接操作屏幕上的内容，不需要物理键盘，不需要触控笔。GitHub 的 PR，第一次让代码审查这件事有了一个完整的工作流容器，你可以在里面评论、讨论、合并，不需要在邮件里来回发 diff 文件。Notion 的 Block，第一次让文档、数据库、任务清单可以在同一个地方用同一种方式组织。

"tiny core"的关键不是"小"，而是"精准"。你的核心机制是否精准地命中了某个真实的、被压抑的用户需求，这件事决定了产品的天花板。

这个观点击中了我一个长期以来的直觉。我在带学员做项目的时候，最常看到的问题不是产品的功能太少，而是产品的核心模糊。做 AI 写作工具的，想同时支持营销文案、学术论文、情感咨询；做 AI 客服的，既要接入多轮对话，又要支持文档检索，还想加商品推荐。每个功能单独拿出来都有道理，但没有一个是那个"tiny core"。

在 AI 时代，执行成本降低了，意味着能上线的功能更多了。但这反而让"tiny core"的稀缺性更高。因为当每个人都能快速堆功能的时候，真正难的是你能不能在开始之前就想清楚：这件事的精准核心是什么？

---

**不是所有软件都会消失**

对话里有一个话题让我觉得 Max 的思维比较清醒——他对"SaaSpocalypse"（SaaS 末日论）持保留态度。

最近市面上有很多声音在说：AI Agent 出来之后，传统 SaaS 就全完了，因为 Agent 可以帮你做任何软件能做的事，甚至更多。

Max 的判断是：这个预测太激进了。他的理由是，软件的价值不只是功能，还有它对某个工作流的组织方式。Notion 之所以被人用，不只是因为它能存信息，而是因为它定义了一种信息组织的方式，这种方式影响了团队的协作模式。这个东西不是一个 Agent 能轻易替代的。

我对这个判断有自己的延伸思考。我觉得 SaaS 真正会被冲击的，是那些"功能即价值"的产品——你用它只是为了完成某个具体操作，这个操作如果 AI 能直接帮你做，你就不需要这个产品了。但那些已经深度嵌入工作流、沉淀了大量数据、定义了团队协作节奏的产品，反而有可能在 AI 时代活得更好——因为它们积累了 AI 最需要的东西：高质量的私有数据和工作流上下文。

这和我一直在跟学员说的一个判断是一致的：AI 时代，最有价值的 SaaS 不是功能最多的，而是数据最深的。谁掌握了最真实、最垂直、最高密度的业务数据，谁就在 AI 时代有了真正的护城河。

---

**让设计师和 PM 开始写代码，Notion 是怎么做到的**

Max 在 Notion 内部做了一件很多公司都在尝试但鲜少成功的事：让非工程师背景的设计师和 PM 开始用 AI 工具构建可运行的原型，甚至参与部分功能的实际交付。

他说关键不是培训，而是氛围和工具。Notion 内部有一个叫做"prototype playground"的共享空间，任何人都可以在里面丢进去一个 Figma 文件，然后用 Claude Code 把它变成一个可以点击的原型。这件事降低了门槛，因为你不需要事先学会写代码，你只需要把设计文件放进去，然后开始跟 AI 对话。

更重要的是，他们用了一句我很喜欢的内部口号——"drive it like it's stolen"。意思是说，不要太宝贝手里的资源，直接开冲，能跑多快跑多快，出了问题再修。

这个氛围的塑造比任何培训项目都有效，因为它直接把"动起来"变成了文化默认值，而不是需要克服心理障碍才能启动的特殊行为。

这让我想到我在训练营里一直在做的事情——我们不叫它"AI 技能培训"，我们叫它"AI 实战训练营"。两个字的差别背后是完全不同的逻辑：技能培训是先学再用，实战训练是用中学、做中学。我一直坚持的一点是，你要让学员在第一天就动手，哪怕第一天产出的是一个只有三个页面、会在第二步报错的 demo，也比坐着听两天理论强。

动起来的人，才有机会进步。

---

**我的思考：主动性是这个时代真正的稀缺资源**

Max 这场对话让我确认了一件我早就有直觉、但没有完整表达过的事。

AI 带来了工具能力的极大平均化。写代码，以前要学几年的东西，现在你跟 Claude 对话几轮就能出结果。搭原型，以前需要两三个人花一周，现在一个人一天能试五个方向。做数据分析，以前要熟悉 SQL 和 Python，现在很多任务用自然语言描述就能跑出来。

工具能力被平均化，意味着谁拥有这些工具带来的能力优势差距在缩小。但与此同时，另一个东西在被放大：**你愿不愿意主动去用这些工具、主动去解决问题、主动去推动事情落地的那种意愿和冲劲。**

这就是为什么我说主动性比技能更重要。不是说技能不重要，而是在工具能力被极大平均化的时代，技能本身的区分度在下降，主动性的区分度在上升。

回到我开头说的那个 PM。他焦虑自己不会 Python、不会机器学习。但这不是他的核心问题。他的核心问题是：当有了 Claude Code 这样的工具之后，他有没有那种「我要去做一个产品出来」的冲动？还是他依然在等一个别人来告诉他该做什么的信号？

我认识到的一个现实是：技能培训是有终点的，你把一个技能学完了就完了。但主动性是一种生活方式，它不是你学完某门课之后拥有的东西，而是你每天每个决策里体现出来的选择——是主动出击还是等着被安排。

我在训练营里说过一句话：AI 时代对人的最大考验，不是你有没有跟上技术变化，而是你有没有那种「不管世界怎么变，我都会冲出去找到自己的位置」的劲。

Max 在访谈里引用了圣经以斯帖记里的一句话，大意是：也许你来到这个世界，就是为了这样一个时刻。我不信教，但我理解他想表达的意思——我们所有人，都恰好处在这个技术史上最特殊的转折点。这是一个可以从零开始构建、可以用极低的成本验证想法、可以让一个人的影响力被极大放大的时代。

这个时代对愿意主动动手的人是极其友好的。

但它对等着别人给答案的人，会非常残酷。

所以，与其问「我该学什么技能」，不如先问自己：我有没有那个「不管怎样我都要冲」的底气？

欢迎留言聊聊你的看法——你觉得自己现在最缺的是技能，还是主动性？
