# zh-writing-skill

ZH 账号写作的统一入口。**收到任何内容/分析文章请求，都先找张和观点，再做选题预检，最后决定是否路由写作。**

文章质量靠**张和观点定位 → deep research → 选题预检 → 发表价值标准 → 选择基准形态 → 素材路由 → 写作 → 独立审稿 → 有限返修**这条闭环卡住。A/B/C 只负责写法，不再拥有放行权；`zhang-viewpoint-first.md`、`article-quality-standard.md`、`topic-preflight.md`、`benchmark-corpus.md` 和 `zh-editor-review.md` 可以否决文章。交稿线是审稿质量分 >= 80 且 `Verdict=PASS`。

A/B/C 三个路由文件（`A-firsthand.md` / `B-knowledge-system.md` / `C-single-source.md`）是写作方法参考，不是质量保证。不要把“符合路由文件”误判为“甲方会满意”。

它们是普通 markdown 文件，不带 frontmatter，不会被 Claude 当作独立 skill 触发——只能通过本路由加载。

---

## 成功指标

本 skill 的目标不是“流程完整”，而是**最终文章质量过关**。

一次写作 run 只有两种成功：

1. **素材足够时**：产出一篇正文，经过 `zh-editor-review.md` 独立审稿后 `Quality Score >= 80` 且 `Verdict=PASS`。
2. **素材不足时**：明确返回 `SUPPLEMENT / DOWNGRADE / KILL`，说明缺什么，不生成一篇看似完整但低于 80 分的长文。

下面这些不算成功：

- Article Brief 写得完整，但正文只有 60-70 分。
- 审稿表看起来严格，但最后仍放行弱稿。
- 文章符合 A/B/C 路由，却缺张和不可替代素材。
- 继续加风格禁令，让文章更像模板稿。
- 外部研究很深，但已经替换或偏移了张和原来的判断。
- 把研究后的延展结论写成张和早就这么认为。

优化本 skill 时，只看它是否提高“最终文章 PASS>=80”的概率。流程、rubric、benchmark 都只是辅助工具，不能替代最终文章质量。

允许也鼓励 deep research。张和现有材料只有 50% 深度时，可以用外部研究补机制、证据、案例、反例和边界，把文章推到 80 分；但必须让研究服务 `zhang-viewpoint-first.md` 里的 `Viewpoint Core`，不能杜撰、不能偷换立场、不能把外部观点归因给张和。

## 总流程

1. **判断类型**：运营事务文不进 A/B/C；内容/分析文章进入观点定位。
2. **张和观点定位**：内容/分析文章如果是大选题、行业事件、单源解读、方法文或需要代表张和主账号发声，先加载 `zhang-viewpoint-first.md`，输出 `Zhang Viewpoint Dossier`。没有至少 MEDIUM 置信度的张和观点，不写第一人称主账号文章。
3. **Deep Research**：只有在 `Decision Before Research=WRITE-RESEARCH` 时才做外部研究。研究用于补深度，不用于改换张和立场。
4. **选题预检**：加载 `topic-preflight.md`，输出 `Article Brief`。Decision 不是 `WRITE` 时，不写正文。
5. **发表价值标准**：加载 `article-quality-standard.md`，检查 7 个发表价值问题和硬门槛；答不上来先补素材或降级。
6. **选择基准形态**：加载 `benchmark-corpus.md`，为 brief 选一个主 benchmark shape（业内复盘 / PM 技术教材 / 体感报告 / 反主流单点 / 高在场度单源解读）。没有 shape 能承接，先补素材或降级。
7. **质量校准**：需要判断风格和质量时加载 `quality-anchors.md`。一篇甲方认可稿只做正样本锚点，14 篇差稿做反样本库。
8. **素材路由**：只有 brief 通过后，按 A/B/C 选择写作路由。
9. **正文写作**：按路由文件写，但优先服务张和 `Viewpoint Core`、brief 的核心判断、证据计划和 benchmark shape。
10. **独立审稿**：写完加载 `zh-editor-review.md`，输出 `PASS / REVISE / SUPPLEMENT / KILL`。质量分 >= 80、观点对齐达标且 `PASS` 才交稿。
11. **有限返修**：每篇正文最多两轮返修；两轮后仍不过，回到观点定位或 brief 补素材、换角度、降级或放弃。

如果用户已经给了通过预检的 brief，也要确认是否已有 `Zhang Viewpoint Dossier`；没有的话先补观点定位，再检查发表价值和 benchmark shape。如果用户要求改已有草稿，先加载 `zh-editor-review.md` 审稿，再决定返修、回到观点定位或回到 brief。

## 路由决策

### 第 0 步：先判断这是不是"内容/分析文章"

A/B/C 是 ZH 账号**内容文章**（分析、观点、教材、复盘、解读）的路由。下面这些**不是**内容文章，不进 A/B/C：

- 嘉宾分享 / 嘉宾介绍 / 活动宣传
- 运营招生 / 课程介绍 / 加群引导
- 通知 / 公告 / 致歉 / 节日问候 / 周年回顾
- 任何对外说事的运营、事务、宣传文

这类稿子**自己想清楚怎么写**，按素材和目的判断结构，守通用规则就够（标题口语、不暴露调研、不说教、戏剧性轻松、不用全角破折号）。不要硬套分析骨架，也不要硬立反主流断言。

反主流单点是给**分析文章**兜底的；把活动宣传写成反主流单点是路由错误，不是写作问题。

### 第 1 步（是内容文章）：先定位张和观点，再预检，再顺序判断 3 个问题

先加载 `zhang-viewpoint-first.md` 输出 `Zhang Viewpoint Dossier`，再加载 `topic-preflight.md` 输出 `Article Brief`。只有 `Decision=WRITE`，才继续判断 A/B/C。`SUPPLEMENT` 先补素材，`DOWNGRADE` 降级成短帖或运营文，`KILL` 直接放弃。

#### 1. 手里有任何一手亲历素材吗？
张和说过的话 / 做过的判断 / 踩过的坑 / 大厂内推过的方向 / 长期（≥2 周）实测过的产品

→ yes：加载 `A-firsthand.md`，按亲历强度选子模板（业内复盘 ★ / 踩坑指南 / 反主流单点）

#### 2. 想给 PM 讲透一个技术概念，且能凑齐 ≥3 海外信源？
→ yes：加载 `B-knowledge-system.md`

#### 3. 基于一篇具体海外文章/论文/访谈/大会内容写解读？
→ yes：加载 `C-single-source.md`（默认走高在场度档）

### 兜底（是内容文章但 3 路由都不强匹配）

→ **自己想清楚论证骨架**，按 ZH 账号差异化方向走：要么有亲历素材，要么有清晰判断/反主流断言，要么有信源整合深度。

反主流单点是 A 下面的一个可选子模板，**不再是强默认**。素材撑得起就用，撑不起别硬套。

### 素材稀薄怎么办（既没亲历、没整合、也没判断）

典型：单纯转述某条新闻、没有自己的视角。

- 选项 1：补原始来源、产品细节、数据、案例或张和 `boss_take`，再回来预检
- 选项 2：降级成轻量推文、活动说明或课代表号内容
- 选项 3：直接拒绝写——"这篇没有可写性，建议跳过"是合法回应

ZH 账号差异化 = "有素材 + 有判断"——这条原则适用于内容文章；运营事务文按它自己的逻辑写。

## 多匹配优先级：A > B > C

素材稀缺度从高到低 — 一手经历最贵（不可复制），知识体系次之（需要多源整合判断），单源解读最易做（任何人都能干）。让稀缺素材主导文章是 ZH 账号的差异化关键。

### 边界判断（防误路由）

- 同时有"张和经历"和"海外信源"，**主体扛论证的是张和经历** → 走 A，海外信源做验证
- 同时有"张和经历"和"海外信源"，**张和经历只做单点验证** → 走 B，海外信源做骨架
- 单篇海外文章 + 张和大量产品视角评论 → 走 C 高在场度档（不是 B；B 需要 ≥3 信源整合）
- 长期实测产品 + 反主流判断 → 走 A 业内复盘或反主流单点（产品体感是素材，反主流判断才是论证主体）

## 通用规则（3 路由共享）

把规则分三层，不要把风格建议当硬约束。

### 硬约束

- 不虚构张和经历、学员数据、客户案例、内部细节或产品实测。
- 具体事实必须核查：模型名、产品名、数字、发布时间、实验条件、功能边界。
- 不暴露调研痕迹：不写"我查到""我在知识库里看到"；如果事实无法确认，要删掉或标明不确定。
- 不让正文主体变成招生广告；训练营、公开课、加微信只能在文末轻转化。
- 不用全角破折号。

### 质量启发

- 标题口语化，但不能为了标题牺牲 scope。
- 开头尽量是具体事件、数据、对话、实测或真实问题。
- 核心判断要有边界、能被反驳，不写安全废话。
- 每篇至少有一组强证据：原始来源、真实案例、评测结果、bad case、截图、填好的样例或前后对比。
- 口语化但不松散；有立场但不喊口号；不说教不端着。
- 结尾留一个实质判断或动作，不用"你呢？"之类空反问。

### 参考例子

路由文件里的句式、结构、样本、字数和收尾都是参考，不是必须复刻。正样本只提炼高层质量原则，反样本只识别坏模式。

## 基础验收（跨路由通用最低底线）

路由文件内有自己的写法约束。下面 7 关是**最低底线**，但不是每关对每个路由都同等强制——见每关末尾的适用标注：

1. **发表价值清楚**：按 `article-quality-standard.md` 的 7 个问题，这篇是否值得由张和主账号发布？答不上来，不能继续按“文风优化”处理
   _适用：内容/分析文章都强制_

2. **benchmark shape 清楚**：这篇属于 `benchmark-corpus.md` 的哪一种主形态？它是否达到该形态的 80 分最低线？答不上来，不能继续按“文风优化”处理
   _适用：内容/分析文章都强制_

3. **scope 一致**：标题 / 前两段的断言落在文章实际论证的范围内。错配两个改一个：要么收紧标题，要么扩展论证 scope（前提是材料够）
   _适用：A/B/C 都强制_

4. **理解检验**：合上所有材料、不靠任何引语 / 数字，用自己的话把核心因果讲一遍。讲不出来 = 没真正理解，只是给材料贴了机制标签
   _适用：A/B 强制；C 弱化版（要能讲清你为什么觉得这篇值得解读）_

5. **证据权重不混层**：第一人称观察只能做**验证**，不能单独支撑某条机制。每条机制至少要有 1 个非第一人称观察的证据
   _适用：A/B 强制；C 不适用（C 的主体本就是一个外部信源）_

6. **节标题反向测试**：节标题改成"X 公司怎么说""Y 论文讲了什么"也读得通的，全部不合格——这是来源化伪装。节标题必须是机制断言（一句"A 导致 B 因为 C"的浓缩）
   _适用：A/B 强制；C 可以用 editorial 标题，但首段必须立即兑现核心判断_

7. **去引用测试**：把全文的引用 / 数字 / 案例**全部删掉**，剩下的文字还能不能说清因果？说不清 = 罗列，重写
   _适用：A/B 强制；C 不适用（C 的主体本就是另一个信源的内容）_

7 关都过，只代表可以进入独立审稿，不代表可以交稿。

## 写完之后

1. 先按基础验收自检。
2. 加载 `zh-editor-review.md` 独立审稿，只接受 `PASS / REVISE / SUPPLEMENT / KILL`。
3. 质量分 >= 80 且 `PASS` 后再做语言 polish；`REVISE` 只修 Top Findings 的最多 3 个问题；`SUPPLEMENT` 回到 brief 补素材；`KILL` 回到 brief 或放弃。
4. 每篇最多两轮正文返修。两轮后仍不过，不继续加风格禁令，默认是选题、素材或观点问题。

**交稿时直接点出没把握的地方**让用户决定，不要藏在 draft 里。常见的几种：

- 预检是 `SUPPLEMENT` 但用户要求先写，我缺少 [...]
- 某条事实没找到原始来源，已删 / 已标不确定
- 某条机制主要靠第一人称观察撑住，没找到非第一人称证据
- 审稿器给过 `REVISE`，我只修了第几轮的哪 3 个问题
- 标题和正文 scope 我处理成 [...]，仍可能需要收紧

不要把没解决的问题留给读者去发现。
