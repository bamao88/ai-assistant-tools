# AI PM 作品集，不是把 demo 做出来就够了

我现在看 AI PM 作品集，最不放心的一类，反而是 demo 看起来很顺的。

页面有了，上传文件能跑，模型也会给结论。演示的时候挺像一个完整产品。

但只要多问两句，就会露馅：

这个结论什么时候会错？

错了以后用户怎么发现？

哪些 case 不能让模型直接判断？

如果这三个问题答不上来，这个作品集展示的就不是产品能力，只是把模型接进了一个界面。

## v1 demo 最大的问题，是它让失败被藏起来

有个匿名学员做过一个招聘简历初筛 Agent。

v1 的逻辑很简单：上传 JD 和简历，模型输出匹配度，再给一段理由。演示效果很好。输入一份产品经理 JD，再丢一份简历进去，模型能写出“候选人有项目经验、具备数据分析能力、与岗位要求较匹配”。

这种 demo 很容易让人产生错觉：作品已经成立了。

但我们拿 20 份简历做了一轮测试，问题立刻出现。里面有 7 份被误判。

最典型的一类误判，是模型把“项目经历相似”当成“岗位强匹配”。

比如 JD 要的是 B 端 SaaS 产品经理，要求 3 年以上企业服务经验、熟悉销售线索管理和客户成功流程。候选人简历里写了“做过用户增长项目、搭过活动后台、熟悉数据分析”。模型会抓住“后台”“数据分析”“项目管理”这些词，给出较高匹配。

但真正招聘时，这个人可能完全没做过企业服务，也不懂销售流程。

这里的问题不是模型不会写理由。

恰恰相反，它太会写理由了。

它会把一个不该推荐的人，包装成一个看起来可以考虑的人。

这就是很多 AI 作品集的危险点：它展示的是模型会表达，不是产品会判断。

## v2 要先把标准写进产品，而不是继续调 prompt

后来这个项目改到 v2，我们没有先改页面，也没有先换模型。

第一步是把岗位硬门槛拆出来。

| 字段 | 例子 | 处理方式 |
|---|---|---|
| 年限 | 3 年以上 B 端产品经验 | 不满足则不能直接推荐 |
| 行业 | 企业服务 / SaaS / CRM | 不满足则降权 |
| 必备技能 | 线索管理、客户成功、权限体系 | 缺失时必须明示 |
| 地点 | 北京 / 上海 / 远程 | 不满足则标记风险 |
| 薪资 | 预算范围 | 不确定时不做强判断 |

改完之后，模型不再一上来写匹配度，而是先判断硬门槛。

如果硬门槛不满足，它只能输出“不推荐”或“需人工复核”，不能靠一段漂亮理由把人推荐上去。

同样 20 份简历再测，误判从 7 份降到 3 份。

这个变化比把界面做漂亮重要得多。

因为它证明学员开始理解 AI 产品的核心：不是让模型多说，而是让模型在正确的边界里说。

## v3 才开始像一个产品系统

v2 解决了硬门槛，但还有一个问题：招聘不是所有 case 都能自动判断。

有些候选人很模糊。比如年限接近要求，行业不完全匹配，但某个项目经历很强。模型直接推荐或淘汰都不合适。

所以 v3 加了两件事。

第一，拒绝理由模板。

模型不能只写“匹配度较低”，必须指出是哪一类风险：年限不足、行业不匹配、关键技能缺失、地点冲突，还是信息不完整。

第二，人工复核队列。

高风险 case 不直接给“推荐/淘汰”，而是进入“需 HR 复核”。系统只负责把争议点整理出来。

这一步之后，这个作品集才开始从 demo 变成产品系统。

因为它不再假装 AI 永远能给最终答案，而是承认有些判断必须留给人。

这才是 AI PM 应该展示的能力。

## 好作品集展示的是失败如何被处理

很多转型 AI PM 的人，会把作品集理解成“我做了一个功能”。

但 AI 产品的作品集，真正有价值的是另一件事：你如何发现失败，并把失败变成产品设计。

我会看这几层：

| 作品集层级 | 低分表现 | 高分表现 |
|---|---|---|
| demo | 能跑 | 能说明适用场景 |
| 标准 | 模型自由判断 | 关键标准结构化 |
| eval | 只展示成功案例 | 有 bad case 和误判统计 |
| 边界 | 所有问题都回答 | 高风险 case 转人工 |
| 复盘 | “效果不错” | 说清 v1 到 v3 每次改了什么 |

这张表比“我用了什么模型”重要。

因为模型会变，工具会变，平台会变。但你发现问题、定义标准、处理失败的能力，不会过时。

## 我更愿意看到不完美的 v1

一个作品集如果从头到尾都在展示成功，我反而会怀疑它。

真实的 AI 产品不会那么顺。它一定会有误判、幻觉、边界不清、状态拿不到、用户意图混在一起的问题。

好的作品集不是把这些问题藏掉，而是把它们写出来。

v1 为什么错？

v2 改了哪个判断标准？

v3 为什么要加人工复核？

哪些 case 到现在仍然不能自动化？

这些问题答清楚，比做一个漂亮首页更能说明你像 AI PM。

所以我现在给学员改作品集时，经常会让他们删掉一半功能介绍，补上三样东西：

一组测试 case。

一张误判表。

一次从 v1 到 v2 的真实改动。

AI PM 作品集不是证明“我会用 AI 做 demo”。

而是证明“我知道 AI 在哪里会失败，并且我能把失败改成产品系统的一部分”。

这才是作品集真正的含金量。
