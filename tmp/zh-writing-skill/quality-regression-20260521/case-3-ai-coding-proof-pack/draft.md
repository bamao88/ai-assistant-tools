# AI Coding 交付，最后差的不是代码

过去一年，很多人对 AI Coding 的理解还停在“模型会不会写代码”。

但我现在越来越觉得，真正的分水岭已经往后移了。

代码能写出来，不等于这个改动可信。

demo 能跑，不等于这个项目能交付。

在训练营里，我看过一批 AI Coding 项目。第一次交付时，12 个项目里有 9 个都能跑 demo。页面能打开，按钮能点，主流程也能走完。

但如果问一句：“你怎么证明这个改动是可靠的？”

大多数人答不上来。

## 能跑 demo，不等于能交付

这 12 个项目里，第一次真正能说清“为什么可信”的，只有 3 个。

剩下的项目常见问题很像：

只给截图，不给测试。

只说“Claude 修好了”，不给 diff。

只展示 happy path，不记录失败 case。

只告诉你“现在能跑”，但说不清楚改了哪一层、风险在哪里、怎么验收。

这不是学生不努力。

这是很多人对 AI Coding 的交付标准理解错了。

传统写代码时，人会自然留下很多证据：commit、测试、review comment、issue、PR 描述。AI 介入以后，很多人反而把这些证据链省掉了。

因为模型把代码写得太快，用户会以为“能跑起来”就是结束。

但真实项目里，能跑只是最低线。交付需要的是可复查。

## 我开始要求他们补 proof pack

后来我给这批项目加了一个要求：每次 AI Coding 交付，都要补一份 proof pack。

不是长文档，就五样东西：

| 证据 | 要回答的问题 |
|---|---|
| 需求一句话 | 这次到底要解决什么问题 |
| 关键 diff | 改动发生在哪几处 |
| 测试命令和结果 | 怎么证明主路径没坏 |
| 失败 case | 哪些情况还不行 |
| 人工验收点 | 哪些判断必须人来看 |

这个表看起来很朴素，但作用很大。

因为它把“Claude 说修好了”变成了“我能复查这次修复”。

比如一个项目修登录状态丢失问题。低质量交付会说：“已修复，刷新后不会退出。”

proof pack 版本会写：

需求：刷新页面后保留登录态。

关键 diff：把 token 从内存状态改为 httpOnly cookie；前端启动时增加 session restore。

测试：本地执行登录、刷新、关闭页面重开三步；会话保持；登出后 cookie 清除。

失败 case：跨浏览器不保留；无网络时恢复失败。

人工验收点：检查 cookie 安全属性和登出后是否彻底清理。

这才像一个能交付的 AI Coding 项目。

## proof pack 改变的是讨论质量

补 proof pack 后，有一个很明显的变化。

6 个项目在复盘时，其他学员可以独立复现核心结果。大家不再围着“你这个是不是刚好跑通一次”争论，而是能直接看：

需求是不是定义清楚？

diff 有没有改到关键路径？

测试是不是覆盖了主风险？

失败 case 有没有留下？

人工验收点是不是合理？

没有补 proof pack 的项目，讨论很快就会变成感觉判断。演示的人说“我这边可以”，看的人说“但我不确定”。最后大家只能回到截图和口头描述。

这就是 AI Coding 现在最容易被低估的一点：模型生成速度提高以后，交付证据的重要性反而上升了。

因为代码来得越快，越需要一套办法判断它该不该被信任。

## AI Coding 的核心能力正在后移

我不是说写代码能力不重要。

模型能不能理解需求，能不能改对文件，能不能少引入 bug，当然重要。

但对产品经理和创业者来说，更关键的能力正在变成：

你能不能定义一个可验收的问题。

你能不能看懂 AI 改了哪里。

你能不能用最小测试证明主路径没坏。

你能不能记录失败 case，而不是只展示成功。

你能不能知道哪些地方必须人工看。

这几件事合在一起，才是 AI Coding 交付能力。

如果只会让模型写代码，你得到的是一次性 demo。

如果能补上 proof pack，你才开始拥有可复用的工程交付流程。

## 我真正想训练的是“相信的理由”

AI Coding 让代码变得便宜，但它没有让信任变便宜。

一个项目能不能交付，最后不是看“AI 写了多少代码”，而是看你有没有足够理由相信这个改动。

这个理由不能只来自模型回答。

它要来自需求、diff、测试、失败 case 和人工验收。

所以我现在看 AI Coding 作品，不会只看页面。

我会先看 proof pack。

没有 proof pack 的项目，哪怕 demo 很顺，也只能算探索。

有 proof pack 的项目，哪怕功能很小，也已经开始接近真实交付。

AI Coding 的下一道坎，不是让模型多写一点代码。

而是让每次 AI 写出来的东西，都能留下被人相信的证据。
