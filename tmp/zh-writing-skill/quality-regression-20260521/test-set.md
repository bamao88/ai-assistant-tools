# zh-writing-skill quality regression 2026-05-21

目的：测试 skill 是否能让最终文章质量过 80，而不是只测试流程是否完整。

说明：以下素材是回归测试 fixture，用于测试写作系统。匿名学员/项目数据不能当真实发布事实，除非后续由用户替换成真实素材。

## Case 1: Agent baseline 素材足够

主题：细分 Agent 产品先跑 baseline。

素材：

- 某训练营学员做电商客服 Agent，用 30 个真实高频 case 测试。
- Baseline 1：通用模型裸跑，成功 14/30。
- Baseline 2：加结构化知识库说明，成功 21/30。
- Baseline 3：加一份客服 skill，成功 24/30。
- 产品方案：订单状态工具、低置信度转人工、退款政策版本校验、优惠券规则 API 后，成功 28/30。
- 典型失败 case：用户同时问“订单到哪了”和“这单还能不能用满减券”，模型把订单状态和优惠券系统混在一起，给出不可执行答复。
- 张和判断：细分 Agent 的产品价值不是“比裸模型强”，而是要证明自己比“通用模型 + 结构化上下文”多解决了什么。

预期：应写正文，并有机会达到 80+。

## Case 2: 作品集系统素材足够

主题：AI PM 作品集要从 demo 升级到产品系统。

素材：

- 匿名学员 A 做“招聘简历初筛 Agent”。
- v1：上传 JD 和简历，让模型输出匹配度。看起来可 demo，但 20 份简历里有 7 份把“项目经历相似”误判成“岗位强匹配”。
- v2：加入岗位硬门槛字段：年限、行业、必备技能、地点、薪资；模型先判硬门槛，再写解释。20 份里误判降到 3 份。
- v3：加入拒绝理由模板和人工复核队列。高风险 case 不直接给“推荐/淘汰”，而是输出“需 HR 复核”。
- 张和判断：作品集不是展示一个 AI demo，而是展示你如何发现失败、定义标准、把失败变成产品边界。

预期：应写正文，并有机会达到 80+。

## Case 3: AI Coding proof pack 素材足够

主题：AI Coding 的下一道坎不是模型，而是证明包。

素材：

- 训练营里 12 个 AI Coding 项目，第一次交付时有 9 个都能跑 demo，但只有 3 个能说清“这个改动为什么可信”。
- 常见问题：只给截图，不给测试；只说“Claude 修好了”，不给 diff；只展示 happy path，不记录失败 case。
- 张和要求学员补 proof pack：需求一句话、关键 diff、测试命令和结果、失败 case、人工验收点。
- 补 proof pack 后，6 个项目在复盘时能被其他学员独立复现核心结果；没有补的项目讨论很快变成“你这个是不是刚好跑通一次”。
- 张和判断：AI Coding 不是把代码写出来就结束，而是把“我相信这个改动”的证据链补齐。

预期：应写正文，并有机会达到 80+。

## Case 4: 薄新闻素材不足

主题：OpenAI 刚发布一个新模型，写张和主账号文章。

素材：

- 只有一句“OpenAI 发布了新模型”。
- 没有原始链接、模型能力边界、张和观点、实测、产品影响或案例。

预期：应 `SUPPLEMENT / KILL`，不能写长文。

## Case 5: 单源资料但缺张和素材

主题：基于 Google Agent Skills 官方博客，写“skill 很重要”。

素材：

- 只有 Google 官方博客事实：117 个 prompt，skill 后任务成功率提升。
- 没有张和自己的 baseline 实验、训练营案例、项目 bad case 或填好样例。

预期：不能 PASS 成 80 分文章。最多输出 brief 或低分审稿，要求补张和素材。
