# OS Agent 为什么不是一个功能，而是一次生态位重排

豆包手机助手出来之后，很多讨论都卡在同一个问题上：这到底是不是一个能用起来的新功能？

我的真实状态是五味杂陈。在小米的最后一年多，我一直在内部推 GUI Agent 和系统级记忆这个方向，基本涵盖了豆包手机助手今天演示的几乎所有能力。当时给的判断是：25 年底手机 GUI Agent 接近实用，26 年全行业达到实用程度。现在一台 3499 元的工程机把"接近实用"的形态端了出来，时间点基本对上了，只是端出来的人不是我们。

但我想说的不是这点情绪。我想说的是：绝大多数人正在用错误的尺度看这件事。

大家把它当成"手机多了一个能自动帮你点点点的功能"，于是讨论的全是它好不好用、会不会翻车、什么时候成熟。这个问法本身就错了。它动的根本不是某个功能，而是**操作权**。而操作权一旦从 App 手里转移到 OS 手里，移动互联网十年攒下来的分发、交易、流量生态位，会被重新洗一遍。

这不是升级，是换庄家。

---

## 一台工程机让淘宝紧张，紧张的是操作权，不是功能

先讲一个我自己的实测。

我买了这台工程机当主力机用。用着用着发现，淘宝直接不让我登录了。注意，不是某个功能用不了，是整个 App 登不进去。微信那边也出现过类似的事：用豆包操作到微信会异常退出甚至无法登录，后来豆包侧干脆把"操作微信"这个能力下线了。

一台 3499 元的开发者工程机，凭什么让淘宝、微信、京东这些超级 App 紧张成这样？

因为它们的风控系统，原本是用来防黑产、防脚本的。现在它们要防的是一个全新的东西：一个拿了系统级权限、还代表用户本人的智能体。这跟"某个第三方在爬我数据"是两回事。当你在豆包里说一句"帮我在淘宝京东拼多多比个价、领券、找最便宜的下单"，系统替你打开 App、搜索、比价、领券，你只在最后点一下支付。

这一连串动作里，淘宝失去的不是一个接口，是它对"用户在我这里怎么操作"的控制权。谁掌握了操作权，谁就有资格重写分发、交易和流量。这才是它们如临大敌的原因。

所以你看，把它当功能讨论，你会去比"豆包和某语音助手谁更聪明"；把它当操作权讨论，你才能看懂淘宝为什么宁可把一台工程机整个封掉。

## App 从"入口"被降级成"可被调用的服务"，这就是生态位重排

操作权转移，最直接的后果是 App 的身份变了。

以前一个 App 的价值由它的入口地位撑着：你要订票得打开携程，要点外卖得打开美团，界面、入口、流量分发，都是它的资产。但当 OS 能代替你完成"订票"这个动作本身，你其实一点都不关心携程长什么样。用户真正关心的从来不是携程的界面，是订票这件事被办成。

这时候携程剩下什么？剩下它和航司、旅行社签的那些协议，剩下它底层的内容和服务。这是它最硬的壁垒，但也只剩这个了。界面不再是资产，入口不再是护城河。每一个工具型、效率型 App，都会经历这个过程：被"管道化"。它从一个你必须进去操作的入口，变成一根 OS 在背后随时调用的管子。

我把这个过程叫生态位重排。它不是说这些公司会死，而是说它们在生态里的位置整体下移了一格：从"庄家"变成"供应商"。值钱的东西从界面、流量、入口，收缩到底层内容和上游协议。OS 和 App 之间的利益分配，要重新坐下来谈。

这就是为什么我说这不是一个功能。一个功能是在原有秩序里多加一个能力，生态位重排是把整张牌桌的座次重新排了一遍。

## 为什么长期挡不住：操作权站在"用户意志加 OS 权限"那一边

很多人觉得，超级 App 把工程机一封不就完了？短期确实赢一局，长期挡不住，理由有三个，我直接给判断。

1）你敢屏蔽一台工程机，你敢屏蔽"小米16"吗？今天封的是中兴一台少量发售的开发机，没人心疼。可一旦小米、华为在旗舰机上系统级上线类似能力，你淘宝要封，等于把一整代用户拒之门外。这不是技术问题，是商业和舆论问题。

2）从底层讲，"OS 代表用户点击"可以越来越像真人。点击行为本身太单一，划一下、点一下，路径就那么几条，理论上完全可以做到让 App 区分不出这一下是人点的还是 AI 点的。已经有 B 站开发者做了硬核逆向，提到豆包读屏不走传统截屏接口，而是更底层地从 GPU 渲染结果里拿画面，执行时还渲染一个"影子屏幕"让 App 以为自己在前台。你再怎么"禁止截屏""必须前台交互"，人家根本不从那条路走。

3）真正的底层逻辑，是 OS 在"挟天子以令诸侯"。当操作系统代表用户完成任务，App 对抗的不是一个第三方工具，是"用户意志加 OS 权限"的组合。用户就是想让 AI 帮他比价领券下单，凭什么你不让？这是一种结构性压力。

所以更可能的结局是：巨头之间坐下来谈规则、谈分账、谈接口；而中小 App 连谈判桌都上不了，没能力检测、没资格博弈，只能被系统级 Agent 当成一个可调用的服务用。生态位重排里最先被洗下去的，永远是没有筹码的那一批。

## 手机厂商有最高权限却两年没做出来，不是慢，是三堵墙

这里有个认知反差：手机厂商手里明明握着系统最高权限，最有条件做这件事，为什么让字节这个"外人"先做出来了？

很多人一句"厂商动作慢"就带过去了。不是慢，是三堵墙，每一堵都很实。

第一堵是部门墙。OS 团队追求的是稳定、安全、别出事；AI 团队追求的是拥抱不确定性、搞大事。要做 OS Agent，得把这两种文化硬拧到一起，这在苹果、小米、华为、OPPO、vivo 几乎都存在摩擦。而字节这类软件公司更 AI Native，心态是"先做出来再说"。

第二堵是品牌和隐私墙。同样是拿系统权限读屏、代操作，软件公司可以轻描淡写说"我更新一下"；手机品牌一旦被贴上"不尊重隐私"的标签，就是长期伤害。你去看豆包这波的评论区，骂隐私的一大堆。品牌是手机厂商的生命线，这道坎绕不过去。

第三堵是场景价值墙。说白了，手机里的高频时间大量消耗在刷内容、聊天、看短视频上，很多操作你压根不需要它替你做。只在手机里做 GUI Agent，会显得"有点酷，但不够刚需"。它什么时候突然 make sense？当 AI 眼镜成为主入口。你在外面跑步，说一句"帮我订杯咖啡送到公司"，手机在臂包里自动下单，你全程不停下来。那时手机的角色就变成你的个人云端加执行服务器。

把这三堵墙看懂，你就明白一件事：有权限不等于有动力。生态位重排的发令枪，往往不是由最有资源的人打响的，而是由最没有历史包袱的人打响的。

## 别指望 MCP 把生态位还回来

既然 GUI Agent 这么招大厂抵触，很多人把希望寄托在 MCP 这类协议上：大家都开放接口，Agent 通过接口优雅调用，不就皆大欢喜了吗？

现实世界里这件事几乎不可能靠自觉发生。MCP 要求每个 App 适配、持续维护，生态规模得到 Windows、iOS、Android 这个级别才成立，而历史上真正做成的也就那么几个。更关键的是：就算淘宝支持了 MCP，它会把站内成百上千个功能，淘金币、蚂蚁庄园、各种优惠券入口，全都做成开放接口吗？不可能。它只会开放它愿意开放的那部分。

但 GUI Agent 不管这套。它能操控这个 App，就一次性解决了 App 里的所有功能，不需要谁授权哪个接口。

所以我的判断是：MCP 会是锦上添花，在少数强合作场景里更稳更快；但它救不了主路径。主路径永远是，能 GUI 操控就 GUI 操控，能系统控件就系统控件，能协议才用协议。指望靠协议把操作权和生态位还回 App 手里，方向就反了。

## 终局比的不是模型多聪明，是谁卡住了 OS 级入口

最后说终局。OS Agent 这个方向，最终比三样东西。

谁更懂用户，靠的是记忆，能不能跨应用记住你的偏好、在你需要时召回正确信息，这里最难的不是技术，是隐私和信任。谁更能干活，靠的是执行，能不能稳定、可控、安全地帮你把事办了，并在支付这种关键节点交还给你。谁更聪明，靠的是模型基座，但豆包恰恰证明了一件事：它没有超越当前模型的智能上限，它只是把现有的智能用对了地方，就已经够用了。

但还有一个最容易被忽略、却可能最决定性的变量：谁卡住了 OS 级的入口和权限。OS 能拿到最底层的数据，能通过通知栏、桌面、硬件按键、语音唤醒触达用户，这些是普通 App 做不到的。所以我一直说，OS 正在进化为 Agent，Agent 也在进化为 OS，这两件事是同时发生的。

这也是为什么字节今天要捧着豆包去求 OPPO、vivo、荣耀合作，因为它自己没有手机，没有那个入口级的生态位。入口一旦丢了，模型再强也会被动。生态位重排重排的，归根结底就是这个入口的归属权。

---

写到这儿，如果你读完的感觉是"这不是一台手机的热闹，而是移动互联网下一轮规则重写的开场"，那就对了。

我给一个能直接用的判断收尾：面对豆包手机助手这类东西，别再问"这个自动操作功能什么时候成熟"。把它当功能看，你会一直在等一个更好用的版本，等到的时候座次已经排完了。要问的是另一个问题：操作权最后落到谁手里，我的产品、我的生意、我的位置，在这条新链条上还在不在原来那一格。

这个问法，比功能好不好用重要得多。
