# 我在小米踩了上亿的坑才明白：做 Agent，PM 不会评估就别上桌

几年前我在小米做自动驾驶的数据闭环，几百人的团队，上亿的预算，重心几乎全压在训练集上。我们默认只要数据够多、模型够大，效果自然会上去。后来才发现方向错了：特斯拉真正下功夫的地方不是训练集，是评测集，他们的 AI 测评负责人和数据引擎负责人是同一个人，直接向马斯克汇报。等我们绕回来重建评测体系，已经交了上亿的学费。

那是自动驾驶。今天大量产品经理在做 Agent 产品，同一个坑被放大了不止一个量级，而且这次连试错的预算都没有。

我的判断很直接：在 Agent 产品里，评估已经不是上线前跑一遍的质检，也不是简历上的加分技能，而是 AI PM 的入场券。谁不会设计、不会读 Agent 的评测，谁就根本判断不了自己的产品到底成没成。

## Agent 把"一步对错"变成了"整条路对错"

传统软件测试是输入 A 出 B，对就过、错就改。单轮大模型评测也还好，一次输入对一次打分。Agent 不一样，它要走多步：规划、调工具、读返回、再规划，最后才给结论。麻烦在于误差会沿着这条轨迹累积。

你可以做个最朴素的乘法。每一步 95% 的可靠性听起来很高，但一个 20 步的任务，0.95 连乘 20 次只剩 36%。单步越可靠你越容易高估它，因为没人会自觉去算这个乘法。

更隐蔽的是假阳性。一个调研 Agent 可能调了五次工具才给出结论，其中三次工具调错了、调重了、甚至调了不该调的，但最后那段文字读起来一点毛病没有。只看最终输出，你会把它判成成功。业界一个反复出现的观察是：只看输出的评测，通过率会比看完整轨迹的评测虚高两到四成。也就是说，你以为 80 分的产品，按轨迹一测可能只有五六十分。

这就是"Agent 评估"和"AI 评估"四个字的区别。不是多了几个指标，是判断"产品到底成没成"这件事本身的难度被结构性地抬高了。

## 所以光"看结果"不够，必须"看中间过程"

这正是我在训练营里反复跟学员强调的：AI 评测必须亲眼看原始 case，看输入、看输出、看 AI 的中间产物，不能只看统计图和那几个 benchmark 分数。移动互联网时代有时候瞄一眼统计图就够了，AI 不行，尤其是 Agent。

带学员做 deerflow（一个多 Agent 的 deep research 项目）时，我们的第一个动作不是改 prompt，而是人工标够 200 条日志，把每条错误归类，定位到底是 planner 差、reporter 差还是 coordinator 差。没有这一步，你看到一个结果不好，根本不知道该骂哪个 Agent，只能凭感觉瞎调。

也是因为这个，Agent 评测要同时养两套评测集：一套端到端，从场景层面覆盖各种业务；一套模块专属，单独测某个环节，比如工具调用准不准。只做端到端、看不到中间过程，等于把整条轨迹的复合误差糊成了一个分数，你永远定位不到病根。

## 这件事为什么必须 PM 来扛

总有人说，评测不是测试团队、算法团队的活吗？在 AI 时代不是了。

评测的本质是定义"什么叫好"，而"什么叫好"恰恰是产品经理的核心职责。算法工程师的注意力在模型和线上指标，很多人还停留在九成时间调算法、一成搞数据的认知里，评测集这块恰恰是 PM 能为团队做出最大贡献、也最该自己抢过来的地方。硅谷顶尖团队早把这当共识：产品经理不做评测，以后就别干了。

讲个具体的。训练营里有个学员做快递下单助手，用自然语言下单，第一版成功率只有 40% 到 50%。他没去堆新功能，而是用评测驱动一点点抠：建评测集、跑 case、定位失败类型，发现问题出在架构、异常处理和 API 调试上，逐个改，最后做到 95% 才上线。

这个从 40% 到 95% 的过程，比做十个炫酷的新功能都更能体现一个 AI PM 的能力，也是面试时唯一讲得出血泪的环节。注意，撑起这个过程的不是某次灵感，是一套能反复跑、能定位、能回归的评测体系。没有这套体系，他连"现在到底是 60% 还是 90%"都说不清，更别说知道下一步该改哪。

## 把边界说清楚，免得你又走到另一个极端

第一，别指望模型变强就能省掉评测。AI 产品有个反直觉的规律：两个产品的功能会逐渐拉齐，但效果上的差距一直都在。模型再强，0.95 连乘 20 次还是 36%，复合误差不会因为单步变强就自己消失。

第二，别一上来就追求科学打分。我见过太多次，一旦要求做量化打分体系，十个小组有七个会卡在"这也太难评了"然后放弃，一放弃就全亏了。起步阶段，每人测 5 个 case、用主观感受排个序、把优劣说清楚，这就赚了。评测集本来就不可能一次穷尽，它是每周加深一点认知、慢慢逼近真实场景的东西，不是上线前一次性交付的文档。

第三，评测要绑真实业务、用你自己懂的领域去测。拿"帮我找最贵的胡萝卜"这种假 case，测不出真问题；接进真实订单、商品、库存，工具调用才测得出来。用自己懂的领域测也是同理，答案不好你才感觉得出来。

## 回到那个判断

Agent 把效果的不确定性从一步推到了整条轨迹，直接后果是：判断产品好坏的难度被结构性地抬高，而抬高的这部分，正好落在"定义什么叫好"的人身上，也就是 PM。

如果你现在在做 Agent 产品，不用一上来就搭评测平台。今天就能起步的最小动作是：挑一个真实 case，把这条轨迹里每个 Agent 拿到的上下文、调用的工具、返回的结果，一步步看一遍，标出它从哪一步开始走偏。看完 200 条，你对这个产品的理解会和只看分数的人完全不在一个层面上。

这就是为什么我说，Agent 时代评估是入场券，不是加分项。它不保证你能做出好产品，但不会它，你连自己有没有做出好产品都判断不了。
