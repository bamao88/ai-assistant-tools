# Topic Preflight

写正文前先做选题预检。这个文件的作用不是润色标题，而是判断这篇文章是否值得写、能不能增强张和的专家人设。

对大选题、行业事件、方法文、单源解读和任何需要代表张和主账号发声的文章，先执行 `zhang-viewpoint-first.md`。本 brief 必须继承 `Zhang Viewpoint Dossier`，再判断能不能写。不要先做外部研究、再倒推张和观点。

## 输出格式

完成 `Zhang Viewpoint Dossier` 后，输出这个 brief，不要直接写正文：

```markdown
# Article Brief

## Decision
WRITE / SUPPLEMENT / DOWNGRADE / KILL

## Route
A-firsthand / B-knowledge-system / C-single-source / operations / unknown

## Benchmark Shape
从 `benchmark-corpus.md` 选择一个主形态：业内人士深度复盘 / PM 视角技术教材 / 体感报告或产品实测 / 反主流单点 / 高在场度单源解读 / none。说明为什么匹配，以及该形态的 80 分最低线是否能满足。

## Zhang Viewpoint Source
引用 `zhang-viewpoint-first.md` 的 Dossier：张和原观点是什么，来自哪些路径或用户素材，置信度 HIGH / MEDIUM / LOW。

## Viewpoint Core
1-2 句话说明这篇文章必须守住的张和立场。

## Deep Research Plan
外部研究要补什么：机制、原始事实、产品细节、竞品对照、反例、可执行样例。说明哪些属于研究延展，不能归因给张和原话。

## Research Source Ledger
列出准备写进正文的外部研究结论，尤其是数字、比例、发布时间、实验结果、产品能力边界。每条必须有来源路径或 URL，并标明：直接支持 / 间接支持 / 只支持方向不支持数字。只支持方向的内容不能写成精确数字。

如果正文需要用假设数字或示意比例增强论证，也要在这里说明口径。没有来源或计算过程时，不能写精确数，只能写区间或定性表达。

## Viewpoint Drift Risk
LOW / MEDIUM / HIGH。列出最可能偏移的地方，以及如何避免。

## Publication Value
按 `article-quality-standard.md` 的 7 个问题简短回答：解决谁的问题、为什么现在写、张和凭什么讲、核心判断是否有风险、证据能否改变判断、读者能做什么、普通 LLM 能否轻易复刻。

## Topic
这篇到底写什么，边界收在哪里。

## Why Now
为什么现在值得写：近期事件、产品变化、读者问题、训练营真实共性问题，至少一个。

## Author Right
张和凭什么讲：亲历、学员案例、咨询/项目经验、长期判断、公开一手信源整合，至少一个。不能只写履历标签。

## Core Claim
一句能被反驳的判断。不能是“X 很重要”“要重视 Y”这类安全句。

## Evidence Plan
列出将支撑正文的证据：一手素材、具体案例、可核查事实、原始链接、数据、截图、填好的样例或 bad case。

## Case Fact Boundary
如果使用用户给定或知识库中的案例，区分三类内容：已给事实 / 合理产品判断 / 不可写的场景补全。未提供的学员情绪、现场对话、张和即时反馈、客户反应、内部细节，都不能为了叙事顺手补出来。

代表性模式可以写，但不能伪装成具体最近事件。来源没有明确时间、人物、渠道或互动记录时，不写“上周一个学员”“过去两周被问最多”“昨天有个客户”这类时间锚点；改写成“这类问题我反复见到”“训练营里经常有人交这种表”。

## Primary Case Spine
如果是方法文、训练营复盘或 PM 技术教材，必须填写一个贯穿全文的主案例：原始状态、失败证据、修改动作、结果变化、产品判断。不是这类文章可写“不适用”。

## Reader Takeaway
读者看完能带走的判断、方法或动作。

## Sales Risk
LOW / MEDIUM / HIGH，并说明会不会像训练营广告或转型焦虑承接。

## Publishability Estimate
预计分 X/100。按 `article-quality-standard.md` 的 100 分表估算：发表价值、原创判断、论证强度、专家在场、读者带走、信任与克制；再检查 benchmark shape 匹配度。

## Missing Material
还缺什么；没有缺口写“无明显缺口”。

## Next Action
直接写 / 补素材后写 / 降级成短帖或运营文 / 放弃
```

## 判定规则

- `WRITE`：预计成稿能达到 80 分；通过 `article-quality-standard.md` 的硬门槛；核心判断清楚，至少有一种强证据，能增强“AI 产品判断 / Agent 工程落地 / Evals 方法论 / AI PM 成长方法论”其中一个心智，并且能明确落到 `benchmark-corpus.md` 的一个主形态。
- `SUPPLEMENT`：题值得写，但缺张和明确立场、原始来源、真实案例、数据、bad case、截图或填好的样例。先补素材，不写正文。
- `DOWNGRADE`：材料只够做轻量推文、活动说明、工具记录或课代表号内容，不适合作为张和主账号专业文章。
- `KILL`：只是在转述新闻、复述外部博客、制造求职焦虑、服务招生，或核心判断没有证据支撑。

## 硬门槛

出现任一情况，不能直接写长文，也不能给 `WRITE`：

- 内容/分析文章需要代表张和主账号发声，但没有 `Zhang Viewpoint Dossier`。
- 第一人称张和观点文缺少至少 MEDIUM 置信度的张和原观点，且用户没有在本轮明确补充观点。
- 外部研究已经形成新主张，但无法说明它如何从张和 `Viewpoint Core` 生长出来。
- 外部研究中的精确数字、比例、排名、实验结果没有进入 `Research Source Ledger`，或来源只支持方向不支持数字。
- 假设数字、示意比例、估算增量没有来源或计算过程，却准备写成精确数字。
- 需要写“张和一直认为 / 张和在训练营看到 / 我做过”这类表述，但素材里没有对应来源。
- 用户只给了案例数据，但正文需要写现场对话、学员情绪、张和当时怎么回应、客户怎么反应等未提供细节。
- 来源只支持“反复出现的模式”，但正文要写成某个具体最近事件、具体学员、具体客户或具体对话。
- 没有可核查事实，也没有一手经历或具体案例。
- 只有“传统 PM 也有机会”“要懂边界”“要做 eval”这类泛判断。
- 文章成立主要靠训练营、公开课、加微信等转化信息。
- 需要学员数据、客户案例、内部经历，但素材里没有，且用户没有授权补充。
- 标题很顺，但 brief 说不清“具体写哪个对象、问题和边界”。
- 按 `article-quality-standard.md` 的 7 个发表价值问题，任意 2 个答不上来。
- 方法文 / 训练营复盘 / PM 技术教材没有 `Primary Case Spine`。
- 说不清这篇要对标 `benchmark-corpus.md` 的哪一种高质量形态。

## 预估分规则

- 80-100：可以写，进入 A/B/C 路由。
- 63-79：题可能成立，但先补素材或收窄角度。
- 0-62：放弃或降级，不写主账号长文。

估分不是为了精确，而是防止 60 分选题被文风包装成“看起来还行”的长文。

## 补素材优先级

优先向下补，不要靠文风硬撑：

1. 张和原话、会议记录、候选文件里的 `boss_take`。
2. 学员真实 bad case、项目截图、评测表、迭代前后对比。
3. 原始博客、论文、官方文档、产品发布页、代码仓库。
4. 竞品案例或行业案例。
5. 一个填好的方法论样例，而不是空模板。
6. 能把文章推入某个 benchmark shape 的关键素材：亲历、实测、三源整合、自创分类法、真实 bad case 或填好样例。

## 不要做的事

- 不要把“符合 A/B/C 路由”当成“值得写”。
- 不要为了通过预检编造张和经历、学员数据、客户案例或内部信息。
- 不要把一篇文章同时塞进太多目标：热点、转型、招生、技术教材、活动引流。
