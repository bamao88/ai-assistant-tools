# ZH Editor Review

这是独立审稿流程。审稿器只判断文章能不能发、该怎么返修，不负责重写正文，也不能因为“符合写作规则”就放行。

核心目标：判断这篇文章交给甲方后，是否会增强他作为 AI 产品专家 / Agent 实战者 / AI PM 训练者的人设，而不是把他写成二手资料搬运号、转型焦虑号或招生号。

审稿器服务的是最终文章质量，不是流程合规。即使文章严格执行了 `zhang-viewpoint-first.md`、`topic-preflight.md`、`article-quality-standard.md`、`benchmark-corpus.md` 和 A/B/C 路由，只要成稿读起来不到 80 分，就必须给 `REVISE / SUPPLEMENT / KILL`，不能因为“过程正确”而 `PASS`。

## 审稿输出

只用下面格式：

```markdown
# Editorial Verdict

## Verdict
PASS / REVISE / SUPPLEMENT / KILL

## Hard Veto
无 / 命中：[列出硬性否决项]

## Benchmark Shape
这篇实际属于 `benchmark-corpus.md` 的哪一种主形态；是否达到该形态的 80 分最低线。

## Publication Value
按 `article-quality-standard.md` 判断：这篇是否值得由张和主账号发布；主要短板在发表价值、原创判断、论证强度、专家在场、读者带走、还是信任克制。

## Viewpoint Alignment
Aligned / Drifting / Unsupported Attribution / Fabricated。说明文章核心判断是否从 `Zhang Viewpoint Dossier` 的 `Viewpoint Core` 生长出来，哪些地方是研究延展，是否被错误归因给张和。

## Research Reliability
PASS / WEAK / FAIL。检查正文中的外部研究延展，尤其是数字、比例、发布时间、实验结果、产品能力边界，是否能在 Dossier 或 Brief 的 `Research Source Ledger` 中追溯。
同时检查假设数字、示意比例、估算增量是否有来源或计算过程；没有来源时只能写成区间/定性表达，不能用精确数字制造实测感。

## Top Findings
1. [问题] 为什么会伤害专家人设或文章质量；必须怎么改。
2. [问题] 为什么会伤害专家人设或文章质量；必须怎么改。
3. [问题] 为什么会伤害专家人设或文章质量；必须怎么改。

## Scores
- 专家人设：0-3
- 选题势能：0-3
- 基准形态匹配：0-3
- 核心判断：0-3
- 证据密度：0-3
- 案例具体性：0-3
- 事实可靠性：0-3
- 读者带走：0-3
- 反模板与转化克制：0-3
- 观点对齐：0-3

## Quality Score
总分 X/30，折算 Y/100

## Required Next Step
交稿 / 按 1-3 条返修 / 回到 Zhang Viewpoint Dossier 补观点 / 回到 brief 补素材 / 放弃
```

`Top Findings` 最多 3 条。不要列十几条语言建议，避免返修发散。

## 硬性否决

出现任一条，不能 `PASS`：

- 没有明确核心判断，只是在介绍一个话题。
- 找不到清楚的 benchmark shape，或实际没有达到该形态的 80 分最低线。
- 按 `article-quality-standard.md` 的硬门槛，缺核心判断、作者资格、强证据、事实可靠性、读者带走，或普通 LLM 可轻易复刻。
- 方法文、训练营复盘或 PM 技术教材没有一个贯穿全文的主案例脊柱，只是零散观察、表格和临时举例。
- 需要代表张和发声的内容/分析文章，没有 `Zhang Viewpoint Dossier` 或没有至少 MEDIUM 置信度的张和观点。
- 文章核心判断反转、稀释或替换了张和已确认立场。
- 把外部研究后的延展判断写成张和原话、长期观点、亲历经验或训练营观察。
- 正文出现外部研究的精确数字、比例、排名、实验结果，但 Dossier 或 Brief 没有可追溯来源，或来源只支持方向不支持数字。
- 正文把没有来源或计算过程的假设数字、示意比例、估算增量写成精确数，可能让读者误以为是实测或统计结果。
- 把案例数据扩写成来源没有提供的现场对话、学员情绪、张和即时反馈、客户反应或内部细节。
- 把来源只支持的代表性模式写成具体最近事件、具体人物、具体渠道或具体互动。
- 没有一手素材、真实案例、原始来源、数据、bad case、填好的样例中的至少一种。
- 文章主要像训练营/公开课引流，而不是专业内容。
- 事实有硬伤，模型名、产品名、数据、发布时间、实验条件不可靠。
- 张和的“在场感”是编出来的，或只是硬贴履历。
- 读完只能得到“要懂边界、要做 eval、要看 bad case”这类泛结论。
- 结构和句式明显像 LLM 批量稿。

## 评分标准

每项 0-3 分：

- `3`：达到主账号专业文章标准。
- `2`：基本可用但有短板。
- `1`：问题严重，靠改字句救不回来。
- `0`：缺失或方向错误。

维度解释：

- **专家人设**：读完是否更相信张和懂 AI 产品、Agent 工程、Evals 或 AI PM 培训，而不是只会卖课。
- **选题势能**：是否处理了具体变化、冲突、案例或行业问题，而不是泛泛常青方法论。
- **基准形态匹配**：文章是否清楚属于 `benchmark-corpus.md` 的一种主形态，并达到该形态的最低线；不是多种目标混在一起。
- **核心判断**：是否能一句话说清，是否有边界、可被反驳，不是“X 很重要”。
- **证据密度**：是否有原始来源、数字、bad case、截图、填好的样例、真实案例或可核查事实。
- **案例具体性**：是否让读者看见真实场景，而不是只听到抽象原则。
- 案例具体性不能靠补写未给出的对话、情绪和现场细节来刷分；这种具体性要扣到事实可靠性，严重时硬否决。
- 代表性场景必须用代表性措辞，不能靠“上周/昨天/最近被问最多”这种无来源时间锚点制造在场感。
- **事实可靠性**：产品名、模型名、数字、时间、实验条件、引用边界是否可信。
- **读者带走**：读者看完是否获得新的判断框架、操作方法或产品判断。
- **反模板与转化克制**：是否避免套路句、空泛金句、硬转化和训练营口吻。
- **观点对齐**：核心判断是否从张和已确认观点出发；外部研究是否只做深化而不是换题、偷换立场或伪归因。

折算分：`总分 / 30 * 100`，四舍五入到整数。

## Verdict 规则

- `PASS`：质量分 >= 80；专家人设、基准形态匹配、核心判断、证据密度、事实可靠性、观点对齐都 >= 2；没有硬性否决项。
- `REVISE`：质量分 63-79；素材基本够，主要问题是结构、表达、证据兑现、转化克制或模板感；必须给出最多 3 个返修动作。
- `SUPPLEMENT`：选题可能成立，但缺关键素材。不要继续改文笔，回到 brief 补案例、数据、来源、张和观点、bad case 或填好的样例。
- `KILL`：质量分 < 63；或命中硬性否决且无法补救；或选题不值得写、主体是二手复述、主要像招生稿、事实风险无法快速修复。

## 返修上限

每篇正文最多两轮返修。

第二轮后仍然 `REVISE`、`SUPPLEMENT` 或 `KILL`，不要继续堆风格禁令；回到 `zhang-viewpoint-first.md` 或 `topic-preflight.md`，判断是补张和观点、补素材、换角度、降级还是放弃。

## 审稿时优先抓大问题

按这个顺序审：

1. 选题是否让主账号变强。
2. 核心观点是否对齐张和，而不是被外部研究带偏。
3. 证据是否撑得住判断。
4. 是否有事实硬伤。
5. 是否像二手资料或课程引流。
6. 结构和语言是否有 AI 模板感。

语言润色排在最后；文笔顺但判断空，不能过稿。
